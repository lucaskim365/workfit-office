# 그룹웨어 문서관리 기능명세서

## 1. 기능 개요

### 1.1 기능명

**문서관리**

### 1.2 목적

회사에서 사용하는 규정, 업무 매뉴얼, 서식, 업무자료 등의 중요 문서를 체계적으로 분류·보관하고 임직원이 필요한 문서를 쉽게 조회하고 다운로드할 수 있도록 한다.

문서관리는 단순한 파일 저장 공간을 넘어 **회사에서 공식적으로 사용하는 문서의 기준 저장소** 역할을 한다.

단, 초기 MVP에서는 복잡한 전자문서관리 기능은 제외하고 **문서 등록·조회·다운로드를 중심으로 구현**한다.

---

# 2. 게시판과의 역할 구분

문서관리와 게시판은 동일한 정보를 중복해서 관리하지 않는다.

| 구분      | 게시판        | 문서관리      |
| ------- | ---------- | --------- |
| 목적      | 정보 전달 및 안내 | 실제 문서 보관  |
| 규정 개정   | 개정 사실 안내   | 개정된 규정 보관 |
| 문서 내용   | 필요 시 요약/안내 | 공식 문서 파일  |
| 버전 관리   | X          | 규정에 한해 지원 |
| 문서 다운로드 | 제한적        | ○         |
| 문서 검색   | 게시글 검색     | 문서 검색     |

### 예시

규정이 개정된 경우:

```text
문서관리
취업규칙 v3.0 등록
        ↓
게시판
"취업규칙이 개정되었습니다."
        ↓
문서관리
현재 시행 중인 v3.0 확인
```

즉,

> **게시판은 "무엇이 바뀌었는지 알려주는 곳"**
> **문서관리는 "현재 어떤 문서를 사용해야 하는지 확인하는 곳"**

으로 역할을 구분한다.

# 3. 문서함 구성

MVP에서는 기본 문서함을 제공한다.

```text
문서관리
│
├─ 전체 문서
├─ 규정
├─ 업무매뉴얼
├─ 서식
└─ 업무자료
```

### 기본 문서함

| 문서함   | 용도                |
| ----- | ----------------- |
| 규정    | 회사의 규정 및 사내 정책    |
| 업무매뉴얼 | 업무 수행 방법 및 사용 안내서 |
| 서식    | 업무에 사용하는 각종 양식    |
| 업무자료  | 기타 업무 관련 자료       |

---

# 4. 문서함 관리

관리자는 문서함을 추가하거나 수정할 수 있다.

### 관리자 기능

* 문서함 생성
* 문서함명 수정
* 문서함 설명 수정
* 문서함 비활성화

초기 시스템에서는 기본 문서함을 제공하고, 회사의 필요에 따라 관리자가 추가 문서함을 생성할 수 있도록 한다.

예:

```text
규정
업무매뉴얼
서식
업무자료
교육자료
안전자료
```

### 일반 직원

문서함을 생성하거나 수정할 수 없다.

---

# 5. 문서 등록 권한

문서 등록은 관리자와 지정된 부서 담당자만 가능하다.

| 사용자    | 문서 조회 | 문서 등록 | 문서 수정 | 문서 삭제 |
| ------ | ----: | ----: | ----: | ----: |
| 일반 직원  |     ○ |     X |     X |     X |
| 부서 담당자 |     ○ |     ○ |     ○ |    ○* |
| 관리자    |     ○ |     ○ |     ○ |     ○ |

* 부서 담당자는 자신에게 관리 권한이 부여된 문서 범위에 한해 관리한다.

### 부서 담당자 예시

```text
인사팀 담당자
 └─ 인사 관련 문서 관리

총무팀 담당자
 └─ 총무 관련 문서 관리

관리자
 └─ 전체 문서 관리
```

---

# 6. 문서 등록

## 6.1 등록 방식

문서 담당자가 문서함을 선택한 후 문서를 등록한다.

```text
문서함 선택
   ↓
문서 등록
   ↓
파일 업로드
   ↓
문서 정보 입력
   ↓
등록
   ↓
즉시 공개
```

문서 등록 후 별도의 관리자 승인 절차를 거치지 않는다.

> **등록 권한 자체를 관리자 및 부서 담당자로 제한하여, 등록 즉시 공개할 수 있도록 한다.**

---

# 7. 문서 등록 정보

| 항목   | 필수 | 설명            |
| ---- | -: | ------------- |
| 문서명  |  O | 문서의 표시 이름     |
| 문서함  |  O | 문서가 속할 분류     |
| 파일   |  O | 실제 문서 파일      |
| 설명   |  X | 문서에 대한 간단한 설명 |
| 담당부서 |  O | 문서를 관리하는 부서   |
| 등록자  | 자동 | 실제 등록 사용자     |
| 등록일  | 자동 | 등록 시점         |

문서 등록 시 작성된 정보는 문서 상세 화면에서 확인할 수 있다.

---

# 8. 문서 공개

문서는 등록이 완료되는 즉시 해당 문서함을 이용할 수 있는 직원에게 공개한다.

초기 MVP에서는 별도의 문서별 공개 승인 절차를 제공하지 않는다.

```text
담당자 등록
     ↓
등록 완료
     ↓
직원에게 공개
```

문서 등록 이후 관리자가 필요에 따라 문서를 수정하거나 삭제할 수 있다.

---

# 9. 문서 목록

문서함을 선택하면 해당 문서 목록을 조회한다.

### 목록 표시 정보

| 항목    | 설명           |
| ----- | ------------ |
| 문서명   | 문서 이름        |

| 담당부서  | 관리 부서        |

| 수정일   | 마지막 수정 날짜    |
| 버전    | 규정 문서인 경우 표시 |

예:

```text

```

문서를 선택하면 문서 상세 화면으로 이동한다.

# 12. 문서 미리보기

지원 가능한 파일 형식에 대해서는 브라우저 내 문서 미리보기를 제공한다.

초기 MVP에서는 PDF를 우선 지원한다.

```text
문서 상세
     ↓
[문서 미리보기]
     ↓
PDF Viewer
```

지원하지 않는 형식은 다운로드 기능을 제공한다.

예:

```text
이 파일은 미리보기를 지원하지 않습니다.

[파일 다운로드]
```

---

# 13. 문서 다운로드

사용자는 문서 상세 화면에서 파일을 다운로드할 수 있다.

```text
[다운로드]
     ↓
원본 파일 다운로드
```

다운로드한 파일은 업로드된 원본 파일을 그대로 제공한다.

---

# 14. 일반 문서 수정

규정을 제외한 일반 문서는 기존 문서 정보를 수정할 수 있다.

대상:

* 업무매뉴얼
* 서식
* 업무자료

예:

```text
그룹웨어 사용자 매뉴얼.pdf
        ↓
파일 업데이트
        ↓
최신 파일로 교체
```

초기 MVP에서는 일반 문서에 대한 별도의 버전 이력을 관리하지 않는다.

---

# 15. 규정 문서 버전 관리

규정은 일반 문서와 달리 **기존 문서를 덮어쓰지 않는다.**

개정된 규정은 새로운 버전으로 등록한다.

```text
취업규칙

v1.0
2024.01.01
   ↓
v2.0
2025.03.01
   ↓
v3.0
2026.08.01 ← 현재 시행
```

이를 통해 과거에 적용되었던 규정을 변경하지 않고 보존할 수 있다.

---

# 16. 규정 버전 정보

규정의 새로운 버전을 등록할 때 다음 정보를 기록한다.

| 항목    | 필수 | 설명             |
| ----- | -: | -------------- |
| 버전    |  O | v1.0, v2.0 등   |
| 시행일   |  O | 해당 버전이 적용되는 날짜 |
| 개정일   |  O | 규정이 개정된 날짜     |
| 개정 사유 |  O | 개정된 이유         |
| 파일    |  O | 해당 버전의 원본 파일   |
| 등록자   | 자동 | 등록 사용자         |
| 등록일   | 자동 | 등록 시점          |

---

# 17. 규정 개정 이력

규정 상세 화면에서 현재 버전과 과거 버전을 함께 확인할 수 있다.

```text
취업규칙

현재 시행
v3.0
시행일 2026.08.01

────────────────────────

개정 이력

v3.0   2026.08.01
근무시간 관련 조항 개정

v2.0   2025.03.01
복무 관련 조항 수정

v1.0   2024.01.01
최초 등록
```

과거 버전을 선택하면 해당 버전의 문서를 조회하거나 다운로드할 수 있다.

---

# 18. 현재 버전 처리

규정에는 하나의 **현재 시행 버전**이 존재한다.

새로운 버전이 등록되고 시행일이 도래하면 해당 버전을 현재 버전으로 지정한다.

과거 버전은 삭제하거나 덮어쓰지 않는다.

```text
v1.0  → 과거 버전
v2.0  → 과거 버전
v3.0  → 현재 시행 버전
```

이를 통해 과거 문서의 내용을 보존한다.

---

# 19. 게시판과 규정 개정 연계

규정이 개정된 경우 문서관리에서 새로운 버전을 등록하고, 필요한 경우 게시판을 통해 직원에게 변경 사항을 안내한다.

### 예시

**문서관리**

```text
취업규칙
v2.0 → v3.0
```

↓

**게시판**

```text
[공지]

취업규칙 개정 안내

2026년 8월 1일부터 취업규칙이 개정되었습니다.

주요 변경사항:
- 근무시간 관련 조항 변경
- 휴가 관련 조항 변경

개정된 규정은 문서관리에서 확인해주세요.

[취업규칙 확인]
```

게시판의 공지글은 문서관리의 해당 문서로 연결할 수 있도록 한다.

---

# 20. 문서 삭제

문서 삭제 권한은 관리자 및 해당 문서를 관리할 수 있는 부서 담당자에게 부여한다.

단, **규정의 과거 버전은 일반적인 문서 삭제 방식으로 삭제하지 않는다.**

### 일반 문서

```text
업무매뉴얼
   ↓
삭제
   ↓
문서 목록에서 제거
```

### 규정

```text
취업규칙
 ├─ v1.0
 ├─ v2.0
 └─ v3.0

과거 버전
→ 이력 보존

현재 버전
→ 새로운 버전 등록을 통해 갱신
```

향후 법적 보존이나 감사 요구사항이 발생할 경우 별도의 문서 폐기 정책을 추가한다.

# 25. 핵심 설계 원칙

### ① 문서관리와 게시판을 분리한다.

게시판은 **정보를 전달하는 공간**, 문서관리는 **공식 문서를 보관하는 공간**으로 정의한다.

### ② 등록 권한을 제한하고 등록 즉시 공개한다.

관리자와 부서 담당자만 문서를 등록할 수 있으므로 별도의 승인 단계를 두지 않는다.

### ③ 규정은 과거 데이터를 덮어쓰지 않는다.

개정 시 새로운 버전을 생성하여 과거 규정을 보존한다.

### ④ 현재 문서를 가장 쉽게 찾을 수 있도록 한다.

직원은 문서관리에서 항상 현재 시행 중인 규정을 우선적으로 확인할 수 있어야 한다.

### ⑤ 문서관리 자체를 복잡한 전자문서관리 시스템으로 만들지 않는다.

MVP에서는 **"회사의 공식 자료실"**이라는 역할에 집중하고, 버전관리·권한관리·보존관리 등의 고급 기능은 실제 운영 요구사항에 따라 단계적으로 확장한다.
