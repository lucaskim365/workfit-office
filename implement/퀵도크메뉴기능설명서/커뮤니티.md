# 그룹웨어 커뮤니티 기능 설명서

## 1. 기능 개요

### 1.1 기능명

**커뮤니티(Community)**

### 1.2 목적

임직원이 업무와 공식적인 공지에서 벗어나 자유롭게 소통하고, 관심사가 비슷한 구성원이 소모임을 만들어 지속적으로 교류할 수 있는 공간을 제공한다.

커뮤니티는 회사의 공식적인 정보 전달을 목적으로 하는 **게시판과 구분하여**, 직원 간의 자발적이고 가벼운 소통을 중심으로 한다.

### 1.3 기본 방향

> **자유게시판은 전 직원이 함께 사용하는 열린 소통 공간**
> **소모임은 특정 구성원이 모여 활동하는 제한된 소통 공간**

# 2. 게시판과의 기능 구분

| 구분     | 게시판            | 커뮤니티                  |
| ------ | -------------- | --------------------- |
| 주요 목적  | 공식 정보 전달       | 직원 간 자유로운 소통          |
| 주요 콘텐츠 | 공지, 규정, 안내, 자료 | 일상, 취미, 관심사, 자유로운 이야기 |
| 이용 대상  | 게시판별 권한에 따름    | 전 직원                  |

| 소모임    | 해당 없음          | 구성원 중심                |
| 익명 게시글 | X              | 자유게시판만 허용             |

| 인기글/랭킹 | X              | X                     |

| 대댓글    | 선택적            | ○                     |
| 가입 개념  | 없음             | 소모임에 적용               |

# 3. 커뮤니티 구성

커뮤니티는 초기 MVP에서 다음 두 영역으로 구성한다.

```text
커뮤니티
│
├─ 자유게시판
│   └─ 전 직원이 자유롭게 소통
│
└─ 소모임
    ├─ 소모임 목록
    └─ 소모임별 공간
```

관심사별 게시판은 초기 MVP에서 제외하고, 향후 사용 패턴에 따라 확장한다.

# 4. 자유게시판

## 4.1 기능 개요

전 직원이 별도의 가입 절차 없이 자유롭게 글을 작성하고 다른 직원의 글을 열람할 수 있는 **SNS형 피드 공간**이다.

단, 일반 SNS와 달리 좋아요 수, 인기글, 랭킹 등의 경쟁 요소는 제공하지 않는다.

### 기본 특징

* 전 직원 전체 공개
* 전 직원 글 작성 가능
* 실명 또는 익명 작성 가능
* 댓글 및 대댓글
* 첨부파일
* 게시글 수정 및 삭제
* 검색
* 알림

---

# 5. 자유게시판 게시글

## 5.1 게시글 작성

모든 직원은 자유게시판에 게시글을 작성할 수 있다.

### 입력 항목

| 항목    | 필수 | 설명         |
| ----- | -: | ---------- |
| 내용    |  O | 게시글 본문     |
| 첨부파일  |  X | 관련 파일 첨부   |
| 작성 방식 |  O | 실명 / 익명 선택 |

게시글 제목은 자유게시판의 피드형 UI 특성을 고려하여 선택적으로 사용하거나 생략할 수 있다.

### 작성 예시

```text
자유게시판

[홍채원]

오늘 점심 뭐 먹을지 고민되네요.
회사 근처 맛집 추천해주세요!

💬 댓글 3

────────────────

[익명]

최근 회사 복지 중에 개선되었으면
하는 부분이 있습니다.

💬 댓글 5
```

# 6. 익명 게시글

## 6.1 익명 작성

자유게시판에서는 게시글 작성 시 **실명 또는 익명**을 선택할 수 있다.

익명 게시글은 일반 사용자에게 작성자의 이름을 공개하지 않는다.

### 일반 사용자 화면

```text
익명

회사 근처에 새로운 식당이 생겼네요.
다들 가보셨나요?

2026.08.11
```

### 관리자 화면

관리자는 필요한 경우 익명 게시글의 실제 작성자를 확인할 수 있다.

```text
작성자 표시 : 익명
실제 작성자 : 김철수
```

### 정책

* 익명 여부는 게시글 단위로 설정
* 익명 게시글도 실제 작성자 ID를 시스템에 기록
* 일반 사용자에게 실제 작성자 정보 비공개
* 관리자만 실제 작성자 확인 가능

> 익명은 **작성자의 신원을 시스템에서 제거하는 것이 아니라 다른 사용자에게 공개하지 않는 방식**으로 처리한다.

# 7. 게시글 상세

게시글을 선택하면 상세 내용을 확인할 수 있다.

### 표시 정보

* 작성자 또는 익명
* 작성일
* 본문
* 첨부파일
* 댓글
* 대댓글

작성자 본인은 자신의 게시글을 수정하거나 삭제할 수 있다.

관리자는 모든 게시글을 삭제할 수 있다.

---

# 8. 댓글

게시글에 댓글을 작성할 수 있다.

### 지원 기능

* 댓글 작성
* 댓글 수정
* 댓글 삭제
* 대댓글 작성
* 대댓글 수정
* 대댓글 삭제

### 구조

```text
게시글
│
├─ 댓글 1
│   ├─ 대댓글 1
│   └─ 대댓글 2
│
├─ 댓글 2
│
└─ 댓글 3
```

댓글 작성자는 자신의 댓글을 관리할 수 있으며, 관리자는 필요 시 댓글을 삭제할 수 있다.

### 익명 게시글의 댓글

익명 게시글이라고 해서 댓글까지 자동으로 익명 처리하지 않는다.

MVP에서는 **댓글은 기본적으로 실명**으로 표시한다.

---

# 9. 좋아요 및 인기 기능

커뮤니티에서는 다음 기능을 제공하지 않는다.

* 좋아요
* 싫어요
* 인기글
* 추천글
* 조회수 기반 랭킹
* 작성자별 인기 순위

이는 기업 내 직급 관계에 따른 불필요한 평가·반응 경쟁을 방지하고, 직원들이 부담 없이 소통할 수 있는 환경을 만들기 위한 것이다.

> 커뮤니티는 **인기를 얻기 위한 공간이 아니라 편하게 이야기하는 공간**을 지향한다.

---

# 10. 게시글 삭제

게시글 삭제 권한은 다음과 같이 정의한다.

| 사용자    | 본인 게시글 | 타인 게시글 |
| ------ | -----: | -----: |
| 일반 사용자 |  삭제 가능 |  삭제 불가 |
| 관리자    |  삭제 가능 |  삭제 가능 |

삭제된 게시글은 일반 사용자에게 노출하지 않는다.

관리자에 의한 삭제가 필요한 경우에도 실제 데이터 처리 방식은 시스템의 감사 및 운영 정책에 따라 별도로 관리할 수 있다.

# 11. 소모임

## 11.1 기능 개요

소모임은 특정 관심사나 목적을 가진 직원들이 모여 지속적으로 소통할 수 있는 **프라이빗한 커뮤니티 공간**이다.

예:

* ⚽ 풋살 모임
* 🎮 게임 모임
* 📚 독서 모임
* 🎸 음악 모임
* 🏃 러닝 모임
* 💻 개발 스터디

자유게시판과 달리 소모임에는 **멤버 개념과 가입 방식**이 존재한다.

---

# 12. 소모임 생성

모든 직원은 소모임을 생성할 수 있다.

소모임을 생성한 사용자는 기본적으로 해당 소모임의 **운영자**가 된다.

### 입력 항목

| 항목        | 필수 | 설명                   |
| --------- | -: | -------------------- |
| 소모임명      |  O | 소모임 이름               |
| 소개        |  O | 소모임 목적 및 활동 내용       |
| 대표 이미지    |  X | 소모임 대표 이미지           |
| 가입 방식     |  O | 자유가입 / 승인 / 초대       |
| 소모임 공개 여부 |  - | 초기 MVP에서는 소모임 목록에 공개 |

---

# 13. 소모임 가입 방식

소모임 생성자는 다음 세 가지 가입 방식을 선택할 수 있다.

### 13.1 자유가입

직원이 별도의 승인 없이 바로 소모임에 가입할 수 있다.

```text
[소모임 가입]
       ↓
    즉시 가입
```

예:

> 사내 풋살 모임
> 사내 누구나 자유롭게 가입

---

### 13.2 운영자 승인

직원이 가입 신청을 하면 운영자가 승인한 후 멤버가 된다.

```text
가입 신청
    ↓
운영자 확인
    ↓
승인 / 거절
```

예:

> 독서 모임
> 가입 신청 후 운영자 승인

---

### 13.3 초대 전용

운영자가 초대한 직원만 소모임에 가입할 수 있다.

```text
운영자 초대
    ↓
초대받은 직원
    ↓
가입
```

예:

> 소규모 프로젝트성 모임
> 운영자가 지정한 구성원만 참여

---

# 14. 소모임 공개 범위

소모임의 존재 자체는 전 직원에게 공개할 수 있다.

그러나 **소모임 내부 게시글과 활동 내용은 멤버에게만 공개**한다.

```text
전 직원
│
├─ 소모임 이름 확인 ○
├─ 소모임 소개 확인 ○
├─ 멤버 수 확인 ○
│
└─ 내부 게시글 확인 ✕
          ↓
       소모임 멤버
          ↓
       게시글 확인 ○
```

이를 통해 직원이 새로운 소모임을 발견할 수 있으면서도 실제 활동 공간은 프라이빗하게 유지한다.

# 15. 소모임 멤버

소모임에는 다음 역할을 둔다.

| 역할  | 권한                    |
| --- | --------------------- |
| 운영자 | 소모임 관리, 멤버 관리, 게시글 관리 |
| 멤버  | 게시글 작성, 댓글, 소모임 활동    |
| 비회원 | 소모임 정보 확인             |

### 운영자 주요 기능

* 소모임 정보 수정
* 가입 신청 승인/거절
* 멤버 관리
* 운영자 변경
* 소모임 폐쇄

---

# 16. 소모임 게시글

소모임 멤버는 소모임 내부에 게시글을 작성할 수 있다.

### 기능

* 게시글 작성
* 게시글 수정
* 게시글 삭제
* 댓글
* 대댓글
* 첨부파일

게시글은 소모임 멤버만 열람할 수 있다.

```text
소모임
│
├─ 소개
├─ 멤버
│
└─ 게시글
     ├─ 게시글 1
     ├─ 게시글 2
     └─ 게시글 3
```

---

# 17. 소모임 탈퇴

멤버는 자신이 가입한 소모임에서 탈퇴할 수 있다.

단, 운영자가 탈퇴하는 경우에는 운영자 부재를 방지하기 위해 다음 정책을 적용한다.

> **운영자 탈퇴 시 다른 멤버에게 운영자 권한을 위임하거나 소모임을 폐쇄한다.**

MVP에서는 운영자 탈퇴 시 **다른 멤버를 운영자로 지정하도록 하는 방식**을 우선 적용한다.

---

# 18. 알림

커뮤니티 활동과 관련된 주요 이벤트에 대해 그룹웨어 내부 알림을 제공한다.

### 주요 알림 대상

| 이벤트          | 알림 대상   |
| ------------ | ------- |
| 내 게시글에 댓글 작성 | 게시글 작성자 |
| 내 댓글에 대댓글 작성 | 댓글 작성자  |
| 소모임 가입 신청    | 소모임 운영자 |
| 가입 신청 승인     | 신청자     |
| 가입 신청 거절     | 신청자     |
| 소모임 초대       | 초대 대상자  |
| 소모임 운영자 변경   | 변경 대상자  |
| 소모임 관련 주요 공지 | 소모임 멤버  |

알림을 클릭하면 해당 게시글 또는 소모임 화면으로 이동한다.

# 19. 검색

커뮤니티 내 게시글을 검색할 수 있다.

### 검색 대상

* 게시글 내용
* 게시글 제목을 사용하는 경우 제목
* 작성자

### 범위

```text
전체 커뮤니티 검색
        │
        ├─ 자유게시판
        │
        └─ 내가 접근 가능한 소모임
```

소모임 게시글은 해당 소모임의 멤버에게만 검색 결과가 노출되어야 한다.

# 22. 데이터 구조

Firebase/Firestore 기반 구조를 고려하여 다음과 같이 분리한다.

```text
communities
 └─ communityId
      ├─ type
      ├─ name
      ├─ description
      ├─ imageUrl
      ├─ joinPolicy
      ├─ ownerId
      ├─ memberCount
      ├─ isActive
      ├─ createdAt
      └─ updatedAt
```

자유게시판은 별도의 커뮤니티를 생성하는 방식보다는 시스템에서 고정된 공간으로 처리할 수 있다.

게시글:

```text
communityPosts
 └─ postId
      ├─ communityId
      ├─ authorId
      ├─ isAnonymous
      ├─ title
      ├─ content
      ├─ attachments
      ├─ status
      ├─ createdAt
      └─ updatedAt
```

댓글:

```text
communityComments
 └─ commentId
      ├─ postId
      ├─ parentCommentId
      ├─ authorId
      ├─ content
      ├─ createdAt
      └─ updatedAt
```

소모임 멤버:

```text
communityMembers
 └─ memberId
      ├─ communityId
      ├─ userId
      ├─ role
      ├─ status
      ├─ joinedAt
      └─ updatedAt
```

가입 신청:

```text
communityJoinRequests
 └─ requestId
      ├─ communityId
      ├─ userId
      ├─ status
      ├─ createdAt
      └─ processedAt
```

# 25. 최종 사용자 구조

최종적인 사용자 경험은 다음과 같이 구성한다.

```text
커뮤니티
│
├─────────────────────────────┐
│                             │
▼                             ▼
자유게시판                    소모임
│                             │
│                             ├─ 소모임 목록
│                             │
│                             └─ 소모임 상세
│                                  │
├─ 전체 피드                    ├─ 소개
├─ 글 작성                      ├─ 멤버
├─ 실명/익명                    └─ 게시글
├─ 댓글                              │
├─ 대댓글                            ├─ 글 작성
├─ 첨부파일                          ├─ 댓글
└─ 검색                              ├─ 대댓글
                                     └─ 첨부파일
```

## 핵심 원칙

**자유게시판**

> 전 직원이 부담 없이 들어와 자유롭게 이야기하는 열린 공간

**소모임**

> 관심사가 같은 직원들이 모여 멤버끼리 편하게 소통하는 작은 공간

**커뮤니티 전체**

> SNS의 편리한 소통 방식은 가져오되, 좋아요·랭킹·인기 경쟁과 같은 조직 내 불필요한 경쟁 요소는 배제한다.
