# 인명관리 기능명세서

## 1. 기능 개요

### 1.1 목적

인명관리는 그룹웨어에 등록된 임직원의 기본정보와 조직정보를 관리하고, 전자결재·문서관리·주소록·조직도 등 그룹웨어의 각 기능에서 공통으로 사용할 수 있도록 **사용자 기준정보를 제공하는 기능**이다.

본 기능은 인사관리(HR) 전체를 대체하지 않으며, 그룹웨어 운영에 필요한 최소한의 직원 및 조직 정보를 관리하는 것을 목적으로 한다.

### 1.2 주요 기능

* 임직원 조회
* 임직원 상세정보 조회
* 임직원 등록 및 수정
* 임직원 재직상태 관리
* 부서 및 직급/직책 정보 관리
* 조직도 조회
* 임직원 검색
* 전자결재와의 사용자 정보 연계

# 4. 임직원 목록

## 4.1 기능 설명

그룹웨어에 등록된 임직원을 목록으로 조회하고 검색·필터링할 수 있다.

## 4.2 주요 기능

* 전체 임직원 조회
* 이름 검색
* 사번 검색
* 부서별 필터
* 직급별 필터
* 재직상태별 필터
* 임직원 상세정보 이동

## 4.3 목록 항목

| 항목   | 설명          |
| ---- | ----------- |
| 프로필  | 사용자 프로필 이미지 |
| 사번   | 직원 고유 사번    |
| 이름   | 직원명         |
| 부서   | 현재 소속 부서    |
| 직급   | 직급          |
| 직책   | 직책          |
| 이메일  | 업무용 이메일     |
| 연락처  | 업무용 연락처     |
| 재직상태 | 재직/휴직/퇴직 등  |
| 관리   | 상세보기/수정     |

## 4.4 검색

검색어 입력 시 다음 정보를 기준으로 검색할 수 있다.

* 이름
* 사번
* 이메일

예:

```text
[검색어 입력] [검색]

검색 대상: 이름 / 사번 / 이메일
```

# 5. 임직원 등록

## 5.1 기능 설명

관리자가 그룹웨어에서 사용할 임직원 정보를 등록한다.

## 5.2 입력 항목

### 필수

| 항목    | 필수 | 설명           |
| ----- | -: | ------------ |
| 사번    |  O | 직원 식별번호      |
| 이름    |  O | 직원명          |
| 소속 부서 |  O | 직원의 현재 소속 부서 |
| 직급    |  O | 사원/대리/과장 등   |
| 재직상태  |  O | 기본값: 재직      |

### 선택

| 항목      | 필수 | 설명              |
| ------- | -: | --------------- |
| 프로필 이미지 |  X | 사용자 프로필 이미지     |
| 직책      |  X | 팀장/파트장 등        |
| 이메일     |  X | 업무용 이메일         |
| 연락처     |  X | 업무용 전화번호        |
| 입사일     |  X | 입사일             |
| 로그인 계정  |  X | 그룹웨어 사용자 계정과 연결 |

## 5.3 등록 규칙

1. 사번은 중복될 수 없다.
2. 필수 정보가 입력되지 않은 경우 등록할 수 없다.
3. 존재하지 않는 부서는 선택할 수 없다.
4. 임직원 등록 시 기본 재직상태는 `재직`으로 설정한다.
5. 로그인 계정과 연결되는 경우 하나의 직원에게 하나의 사용자 계정을 연결하는 것을 원칙으로 한다.

# 6. 임직원 정보 수정

## 6.1 기능 설명

관리자는 등록된 임직원의 조직 및 기본정보를 수정할 수 있다.

## 6.2 수정 가능 정보

* 프로필 이미지
* 이름
* 부서
* 직급
* 직책
* 이메일
* 연락처
* 입사일
* 재직상태

## 6.3 수정 규칙

### 현재 정보

임직원의 현재 조직정보가 변경되면 이후 그룹웨어 기능에서 변경된 정보를 사용한다.

예:

```text
기존
홍길동 → 개발팀 → 과장

변경
홍길동 → 기획팀 → 과장
```

변경 후 새로운 결재선이나 조직도에서는 기획팀 소속으로 표시한다.

### 기존 전자결재 문서

임직원 정보가 변경되더라도 **이미 완료된 전자결재 문서의 결재 이력 및 당시 표시 정보는 변경하지 않는다.**

즉,

```text
현재 인명정보
      ↓
현재 조직/직급

과거 결재문서
      ↓
결재 당시의 결재자 및 결재정보 유지
```

를 원칙으로 한다.

# 7. 재직상태 관리

## 7.1 상태값

MVP에서는 다음 상태를 사용한다.

| 상태 | 설명            |
| -- | ------------- |
| 재직 | 현재 정상적으로 근무 중 |
| 휴직 | 휴직 상태         |
| 퇴직 | 퇴직 처리된 상태     |

필요한 경우 추후 `입사예정`, `파견`, `정직` 등의 상태를 확장할 수 있다.

## 7.2 퇴직 처리

임직원을 퇴직 처리하는 경우 직원 데이터를 삭제하지 않고 재직상태를 `퇴직`으로 변경한다.

```text
홍길동
상태: 재직
      ↓
퇴직 처리
      ↓
상태: 퇴직
```

### 삭제하지 않는 이유

전자결재 등 기존 업무 기록에서 해당 사용자를 참조하고 있기 때문이다.

따라서 직원의 실제 데이터를 삭제하면 과거 문서의 결재자 정보가 유실될 수 있다.

**원칙: 임직원 데이터는 물리적으로 삭제하지 않고 상태값으로 관리한다.**

# 8. 조직정보

## 8.1 부서

직원은 하나의 기본 소속 부서를 가진다.

예:

```text
기술본부
 └─ 개발팀
     └─ 홍길동
```

부서 변경 시 직원의 현재 소속 부서를 변경한다.

## 8.2 직급

직원의 직급을 관리한다.

예:

```text
사원
주임
대리
과장
차장
부장
```

※ 회사의 실제 직급 체계에 맞게 관리한다.

## 8.3 직책

직급과 별도로 조직 내 역할을 관리한다.

예:

```text
팀원
팀장
파트장
본부장
```

직급과 직책은 별개의 정보로 관리한다.

예:

```text
홍길동
직급: 과장
직책: 팀장
```

# 10. 전자결재 연계

인명관리는 전자결재에서 사용하는 **사용자 기준정보의 원천**으로 활용한다.

## 10.1 결재선 사용자 검색

전자결재에서 결재자를 검색할 때 인명관리의 직원 정보를 사용한다.

```text
[결재자 검색]

홍길동
개발팀 / 과장 / 팀장
```

## 10.2 결재선 선택 제한

다음 사용자는 신규 결재선에서 기본적으로 선택할 수 없도록 한다.

* 퇴직자
* 비활성 계정 사용자
* 그룹웨어 사용이 중지된 사용자

단, 과거 결재문서에서는 해당 사용자의 결재 이력을 정상적으로 표시해야 한다.

## 10.3 결재선 자동화와의 연계

향후 자동 결재선 기능에서 다음 정보를 활용할 수 있다.

```text
기안자
 ↓
소속 부서
 ↓
직급
 ↓
직책
 ↓
상위 부서
 ↓
결재권자
```

예:

```text
기안자: 홍길동
부서: 개발팀
직급: 과장
       ↓
개발팀 팀장
       ↓
기술본부 본부장
```

따라서 인명관리의 조직정보는 향후 **기본 결재선 및 자동 결재선 구성의 기준정보**가 된다.

# 13. 데이터 관리 원칙

## 13.1 직원 삭제 금지

전자결재 및 업무 이력과 연결된 직원은 물리적으로 삭제하지 않는다.

```text
잘못된 방식
직원 삭제 → 관련 업무 데이터 참조 오류

권장 방식
직원 상태 → 퇴직
```

## 13.2 과거 업무기록 보존

직원의 현재 정보가 변경되더라도 기존 업무기록은 영향을 받지 않아야 한다.

특히 전자결재의 경우:

```text
현재 홍길동
개발팀 / 부장
```

으로 변경되었더라도,

```text
2025년 결재문서
홍길동 / 개발팀 / 과장
```

의 결재 기록을 현재 정보로 덮어쓰지 않는다.

## 13.3 사용자 ID와 직원 정보의 관계

로그인 계정과 직원 정보는 논리적으로 구분한다.

```text
사용자 계정(User)
       │
       └── 직원(Employee)
                │
                ├── 부서
                ├── 직급
                ├── 직책
                └── 재직상태
```

이를 통해 계정 인증과 직원 조직정보를 분리하여 관리한다.

# 14. 주요 업무 흐름

## 14.1 신규 직원 등록

```text
관리자
 ↓
인명관리
 ↓
임직원 등록
 ↓
기본정보 입력
 ↓
부서/직급/직책 지정
 ↓
재직상태 = 재직
 ↓
저장
 ↓
조직도 및 그룹웨어 기능에 반영
```

## 14.2 부서 이동

```text
관리자
 ↓
직원 조회
 ↓
직원 상세
 ↓
소속 부서 변경
 ↓
저장
 ↓
현재 조직도 변경
 ↓
향후 결재선/문서 기능에 변경정보 적용
```

## 14.3 퇴직 처리

```text
관리자
 ↓
직원 조회
 ↓
직원 상세
 ↓
재직상태 = 퇴직
 ↓
저장
```

처리 후:

* 조직도에서 현재 재직자 목록에서는 제외
* 신규 결재자 검색에서 제외
* 로그인 차단 정책과 연계
* 기존 결재문서의 결재이력은 유지

# 16. MVP에서 제외할 기능

초기 그룹웨어에서는 인명관리의 범위를 불필요하게 확대하지 않는다.

다음 기능은 추후 확장 대상으로 한다.

* 급여관리
* 근태관리
* 연차관리

# 17. MVP 최종 정의

인명관리 MVP는 다음 네 가지를 핵심으로 한다.

> **① 직원 정보 관리**
> **② 조직 정보 연계**
> **③ 재직상태 관리**
> **④ 전자결재 등 그룹웨어 기능에 사용자 기준정보 제공**

따라서 인명관리를 독립적인 대규모 인사시스템으로 구현하기보다는,

```text
           조직관리
              │
              ↓
          ┌───────┐
          │ 인명관리 │
          └───┬───┘
              │
      ┌───────┼───────┐
      ↓       ↓       ↓
   전자결재  문서관리  주소록
```

와 같이 **그룹웨어의 공통 사용자 기준정보 영역**으로 설계하는 것을 권장한다.
