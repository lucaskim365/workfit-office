좋아. 지금까지 정의한 기능을 보면 **커뮤니티는 일반적인 게시판 UI보다 조금 더 서비스형으로 만드는 게 맞아.** 특히 자유게시판을 Pinterest식 Masonry 피드로 잡으면 우리가 원했던 "가볍게 들어와서 구경하고, 부담 없이 글 쓰는 공간"이라는 성격이 잘 살아날 것 같아.

다만 **소모임까지 똑같은 UI로 만들면 오히려 복잡해질 수 있으니**, 둘의 성격을 UI에서도 다르게 표현하는 걸 추천해.

# 1. 전체 커뮤니티 구조

우선 나는 이렇게 잡고 싶어.

```text
커뮤니티
│
├── 자유게시판
│     └── Masonry 피드
│
└── 소모임
      ├── 소모임 탐색
      ├── 내 소모임
      └── 소모임 상세
            ├── 홈
            ├── 게시글
            └── 멤버
```

화면으로 표현하면:

```text
┌─────────────────────────────────────────────────────────┐
│ 커뮤니티                                  🔔  🔍  👤    │
├──────────────┬──────────────────────────────────────────┤
│              │                                          │
│ 자유게시판    │              콘텐츠 영역                 │
│              │                                          │
│ 소모임       │                                          │
│              │                                          │
│ 내 소모임     │                                          │
│              │                                          │
│              │                                          │
└──────────────┴──────────────────────────────────────────┘
```

여기서 **왼쪽을 너무 크게 만들지 않는 것**이 중요해.

커뮤니티는 메뉴 탐색보다 콘텐츠를 보는 것이 핵심이니까.

# 3. 카드에 모든 내용을 보여줄 필요는 없어

Masonry를 쓰면 카드 높이가 콘텐츠에 따라 달라지니까 오히려 장점이 있어.

예를 들어:

### 짧은 글

```text
┌──────────────┐
│ 홍채원        │
│               │
│ 오늘 날씨     │
│ 정말 좋네요! │
│               │
│ 💬 2          │
└──────────────┘
```

### 긴 글

```text
┌──────────────┐
│ 익명          │
│               │
│ 회사 생활을   │
│ 하다보면...  │
│               │
│ ...           │
│               │
│ 💬 8          │
└──────────────┘
```

### 사진 게시물

```text
┌──────────────┐
│ 김철수        │
│               │
│ 주말에 다녀온 │
│ 곳입니다.     │
│               │
│   [ 사진 ]    │
│               │
│ 💬 4          │
└──────────────┘
```

이렇게 하면 **글의 성격 자체가 카드의 높이와 형태를 만들어주는 느낌**이 생겨.

# 4. 자유게시판 상단

나는 상단에 기능을 많이 넣지 않을 거야.

```text
┌─────────────────────────────────────────────────────────┐
│ 자유게시판                                               │
│ 직원들과 자유롭게 이야기를 나눠보세요.                  │
│                                                         │
│ [ 전체 ▼ ] [ 검색                         🔍 ] [＋ 글쓰기 ]│
└─────────────────────────────────────────────────────────┘
```

여기서 `전체` 필터는 나중에 필요하면:

* 최신글
* 내가 작성한 글
* 익명글

등으로 확장할 수 있지만 **MVP에서는 최신글 하나만 있어도 충분**해.

# 5. 글 작성은 Modal보다 별도 화면?

여기서는 네가 이전 전자결재에서 고민했던 것과는 조금 달라.

커뮤니티 글 작성은 **Modal이 더 적합**하다고 생각해.

왜냐하면 작성 내용이 비교적 짧고, 사용자가 현재 피드에서 벗어날 이유가 별로 없기 때문이야.

```text
                  ┌─────────────────────────┐
                  │ 새 글 작성          ✕   │
                  ├─────────────────────────┤
                  │                         │
                  │ ○ 실명   ○ 익명         │
                  │                         │
                  │ 무슨 이야기를 하고       │
                  │ 싶으신가요?              │
                  │                         │
                  │                         │
                  │                         │
                  │                         │
                  │ 📎 파일 추가             │
                  │                         │
                  ├─────────────────────────┤
                  │             [등록하기]   │
                  └─────────────────────────┘
```

특히 **익명/실명 선택을 글 작성창에서 매우 명확하게** 보여주는 게 좋아.

# 6. 게시글 상세는 Drawer도 괜찮아

여기서 재미있는 선택지가 있어.

Masonry 카드를 클릭했을 때 새로운 페이지로 이동하는 대신 **오른쪽 Drawer**를 열 수 있어.

```text
┌─────────────────────────────┬───────────────────────────┐
│                             │ 게시글                    │
│                             │                       ✕   │
│     다른 카드들             │                           │
│                             │ 홍채원                    │
│                             │ 오늘 점심 뭐 드실까요?   │
│                             │                           │
│                             │ 회사 근처 맛집 추천...   │
│                             │                           │
│                             │ ───────────────────────   │
│                             │                           │
│                             │ 댓글 3                    │
│                             │                           │
│                             │ 김철수                    │
│                             │ ○○식당 추천합니다.       │
│                             │                           │
│                             │ 이영희                    │
│                             │ 저도 가봤어요!            │
│                             │                           │
│                             │ [댓글 작성...]            │
└─────────────────────────────┴───────────────────────────┘
```

이 방식의 장점은 **피드를 보고 있던 흐름이 끊기지 않는다는 것**이야.

나는 자유게시판에는 이 방식을 꽤 추천해.

# 7. 소모임은 완전히 다르게

소모임은 Masonry 피드보다 **카드형 탐색 화면**이 더 어울려.

```text
소모임                                      ＋ 소모임 만들기

┌────────────────┐ ┌────────────────┐ ┌────────────────┐
│                │ │                │ │                │
│   ⚽            │ │   📚            │ │   🎮            │
│                │ │                │ │                │
│ 퇴근 후 풋살    │ │ 독서 모임       │ │ 게임 같이해요   │
│                │ │                │ │                │
│ 회원 12명       │ │ 회원 8명        │ │ 회원 15명       │
│ 자유가입        │ │ 승인 필요       │ │ 초대 전용       │
│                │ │                │ │                │
│ [소모임 보기]   │ │ [소모임 보기]   │ │ [소모임 보기]   │
└────────────────┘ └────────────────┘ └────────────────┘
```

여기서 중요한 게 **가입 방식 표시**야.

사용자가 소모임을 둘러보다가

> "아, 이건 누구나 가입할 수 있구나."

를 바로 알 수 있어야 해.

## 12. 특히 나는 이 UI 원칙을 추천해

지금까지 이야기한 방향을 UI에 그대로 녹이면:

**자유게시판**

> 🧱 **Masonry + 카드 + Drawer**

가 핵심.

**소모임**

> 🗂️ **소모임 카드 + 내부 피드**

가 핵심.

그리고 전체적으로:

* 좋아요 ❌
* 인기순 ❌
* 랭킹 ❌
* 과도한 숫자 표시 ❌
* 실명/익명 명확하게 표시
* 댓글은 가볍게
* 글 작성은 빠르게
* 소모임은 프라이빗하게

이렇게 가져가면 상당히 깔끔할 것 같아.

---

### 여기서 하나 결정하면 실제 화면 설계로 넘어갈 수 있어

**자유게시판 Masonry를 어느 정도까지 "SNS스럽게" 만들지**가 중요해.

내 추천은 **중간 정도**야.

**A. 미니멀**

> 글 + 작성자 + 댓글만. 아주 담백한 사내 게시판.

**B. 추천 ⭐**

> 글 + 이미지 + 작성자 + 댓글 + 카드형 Masonry. SNS 느낌은 있지만 기능은 단순.

**C. SNS형**

> 프로필, 이미지, 동영상, 멘션, 해시태그, 다양한 미디어 등을 적극적으로 지원.

지금까지 우리가 잡은 **"가볍게 소통하지만 SNS의 경쟁 요소는 제거한다"**는 방향에는 **B가 가장 잘 맞아 보여.**
