# [기획서 & 개발 명세서] 전자결재 '관련 문서 연결 (relatedDocs)' 기능

## 1. 개요 및 목적
* **개요**: 신규 전자결재 문서 작성 시, 과거에 이미 결재 완료(`status === '완료'`)된 기결재 문서를 참조용으로 연동(유첨)하여 상신할 수 있는 기능입니다.
* **목적**:
  * 과거 연관 품의서/계약서/보고서의 수동 다운로드 & 재업로드 번거로움 해소
  * 결재권자가 이전 업무 맥락을 한눈에 파악하여 신속하고 정확한 의사결정을 하도록 지원
  * 완료된 결재 문서 간의 상호 참조 관계 및 이력 보존 추적성 확보

---

## 2. 프로젝트 스택 및 아키텍처 연계 명세

`workfit-office` 프로젝트의 기존 **도메인 스키마 - Data Access Layer - UI 모듈** 구조에 맞추어 설계되었습니다.

### 2.1 Domain Schema (`src/domain/approvalDoc/schema.ts`)
결재 문서 헤더(`approvalDocSchema`)에 `relatedDocs` 스냅샷 구조체 배열을 추가합니다.

```typescript
/** 연결된 관련 문서 (스냅샷 & 참조) */
export const relatedDocSchema = z.object({
  /** 대상 기결재 문서 ID (PK) */
  docId: z.string().min(1),
  /** 문서 번호 (AP-YYMMDD-NNN) */
  docNo: z.string().min(1),
  /** 문서 제목 */
  title: z.string(),
  /** 문서 서식/유형 */
  docType: z.string(),
  /** 기안자 성명 (+직급) */
  drafterName: z.string(),
  /** 기안 부서 */
  drafterDept: z.string(),
  /** 결재 완료 일자 (ISO 또는 YYYY-MM-DD) */
  completedAt: z.string().nullable().optional(),
});

export type RelatedDoc = z.infer<typeof relatedDocSchema>;

// approvalDocSchema 확장
export const approvalDocSchema = z.object({
  // ... 기존 필드
  /** 연결된 관련 기결재 문서 리스트 */
  relatedDocs: z.array(relatedDocSchema).default([]),
});
```

### 2.2 Repository / Query Layer (`src/data/approvalDoc/approvalDoc.repo.ts`, `src/features/gw/useApprovals.ts`)
* **관련 문서 검색 쿼리 함수**: `approvalDocRepo.searchCompletedDocs({ userId, dept, keyword, startDate, endDate })`
* **검색 범위 정책**:
  * 연결 가능한 관련 문서는 **완료 상태(`status === '완료'`)** 문서로 한정합니다.
  * 로그인 유저가 열람 권한을 가진 완료 문서에 한해 검색 및 연동이 가능합니다:
    1. **기안자**: 본인이 기안한 완료 문서 (`drafterId === userId`)
    2. **결재선**: 결재자(결재/합의/전결/대결)로서 결재선에 포함되었던 완료 문서 (`steps.approverId === userId`)
    3. **수신/참조처**: 사용자 본인 또는 본인 부서가 수신/참조처로 지정된 완료 문서 (`recipients`에 userId 또는 userDept 포함)
    4. **시행자/시행 부서**: 본인 또는 본인 부서가 시행자로 지정된 완료 문서 (`execution.targetId === userId` 또는 `execution.targetId === userDeptId`)

## 3. 화면별 상세 기능 및 UI/UX 인터랙션

### ① 기안 작성 모달 (`ApprovalDraftModal.tsx`)
* **위치**: 첨부 파일 영역 하단에 `[🔗 관련 문서 연결]` 섹션 배치
* **인터랙션**:
  * `[+ 관련 문서 선택]` 버튼 클릭 시 **관련 문서 검색 팝업 모달 (`RelatedDocSearchModal`)** 오픈
  * 이미 선택된 관련 문서는 태그/리스트 형태로 표출되며, `[✕]` 버튼을 통해 연결 해제 가능 (원문 삭제가 아닌 링크 해제)
  * 작성 중 선택된 관련 문서 클릭 시, 팝업 미리보기(`ApprovalDocumentViewModal`)로 원본 내용 교차 검증 가능

### ② 관련 문서 검색 팝업 (`RelatedDocSearchModal.tsx`) [신규]
* **검색 필터**: 문서 제목/번호 키워드 검색, 기안자/부서 검색, 완료 기간 설정 (최근 1개월, 3개월, 1년, 전체)
* **목록 테이블**: 문서번호, 서식종류, 제목, 기안자, 완료일시 표시
* **선택 및 반영**: 체크박스로 다중 선택 후 `[선택 완료]` 클릭 시 기안 작성 폼의 `relatedDocs` 상태에 추가 (중복 추가 자동 방지)

### ③ 결재 심사 및 문서 조회 화면 (`ApprovalExecutionPanel.tsx`, `ApprovalDocumentView.tsx`)
* **노출**: 문서 본문 및 결재선 하단에 **[관련 문서 (N건)]** 카드가 렌더링됨
* **열람**: 연결된 관련 문서 항목을 클릭하면 팝업 모달로 해당 완료 문서의 전체 내용(기안 본문, 결재선 이력, 첨부파일 등)을 즉시 열람 가능
* **권한 처리**: 본 신규 문서의 결재권자/참조자는 연결된 관련 문서에 대해서도 조회 권한을 상속받아 즉시 확인 가능

## 4. 예외 케이스 및 보안/이력 정책

1. **원문 상태 변경 (삭제/폐기/회수 등)**:
   * 관련 문서 열람 클릭 시, 대상 문서가 `status === '삭제'`이거나 DB에 존재하지 않는 경우:
   * *"삭제되었거나 열람할 수 없는 문서입니다."* 알림 안내 및 예외 처리
2. **이력 보존성**:
   * 문서 저장/상신 시점의 관련 문서 정보(`docNo`, `title`, `drafterName` 등)를 스냅샷 형태로 저장하여 원본 문서의 제목이 바뀌더라도 기안 당시의 연동 맥락을 보존합니다.
3. **PWA / 모바일 대응**:
   * 모바일 화면(`MobileApprovalDetail.tsx`)에서도 관련 문서 목록 및 클릭 시 모바일용 상세 팝업으로 원활히 연결되도록 지원합니다.

## 5. 민감정보 보호 및 마스킹 (보안) 정책

관련 문서 연동 시 채용 품의서, 연봉 계약서, 개인 신상 정보 등 민감 데이터가 무분별하게 노출되는 것을 방지하기 위한 보안 방안입니다.

### 5.1 [Phase 1: 단기 보안 정책] UI 보안 가이드 및 사내 권한 안내
* **운영 방식**: 시스템 자동 마스킹 기능(Viewing Masking) 도입 전(Phase 1)에는, 사용자에게 관련 문서 열람 권한 범위 및 보안 주의사항을 직관적으로 안내합니다.
* **UI 가이드 안내**:
  * 관련 문서 선택 팝업(`RelatedDocSearchModal`) 및 기안 작성 폼 하단에 보안 안내 문구 배치:
    > 💡 **보안 안내**: 관련 문서 연동 시 원본 문서의 열람 권한이 그대로 유지됩니다. 개인정보나 연봉 등 민감 정보가 포함된 기결재 문서를 선택할 때는 결재선 지정 및 보안 지침에 유의해 주세요.

### 5.2 [Phase 2: 시스템 보안 고도화] 동적 필드 보안 마스킹 (Viewing Masking)
* **시스템 자동 보안 처리**:
  * Phase 2 고도화 적용 후에는 사용자가 별도로 문서를 수동 수정/가공할 필요 없이, 시스템이 열람자의 권한에 따라 민감 정보를 자동으로 마스킹 처리하여 보여줍니다.
* **보안 필드(Secret Field) 지정**:
  * 결재 서식 관리자(`ApprovalFormScreen`)에서 서식 항목(예: `주민등록번호`, `연봉`, `비고(민감사항)`) 생성 시 `isSecret: true` (보안 필드) 속성을 지정할 수 있게 합니다.
* **열람 권한별 차등 노출 (Viewing Masking)**:
  * 관련 문서 팝업 열람(`ApprovalDocumentViewModal`) 시, 현재 열람자가 **최종 권한자(기안자, 인사/재무 관리자 등)**가 아닌 경우 보안 필드의 값이 시스템에 의해 자동으로 마스킹 처리되어 노출됩니다:
    * 예: `880101-1******`, `5*,***,***원` 또는 `[보안 처리된 정보입니다]`
* **상속 보존**:
  * 관련 문서로 연결되어 상신된 문서에서도 원본 서식의 보안 필드 마스킹 규칙이 그대로 상속 적용되어 권한이 없는 결재권자에게는 마스킹된 데이터만 노출됩니다.
* **⚠️ 데이터 불변성 및 기존 서식/문서 무결성 보장 (절대 원칙)**:
  * 서식 관리창(`ApprovalFormScreen`)에서 서식 정의나 보안 필드를 수정/추가하더라도, **이미 기안되거나 완료된 기존 결재 문서 데이터(`approvalDocs`) 및 기존 서식을 절대로 덮어씌우거나 변형해서는 안 됩니다**.
  * 기존 결재 문서는 기안 당시 스냅샷된 양식/필드 데이터 구조를 보존해야 하며, 서식 덮어쓰기로 인한 과거 결재 문서 파손 및 서식 데이터 오염을 근본적으로 차단해야 합니다.

### 5.3 [첨부 문서] 다운로드 및 출력 시 마스킹/워터마크
* **PDF/다운로드 워터마크**:
  * 관련 문서로 유첨된 기결재 문서를 다운로드하거나 인쇄할 때, 열람자 정보(열람자 성명/부서/일시) 및 **"참조용 관련문서"** 워터마크를 자동으로 삽입하여 무단 유출을 방지합니다.
