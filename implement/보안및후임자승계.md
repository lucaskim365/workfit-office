# 🛡️ 문서 보안 공개범위 설정 및 후임자 권한 승계 아키텍처 가이드라인

본 문서는 전자결재 시스템 내에서 민감 정보(연봉, 인사 평가 등)의 보안 제어를 위한 **1단계: 문서별 공개범위 설정**과 퇴사자/부서 이동에 따른 연속성 보장을 위한 **2단계: 후임자 권한 승계 프로세스**의 설계 및 유연한 개발 가이드라인을 정리합니다.

---

## 1단계: 문서별 공개범위 설정 (작성 시점의 보안)

기존 `ApprovalDoc` 내의 일괄적인 보안 등급을 보완하여, 기안자가 상신하는 시점에 문서의 수집 및 가시성 경계를 제한할 수 있는 **공개범위(Visibility)** 기능을 이식합니다.

### 1. 데이터 모델 정의 (`ApprovalDoc` 스키마 확장)
* `zod` 도메인 스키마에 `visibility` 필드 추가:
  ```typescript
  export const DOC_VISIBILITY = ['전사', '부서', '비공개'] as const;
  export type DocumentVisibility = (typeof DOC_VISIBILITY)[number];
  
  // schema.ts 내 추가
  visibility: z.enum(DOC_VISIBILITY).default('부서')
  ```

### 2. 열람 제어 규칙 (Access Control List)
`ApprovalDocumentView.tsx` 내부의 `canAccessDocument` 판별 로직을 업데이트하여 다음의 우선순위로 접근을 통제합니다:
1. **최고 기안 관리자/임원진(대표이사, 상무 등)**: 모든 문서 무조건 허용.
2. **기안자 본인 및 결재선 연관자(결재/합의/대결/참조인)**: 문서 공개범위와 상관없이 항상 열람 가능.
3. **지정 수신처(개인/부서)**: 수신 목록에 속해 있으면 항상 열람 가능.
4. **전사 공개**: 전체 사원 조회 가능.
5. **부서 공개**: 기안자와 조회자의 소속 부서가 일치(`doc.drafterDept === currentUser.dept`)할 때만 열람 가능.
6. **비공개**: 기안자 및 결재선 관계자 외 전사 임직원 열람 차단.

## 💡 UX 단순화 및 보안 자동화 (Best Practice)

기안자의 인지 부하(Cognitive Load)를 최소화하고 휴먼 에러에 의한 보안 사고를 차단하기 위해 **"서식 템플릿 상속 및 자동 매핑"**을 기본 원칙으로 합니다.

### 1. 서식별 자동 매핑 테이블
서식 마스터 설계 시점에 기본 보안 등급과 공개범위가 결합되어 상속됩니다. 기안자는 개별 보안 등급을 복잡하게 고르지 않습니다.

| 서식 유형 (예시) | 기본 공개범위 | 백그라운드 보안 등급 | UX 제공 피드백 메시지 |
| :--- | :--- | :--- | :--- |
| **일반 기안서** | 전사 | 일반 | "본 문서는 전사 임직원에게 공개됩니다." |
| **지출결의서** | 부서 | 대외비 | "본 문서는 소속 부서원만 문서함에서 조회 가능합니다." |
| **채용/인사 품의서** | 비공개 | 극비 | "🔒 보안 규정: 본 서식은 결재선 관계자 외 열람이 자동 차단됩니다." |

### 2. 고급 설정 오버라이드 (Advanced Escape Hatch)
* 일반 사용자에게는 보안 등급 설정을 숨기거나 비활성화 상태로 유지합니다.
* 서식 관리자 페이지에서 **"기안자 임의 변경 허용"** 옵션이 켜져 있는 서식에 한해서만, 기안 작성 화면 하단에 `고급 설정` 토글을 배치하여 기안자가 예외적으로 수동 조정을 할 수 있도록 비상구를 제공합니다.

## 2단계: 후임자 권한 승계 프로세스 (인계 연속성)

부서 이동 또는 퇴사(예: 류지광 이사 퇴사 ➔ 모란 대리 신규입사) 시 조직도 상 부서 일치 여부와 무관하게 전임자의 결재 권한과 문서 히스토리를 후임자에게 이관하는 규칙을 정의합니다.

### 1. 승계 정보 모델 정의 (`ApprovalSuccession`)
인사이동 이력을 추적 및 적용하기 위해 1:1 전임자-후임자 관계 테이블을 정의합니다.
```typescript
export interface ApprovalSuccession {
  id: string; // 승계 고유 ID
  predecessorId: string; // 전임자 사번 (예: 류지광)
  successorId: string; // 후임자 사번 (예: 모란)
  effectiveDate: string; // 승계 시작일 (ISO Date)
}
```

### 2. 결재 및 조회 권한 상속 메커니즘
* **결재 이관**: 결재 프로세스 엔진에서 다음 승인권자 목록(`currentApproverIds`)에 전임자가 있을 때, 후임자 로그인 시 승인 버튼 및 결재 처리 권한이 대결 권한 형태로 자동 상속 활성화됩니다.
* **조회 권한 이관**:
  - `ApprovalDocumentView`의 `canAccessDocument` 검사 시, 조회하려는 문서의 `drafterId`나 결재선(`steps.approverId`)에 **전임자가 포함되어 있다면**, 후임자에게 동일하게 열람 권한이 자동 부여되도록 검사 연산(Inherited Role-based check)을 우회합니다.
  ```typescript
  // 예시: 전임자 관계 조회
  const predecessors = getPredecessorsOf(currentUser.id); // ['류지광_ID']
  const isPredecessorRelated = predecessors.includes(doc.drafterId) || 
                               doc.steps.some(s => predecessors.includes(s.approverId));
  if (isPredecessorRelated) return true;
  ```

## 💡 개발 단계 권장 사항

1. **1단계(공개범위)**를 우선적으로 도입하여 기안 양식의 보안을 즉각적으로 강화합니다. (`ApprovalDraftModal.tsx`에 공개범위 토글 UI 적용)
2. **2단계(승계)**는 전임자-후임자 이관 정보를 관리자 화면에서 매핑할 수 있도록 점진적으로 백엔드 데이터에 확장해 나갑니다.
