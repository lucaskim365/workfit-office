# 긴급 선조치 사후 승인(후결) 프로세스 구현 사양 및 설계 계획서

> **📌 문서 목적**:  
> 본 문서는 긴급 장애 복구, 설비 고장 현장 수리, 입찰 마감 임박 등 정식 결재 승인을 기다릴 수 없는 긴급 상황 발생 시 선조치 후 사후 승인을 받는 **후결(Post-Approval) 프로세스**의 개념, 프로세스 비교, 단계별 흐름, 및 통제/안전장치 시스템 설계 사양을 정의합니다.

---

## 1. 후결(사후 승인)의 개념 및 필요성

### 1.1 개념
- **후결 (Post-Approval)**: 긴급을 요하는 사안이 발생했을 때, 정식 결재선을 모두 거쳐 승인을 받기에는 시간이 촉박하여 **현장 책임자나 상급자의 구두/임시 승인(또는 긴급 선행 조치)을 바탕으로 일을 먼저 진행**한 뒤, 나중에 전자결재 문서를 올려 정식 승인을 받는 역방향(Emergency-First) 승인 방식입니다.

### 1.2 주요 발생 상황
1. **IT/보안 시스템 장애**: 갑작스러운 서버 다운, 랜섬웨어/보안 사고로 즉각적인 외주 긴급 복구 비용 집행이 필요한 경우.
2. **생산/설비 비상 상황**: 공장 설비 고장으로 생산 라인이 멈추어 당장 당일 현장 수리 업체를 부르고 부품을 조달해야 하는 경우.
3. **대외 입찰/계약 긴급 마감**: 계약이나 입찰 제출 마감 시간이 촉박하여 실무자가 선집행/선제출 후 서류를 사후 보완해야 하는 경우.

---

## 2. 일반 결재 vs 후결 프로세스 비교

```
[일반 결재 (정방향)]
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 기안 상신  │ ➔ │ 검토 (승인)│ ➔ │ 최종 승인  │ ➔ │ 업무 집행  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘

[후결 프로세스 (역방향)]
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 긴급 비상  │ ➔ │ 선조치/집행│ ➔ │ 사후 기안  │ ➔ │ 사후 검토  │ ➔ (이력 편입 & 감사 보관)
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

| 구분 | 일반 결재 (Normal Flow) | 후결 프로세스 (Emergency Post-Approval) |
| :--- | :--- | :--- |
| **진행 순서** | 기안 ➔ 승인 ➔ 업무 실행 (정방향) | 비상 상황 ➔ 현장 실행 ➔ 사후 상신 ➔ 사후 승인 (역방향) |
| **의사결정 시점** | 최종 승인 완료 후 실행 권한 발생 | 구두/임시 승인 후 실무 선실행 ➔ 사후 공식화 |
| **주요 목적** | 사전 통제 및 사정 예방 | 긴급 상황 신속 대응 & 사후 감사 이력 공식 보존 |
| **통제 방식** | 기본 결재선 승인 통제 | 긴급 사유 필수화 + 금액 한도 제한 + 특수 UI 뱃지 |

---

## 3. 후결 프로세스의 단계별 흐름

1. **🚨 긴급 조치 및 현장 실행 (Step 1)**:
   - 현업 부서에서 긴급성을 소명하고 구두/임시 승인 하에 긴급 수리, 집행, 선계약 등의 선조치를 취함.
2. **📝 사후 기안 상신 (Step 2)**:
   - 기안자가 전자결재 작성 화면에서 **[🚨 후결(사후 승인) 요청]** 옵션을 체크.
   - 선조치 일시, 구두 승인자, 긴급 사유 및 증빙 자료(현장 사진, 수리 견적서 등)를 필수 입력 후 상신.
3. **🔍 사후 승인 및 결재권자 검토 (Step 3)**:
   - 결재권자는 문서의 내용이 *"정말 사후 결재가 필요할 만큼 긴급하고 타당했는지"* 엄격히 검토 후 사후 승인 또는 반려 처리.
4. **🏛️ 이력 편입 및 감사 보관 (Step 4)**:
   - 승인 완료 시 시스템상에 '사후 승인 완료 문서'로 이력이 별도 기록되며, 사내 감사나 예산 집행 정합성을 증명하는 공식 보관 문서로 보관됨.

## 4. 시스템 설계 시 주의할 점 (실무적 리스크 & 안전장치)

후결은 권한 남용(예산 무단 집행 후 사후 핑계 대기)의 위험이 크므로 다음과 같은 **3대 안전장치(Safety Guards)**를 구현합니다.

### 4.1 ✍️ 긴급 사유 및 선조치 증빙 필수화 (Validation Guard)
- 후결 옵션 선택 시 **'긴급 사유'**, **'선조치 일시'**, **'선조치 승인자'** 필드가 필수 항목으로 추가됨. 공통섹션 : "선조치 내용" -> 긴급사유(텍스트,전체) 선조치 일시(날짜,2열,현재 시간보다 이전으로 설정해야 함.) 선조치 승인자(사용자,2열)
- 내용 미입력 또는 50자 미만 작성 시 상신 거부(`Validation Error`).

### 4.2 🏷️ 특수 결재선 및 식별 UI 표기 (Visual Guard)
- 문서 목록, 문서 상세 보기, 결재선 타임라인 상단에 **[🚨 후결(사후승인)]** 강조 뱃지 노출.
- 결재 도장 스냅샷에 일반 결재와 구별되는 **`[사후승인]`** 스탬프 인영 적용.

### 4.3 💰 금액 한도 제한 및 전결 연동 (Amount Limit & Access Control)
- 관리자 결재 프로세스 설정(`approvalProcessRepo`)과 연계하여 **후결 허용 최고 금액 한도(예: 500만원)** 설정.
- 한도 초과 금액의 후결 상신 시 원천 차단하거나 대표이사(최고 경영자) 승인이 필수 포함되는 특수 결재선 자동 라우팅.
