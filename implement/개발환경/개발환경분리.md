# Appwrite & Firebase 하이브리드
## 로컬 개발 환경설정 및 데이터 이관 매뉴얼

본 문서는 **WorkFit** 프로젝트 개발자가 로컬 환경에서 **Appwrite (데이터베이스)**와 **Firebase FCM (푸시 알림)** 하이브리드 구성을 활성화하고, 개발/운영 데이터와 알림을 격리하여 안전하게 개발을 진행할 수 있도록 안내하는 환경설정 가이드입니다.

---

## 1. 환경설정 개요

현재 WorkFit 프로젝트는 데이터베이스 백엔드를 Firestore에서 **Appwrite**로 전환하고, 웹/모바일 푸시 인프라는 Firebase의 **FCM**을 그대로 활용하는 하이브리드 과도기 상태입니다. 

로컬에서 개발 테스트를 수행할 때 실운영 데이터 오염 및 사용자 단말기로의 푸시 알림 오발송을 원천 차단하기 위해 **개발 환경(Dev)**과 **운영 환경(Prod)**을 1:1 프로젝트 수준으로 격리하여 설정해야 합니다.

* **개발 환경**: Appwrite 프로젝트 (`workfit-dev`) + Firebase 프로젝트 (`workfit-office-dev`)
* **운영 환경**: Appwrite 프로젝트 (`workfit-prod`) + Firebase 프로젝트 (`workfit-office-app`)

## 2. 로컬 개발 환경 변수 설정 ([`.env.local`](file:///c:/WorkFit/전자결재시스템/workfit-office/.env.local))

Git 관리 대상에서 제외되는 로컬 전용 설정 파일 [`.env.local`](file:///c:/WorkFit/전자결재시스템/workfit-office/.env.local)을 프로젝트 루트 디렉토리에 생성하고 아래와 같이 개발계 설정값을 채워 넣습니다.

```bash
# ==========================================
# 1. DB 및 파일 스토리지 드라이버 스위치
# ==========================================
VITE_DB_DRIVER="appwrite"
VITE_STORAGE_DRIVER="firebase"
VITE_AUTH_ENABLED="true"

# ==========================================
# 2. Appwrite 개발계 (Dev) 설정
# ==========================================
VITE_APPWRITE_ENDPOINT="https://appwrite.widdyax.com/v1"
VITE_APPWRITE_PROJECT_ID="workfit-dev-id"        # 개발계 Appwrite 프로젝트 ID
VITE_APPWRITE_DATABASE_ID="workfit-dev-db"       # 개발계 Database ID

# ⚠️ 스키마 생성 및 데이터 이관(ETL) 스크립트 실행 시에만 입력합니다.
# ⚠️ 브라우저에는 절대 노출되지 않으며, 관리자(팀장)로부터 비공개로 전달받아야 합니다.
APPWRITE_API_KEY="...개발계_databases_write_API_KEY..."

# ==========================================
# 3. Firebase FCM 개발계 (Dev) 설정 (VITE_FB_ 접두사 사용)
# ==========================================
VITE_FB_API_KEY="AIzaSyDevApiKey..."              # workfit-office-dev API 키
VITE_FB_AUTH_DOMAIN="workfit-office-dev.firebaseapp.com"
VITE_FB_PROJECT_ID="workfit-office-dev"
VITE_FB_STORAGE_BUCKET="workfit-office-dev.firebasestorage.app"
VITE_FB_MESSAGING_SENDER_ID="111122223333"
VITE_FB_APP_ID="1:111122223333:web:abcdef123456"
VITE_FB_VAPID_KEY="BDev_Vapid_Key_Example..."    # Cloud Messaging 웹 푸시 인증서 키 쌍
VITE_FB_FIRESTORE_DB_ID=""
```

## 3. Appwrite 프로젝트 콘솔 설정 (CORS 및 권한)

로컬 브라우저에서 Appwrite API를 쐈을 때 차단되지 않도록 콘솔 설정이 선행되어야 합니다. (이 설정은 프로젝트 관리자가 1회 설정하거나 계정이 있을 시 직접 진행합니다.)

### 3.1 웹 플랫폼(CORS) 등록
1. Appwrite Console 접속 (`https://appwrite.widdyax.com/console`) 후 개발 프로젝트(`workfit-dev`) 선택.
2. 좌측 메뉴 하단 **Settings > Platforms** 탭으로 이동.
3. **[Add Platform] > Web App** 선택 후 아래 주소를 추가합니다.
   * `localhost` (포트 번호 제외한 호스트명 등록)
   > **CORS 에러 주의:** 이 설정이 누락되면 브라우저에서 Appwrite 호출 시 CORS 차단으로 서비스 이용이 불가합니다.

### 3.2 컬렉션 접근 권한(Permissions) 설정
개발 단계에서 모든 로컬 개발자가 자유롭게 CRUD를 수행하고 Realtime 이벤트를 구독하기 위해, 대상 컬렉션들의 읽기/쓰기 권한이 열려있어야 합니다.
1. `Databases > Databases 목록 > workfit-dev-db` 진입.
2. 각 컬렉션(예: `approvalDocs`, `approvalForms`)의 **Settings > Update Permissions**로 이동.
3. **`Any` (누구나)** 또는 **`Users` (가입 계정 누구나)** 역할을 추가하고 **Read, Create, Update, Delete** 권한을 모두 체크한 후 저장합니다.

## 4. 로컬 스키마 배포 및 데이터 이관 (ETL)

데이터베이스가 비어있는 상태에서는 서식 조회 및 결재 문서 로드가 되지 않습니다. 로컬 환경 변수 설정 단계에서 `APPWRITE_API_KEY`를 제대로 등록했다면 아래 단계를 통해 개발계 DB를 구성할 수 있습니다.

### 4.1 개발 데이터베이스 스키마 생성 (IaC)
코드로 정의된 스키마 배열을 기반으로 Appwrite 내에 테이블 컬렉션, 속성(Attributes), 인덱스(Indexes)를 자동 빌드합니다.
```bash
npm run appwrite:schema
```

### 4.2 기존 데이터 마이그레이션 및 이관 (ETL)
상세 결재선, 첨부파일 등 복잡한 중첩 데이터를 JSON 문자열 형태인 `payload` 컬럼으로 직렬화하여 적재해주는 ETL 스크립트를 가동합니다.
```bash
npm run etl -- --commit
```
> **이관 데이터 안전 주의:** 마이그레이션 스크립트를 수행할 때 타겟 데이터베이스 ID가 개발계(`workfit-dev-db`)로 매핑되어 있는지 `.env.local` 설정을 이중 점검하십시오.

## 5. FCM Service Worker 및 프론트엔드 환경 격리

### 5.1 서비스 워커 환경 쿼리 전송
서비스 워커(`public/firebase-messaging-sw.js`)는 React의 빌드 환경변수 스코프 밖에서 단독 동작하므로, [`src/shared/lib/messaging.ts`](file:///c:/WorkFit/전자결재시스템/workfit-office/src/shared/lib/messaging.ts)에서 등록할 때 Vite 모드를 쿼리 스트링으로 실어 전송합니다.

```typescript
// src/shared/lib/messaging.ts
const envMode = import.meta.env.MODE; // "development" 또는 "production"
const swReg = await navigator.serviceWorker.register(`/firebase-messaging-sw.js?env=${envMode}`);
```

## 6. 개발팀 표준 작업 수칙 (Best Practices)

1. **로컬 서버 기동**: 
   개발계 환경변수를 장착하고 로컬 서버를 가동합니다. `package.json` 설정에 따라 자동으로 개발 모드가 구동됩니다.
   ```bash
   npm run dev
   ```
2. **스키마 및 속성 변경 시**:
   데이터베이스 스키마(컬렉션 필드, 인덱스)를 수정할 때 임의로 콘솔에서 수작업하지 마십시오. 반드시 [`scripts/appwrite-schema.ts`](file:///c:/WorkFit/전자결재시스템/workfit-office/scripts/appwrite-schema.ts)에 스키마 정의를 추가/수정한 뒤 `npm run appwrite:schema`를 재구동하여 멱등성 있게 적용하고 Git에 커밋해야 합니다.

3. **듀얼 라이트 브리지(Cloud Functions) 배포 주의**:
   개발자가 로컬 에뮬레이터를 올리거나 Cloud Functions 배포 명령을 실행할 때, 환경 변수 파일에 운영용 Appwrite Endpoint 및 API Key가 기재되어 있으면 개발용 테스트 쓰기 작업이 운영계 DB로 동기화되어 충돌을 유발할 수 있습니다. Functions 배포/에뮬레이팅 전 환경 설정을 엄격히 검토하십시오.
