# Rule: Daily Work Report Generation ([업무보고])

사용자가 대화 맨 앞에 `[업무보고]` 프리픽스를 붙여 업무 내용과 진행 상태를 전달하는 경우, 제공된 이미지 양식에 맞추어 마크다운 표 형태로 일일 업무 보고서를 작성해야 합니다.

## 작성 양식 및 요건

1. **테이블 구조**:
   * **순번**: 1부터 시작하는 번호
   * **업무 내용**: 개발 대상 및 해결한 문제의 명확한 요약
   * **비고**: 구체적인 분석 원인, 구현 방식, 예외 처리, 향후 개선 사항 등을 글머리 기호(`-`)와 개행(`<br>`)을 사용해 상세하게 기술
   * **진행상태**: 사용자가 제시한 진행 상태 백분율 (예: `100%`, `80%`)

2. **비고란 작성 세부 가이드**:
   * **원인/배경**: 분석된 버그나 필요성 요약
   * **조치/해결책**: 프론트엔드/백엔드/인프라 관점에서 적용한 임시 우회 또는 정석적 조치사항 기술
   * **향후 보완 계획**: 추후 보완 및 고도화 계획(있는 경우) 추가

## 예시 출력 양식

| 순번 | 업무 내용 | 비고 | 진행상태 |
| :--- | :--- | :--- | :--- |
| 1 | ApprovalFormScreen.tsx 리팩토링 및 쪼개기 | - 1,750라인에 달하는 서식 관리 스크린 파일을 4대 도메인 역할(서식 구조 / 기안 권한 / 문서 후속처리 / 결재 규칙)로 분리 완료<br>- 공통 대상 선택기(`FormTargetSelector`) 및 기안권한 패널(`FormPermissionSettings`)을 추출해 중복 코드를 제거<br>- 최종 TypeScript 정적 타입 체크 및 빌드 완료 후 remote main에 머지 및 푸시 완료 | 100% |
