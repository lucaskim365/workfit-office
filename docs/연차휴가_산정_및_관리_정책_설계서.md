# 연차휴가 산정 및 관리 정책 (Leave Policy & Ledger Specification)

본 문서는 **대한민국 근로기준법(제60조, 제61조, 제62조)**, **고용노동부 행정해석**, **대법원 판례**를 기반으로 하며, 워크핏 그룹웨어의 **연차 원장(Leave Ledger)** 및 **휴가 관리 엔진(Leave Accrual Engine)** 구현을 위한 표준 설계 명세서입니다.

---

## 1. 목적

1. 근로기준법상 법정 연차휴가 기준과 사내 연차 운영 기준의 정합성을 보장한다.
2. 회계연도 기준 운영 시 발생할 수 있는 중도입사자 및 퇴직 시 법정 분쟁(차액 미정산)을 기술적으로 원천 방지한다.
3. 숫자의 단순 덮어쓰기가 아닌, **금융 거래식 불변 원장(Immutable Ledger)** 구조를 도입하여 모든 연차의 발생, 이월, 사용, 취소, 소멸의 투명한 감사 추적(Audit Trail)을 보장한다.
4. 향후 근태관리, 캘린더, 실시간 근무상태(Presence)와의 오차 없는 연동 기준을 확립한다.

---

## 2. 적용 법령 및 행정해석 기준

| 법령 / 판례 | 핵심 요약 | 시스템 반영 요구사항 |
|---|---|---|
| **근로기준법 제60조 제1항** | 1년간 80% 이상 출근한 근로자에게 **15일** 유급휴가 부여 | 1년 만근 및 출근율 80% 달성 판정 |
| **근로기준법 제60조 제2항** | 1년 미만 근로자 또는 80% 미만 출근자에게 **1개월 개근 시 1일** 유급휴가 부여 (최대 11일) | 달력 기준 1개월 단위 월별 발생 관리 |

| **근로기준법 제60조 제4항** | 3년 이상 계속근로 시 1년을 초과하는 **매 2년마다 1일 가산** (최대 25일 한도) | $15 + \lfloor \frac{\text{근속연수} - 1}{2} \rfloor$ (상한 25일) |
| **근로기준법 제60조 제6항** | 업무상 부상·질병, 출산전후휴가, 육아휴직 기간은 **출근한 것으로 간주** | 출근율 산정 시 분모/분자 출근 처리 |
| **대법원 2021다227100 판결**<br/>(고용노동부 2021.12 행정해석) | 365일 근무 후 퇴직 시 15일 미발생. **366일째 근로관계가 유지되어야** 15일 연차 확정 | 만 1년 + 1일 재직 상태 확인 후 기표 |
| **행정해석 (근기 68207-620 등)** | 회계연도 기준 관리 허용, 단 **퇴직 시 입사일 기준과 비교하여 유리한 쪽으로 정산** | 회계연도 원장과 입사일 기준 대조 엔진 |
| **근로기준법 제61조** | 연차 유급휴가 사용 촉진 (1차: 6개월 전, 2차: 2개월 전 서면 촉진) | 촉진 대상자 자동 필터링 및 통보 이력 |
| **근로기준법 제62조** | 근로자대표 서면합의에 따른 유급휴가의 대체 | 전사/부서 일괄 연차 차감 트랜잭션 지원 |

## 3. 법정 연차 발생 규칙 상세

### 3.1. 1년 미만 근로자 (신입사원)
* **발생 기준**: 입사일로부터 만 1년이 되기 전까지, 매월 개근 시 익월 1일에 1일씩 발생 (최대 11일).
* **달력 기준 월력 계산**: 30.5일 고정 나눗셈이 아닌, 사원의 `hireDate`의 "일(Day)"을 기준으로 매월 도래 시 발생.
  * 예: 2026-03-15 입사자 ➔ 2026-04-15에 1차 1일 발생, 2026-05-15에 2차 1일 발생 ... (총 11회).
* **유효기간 및 소멸**:
  * 2020년 개정법에 따라, 1년 미만 기간 동안 발생한 모든 연차(최대 11일)는 **입사일로부터 1년이 되는 날(365일째 자정)에 전량 자동 소멸**된다.

### 3.2. 1년 이상 근로자
* **발생 기준**: 직전 1년간 80% 이상 출근 시 15일 발생.
* **366일 근로관계 확인**: 1년(365일) 만근 후 계약 종료 시 15일 발생 불가. 1년 1일 이상 근로관계 유지 필수.
* **유효기간**: 발생일로부터 1년간 행사 가능하며, 기간 경과 시 소멸(또는 보상/촉진).

### 3.3. 근속연수별 가산연차표 (법정 기준)
| 계속근로연수 | 만 근속연수($N$) | 법정 연차 일수 | 계산 산식 |
|:---:|:---:|:---:|---|
| **1년 미만** | $0$ | **최대 11일** | 1개월 개근 시 1일씩 월별 누적 |
| **1년 이상 ~ 2년 미만** | $1$ | **15일** | 기본 연차 |
| **2년 이상 ~ 3년 미만** | $2$ | **15일** | 기본 연차 |
| **3년 이상 ~ 4년 미만** | $3$ | **16일** | $15 + \lfloor (3-1)/2 \rfloor = 15 + 1$ |
| **4년 이상 ~ 5년 미만** | $4$ | **16일** | $15 + \lfloor (4-1)/2 \rfloor = 15 + 1$ |
| **5년 이상 ~ 6년 미만** | $5$ | **17일** | $15 + \lfloor (5-1)/2 \rfloor = 15 + 2$ |
| **...** | ... | ... | 2년마다 1일씩 가산 |
| **21년 이상** | $\ge 21$ | **25일** | **법정 상한 한도 (25일)** |

### 3.4. 연차 선사용(Advance Leave) 및 자동 상계 정책
* **법적 배경 (고용노동부 행정해석 근기 68207-2776)**:
  * 근로기준법상 아직 발생하지 않은 연차라 할지라도, 사용자의 승낙 및 결재 승인 하에 미리 앞당겨 사용하는 것(선사용/당겨쓰기)은 근로자에게 유리하므로 유효하다.
* **적용 대상**:
  * 입사 1년 미만 신입사원이 하계휴가, 경조사 등으로 인해 현재까지 만근 누적된 연차를 초과하여 결재를 득하고 사용한 경우.
* **상계 메커니즘 (Offset Flow)**:
  1. **선사용 기표**: 휴가 결재 승인 시 원장에 정상 사용량(`USAGE`)으로 기록되어 잔여 연차가 일시적으로 마이너스(Negative Balance) 상태가 됨.
  2. **매월 발생분 자동 상계**: 이후 계속 근무를 통해 매월 입사일 도래 시 발생하는 월별 1일(`MONTHLY_GRANT`)이 음수 잔여를 순차적으로 메꿈(상계).
  3. **실무 사례**: 6월 22일 입사자가 7월 말 하계휴가 5일을 선사용(잔여 -5일)한 경우:
     * 7월 22일 만 1개월 개근: +1일 상계 (잔여 -4일)
     * 8월 22일 만 2개월 개근: +1일 상계 (잔여 -3일)
     * 9월 22일 만 3개월 개근: +1일 상계 (잔여 -2일)
     * 10월 22일 만 4개월 개근: +1일 상계 (잔여 -1일)
     * 11월 22일 만 5개월 개근: +1일 상계 (잔여 0일 완제 및 정상화)
     * 12월 22일 ~ 익년 5월 22일: 이후 발생하는 6일은 온전한 플러스 연차로 사용 가능.
* **중도퇴사 시 처리**:
  * 선사용한 연차가 전량 상계되기 전 근로자가 자진 퇴직하는 경우, 초과 사용한 일수만큼 최종 급여정산에서 일할 공제하거나 사내 취업규칙에 따라 처리.

## 4. 회계연도 기준 운영 및 퇴직 시 법정 정산

### 4.1. 회계연도 기준(1월 1일 ~ 12월 31일) 운영 방식
기업 실무상 매년 1월 1일에 전사 사원의 연차를 일괄 정산/부여한다.

1. **입사 당해 연도**:
   * 매월 개근 시 1일씩 발생 (최대 11일).
2. **차기 연도 1월 1일 (중도입사자 비례 연차 부여)**:
   * 전년도 재직일수에 비례하여 연차 부여:
     $$\text{비례 연차} = 15\text{일} \times \frac{\text{전년도 재직일수}}{365} \quad (\text{소수점 올림 또는 사내 반올림 취업규칙 준수})$$
   * 이때 입사 첫해에 발생한 11일 중 미사용한 일수와 합산 관리.

### 4.2. 퇴직 시 정산 원칙 (노동부 행정해석 필수 준수)
* **원칙**: 회계연도 기준으로 관리하더라도 근로자에게 법정 기준보다 불리할 수 없다.
* **정산 프로세스**:
  $$\text{정산 대상 잔여} = \max(\text{입사일 기준 법정 총 발생} - \text{총 사용일수}, \; \text{회계연도 기준 현재 잔여일수})$$
* 만약 입사일 기준 잔여가 더 많은 경우, 그 차이 일수만큼 퇴직 시 연차수당으로 정산 지급해야 한다.

## 5. 휴가 유형 정책 (Leave Policy) 분리 모델

휴가는 '연차에서 차감되는 휴가'와 '독립적으로 부여/관리되는 휴가'로 명확히 분리한다.

```ts
export interface LeavePolicy {
  code: string;                 // 시스템 고유 코드
  name: string;                 // 노출 명칭
  category: 'ANNUAL_DEDUCT' | 'SPECIAL_PAID' | 'UNPAID' | 'ACCRUED';
  
  deductsAnnualLeave: boolean;  // 연차 원장 차감 대상 여부
  deductAmount: number;         // 1.0, 0.5, 0.25 등
  unit: 'DAY' | 'HALF_DAY' | 'QUARTER_DAY' | 'HOUR';
  
  timeWindow?: {
    defaultStart: string;       // "08:30"
    defaultEnd: string;         // "12:30" (오전반차 등)
  };
  
  paid: boolean;                // 유급 여부
  requiresProof: boolean;       // 증빙자료 첨부 필수 여부
  maxDaysPerRequest?: number;   // 1회 최대 신청 가능 일수
}
```

### 표준 휴가 유형 카탈로그
| 코드 | 명칭 | 차감 대상 | 차감량 | 단위 | 유급 | 설명 |
|---|---|:---:|:---:|:---:|:---:|---|
| `ANNUAL` | 종일 연차 | O | 1.0 | DAY | 유급 | 전일(08:30~17:30) 부재 |
| `AM_HALF` | 오전 반차 | O | 0.5 | HALF_DAY | 유급 | **08:30 ~ 12:30** (13:30 출근 정상근무) |
| `PM_HALF` | 오후 반차 | O | 0.5 | HALF_DAY | 유급 | **13:30 ~ 17:30** (오전 근무 후 12:30 조퇴) |
| `QUARTER` | 반반차 | O | 0.25 | QUARTER_DAY | 유급 | 2시간 지정 휴가 (조기퇴근 등) |
| `SUBSTITUTE`| 대체휴무 | 별도 | 1.0/0.5 | DAY | 유급 | 휴일근무 적립 대체휴무 원장에서 차감 |
| `EVENT` | 경조사 휴가 | X | 0.0 | DAY | 유급 | 취업규칙 경조일수 적용, 증빙 필수 |
| `SICK_PAID` | 유급 병가 | X | 0.0 | DAY | 유급 | 회사 지원 병가 (진단서 필수) |
| `SICK_UNPAID`| 무급 병가 | X | 0.0 | DAY | 무급 | 무급 휴직 처리 |
| `REWARD` | 포상 휴가 | 별도/가산 | 1.0 | DAY | 유급 | 연차 원장에 ADJUSTMENT(+)로 적립 |

## 6. 연차 원장 (Leave Ledger) 아키텍처

원장은 **결코 과거 레코드를 수정하거나 삭제하지 않는 Append-Only 불변 데이터 모델**이다.

```ts
export type LeaveLedgerCategory =
  | 'ANNUAL_GRANT'      // 법정 정기 연차 부여 (+)
  | 'MONTHLY_GRANT'     // 1년 미만 월별 개근 연차 발생 (+)
  | 'CARRY_OVER'        // 회계연도 갱신 이월 (+)
  | 'REWARD_GRANT'      // 포상/특별 휴가 추가 부여 (+)
  | 'ADJUSTMENT'        // 관리자 수동 가감 (±)
  | 'USAGE'             // 결재 승인에 의한 사용 (-)
  | 'CANCELLATION'      // 결재 취소/회수에 의한 환원 (+)
  | 'EXPIRATION';       // 유효기간 만료 소멸 (-)

export interface LeaveLedgerEntry {
  id: string;                   // UUID
  employeeId: string;           // 대상 사원 ID
  year: number;                 // 귀속 연도 (예: 2026)
  category: LeaveLedgerCategory;
  
  amount: number;               // 양수(+) 또는 음수(-)
  
  effectiveDate: string;        // 효력 발생일 ("2026-01-01")
  expirationDate?: string;      // 권리 소멸 예정일 ("2026-12-31")
  
  sourceDocId?: string;         // 결재 문서 ID (approvalDoc FK)
  policyCode: string;           // 사용된 휴가 정책 코드 ('AM_HALF' 등)
  
  reason: string;               // 적요 ("2026년 정기 연차 부여", "결재승인: 개인사유 연차")
  metadata?: {
    adminId?: string;           // 관리자 조정 시 담당자
    leaveStartTime?: string;    // "13:30"
    leaveEndTime?: string;      // "17:30"
  };
  
  createdAt: string;            // ISO 타임스탬프
}
```

### 잔여일수 실시간 집계 공식
$$\text{Total Granted} = \sum_{\text{amount} > 0} \text{amount} \quad (\text{단, } \text{EXPIRATION 제외})$$
$$\text{Total Used} = \left| \sum_{\text{category} = \text{'USAGE'}} \text{amount} \right| - \sum_{\text{category} = \text{'CANCELLATION'}} \text{amount}$$
$$\text{Remaining} = \sum \text{amount}$$
$$\text{Available} = \text{Remaining} - \text{PendingApprovalDays}$$

## 7. 시스템 통합 연동 규칙

1. **전자결재 (`ApprovalDraftScreen` & `engine.ts`)**:
   * 상신 시: `Available` 잔여일수 검증 (부족 시 상신 차단) ➔ 임시 대기량(`Pending`) 반영
   * 승인 완료(`completedAt`) 시: 원장에 `USAGE` 엔트리 즉시 기표 (절대 결재 문서를 뜯어고치지 않고 독립 생성)
   * 결재 취소/회수 승인 시: 원장에 `CANCELLATION` 엔트리 신규 기표
2. **실시간 상태관리 (`UserPresence`)**:
   * 당일 유효한 승인 휴가 건 조회:
     * `ANNUAL`: 당일 종일 `LEAVE` 🌴
     * `AM_HALF`: 08:30~12:30 `LEAVE` ➔ 13:30 이후 `ONLINE` 자동 전환
     * `PM_HALF`: 08:30~12:30 `ONLINE` ➔ 13:30 이후 `LEAVE` 자동 전환
3. **근태관리 (`CommuteScreen`)**:
   * 오전반차: 13:30까지 출근 시 정상 출근 인정 (지각 면제)
   * 오후반차: 12:30 이후 퇴근 시 정상 근무 인정 (조퇴 면제)
4. **일정관리 (`CalendarScreen`)**:
   * 승인된 원장 이벤트를 가상 이벤트(Virtual Event)로 캘린더에 색상/시간대별 띠로 렌더링

## 8. 기결재된 기존 휴가 문서(Legacy Approvals) 처리 방안

실제 운영 데이터베이스(`appwrite`, `garage s3`)의 기존 결재 문서(`approvalDocs`)는 사내 규정 및 시스템 규칙(`rule-readonly.md`)에 따라 **절대 수정·삭제·덮어쓰지 않고 100% 읽기 전용(Read-Only)**으로 보존되어야 합니다. 또한 과거 문서는 신규 필드(`startTime`, `endTime`, `AM_HALF`/`PM_HALF` 코드)가 존재하지 않습니다. 이를 안전하고 일관되게 처리하기 위한 표준 처리 전략은 다음과 같습니다.

### 8.1. 런타임 읽기 전용 어댑터 (`normalizeLegacyLeaveDoc`)
기존 DB 레코드를 물리적으로 마이그레이션(UPDATE)하지 않고, 도메인 계층에서 문서를 읽는 시점에 표준 형식으로 동적 정규화하는 어댑터를 배치합니다.

```ts
export interface NormalizedLeaveRecord {
  docId: string;
  drafterId: string;
  leaveType: 'ANNUAL' | 'AM_HALF' | 'PM_HALF' | 'QUARTER' | 'SUBSTITUTE' | 'SPECIAL';
  startDate: string;
  endDate: string;
  startTime: string;      // "08:30" or "13:30" (반차/반반차)
  endTime: string;        // "12:30" or "17:30"
  days: number;           // 1.0, 0.5, 0.25 (과거 수치 100% 보존)
  status: DocStatus;
  isLegacy: boolean;      // 구버전 결재문서 여부
}
```

* **정규화 및 시간대 추론 휴리스틱**:
  1. **신규 포맷 문서**: 문서 내 `startTime`, `endTime`, `leaveType`이 정형화되어 있으므로 그대로 사용.
  2. **과거 `leaveType: '반차'` 문서 (시간대 필드 누락 건)**:
     * 문서 제목(`title`) 및 사유(`reason`) 텍스트 분석:
       * "오후", "PM", "오후반차" 등의 키워드 감지 시 ➔ `PM_HALF` (`13:30 ~ 17:30`)로 매핑.
       * "오전", "AM", "오전반차" 등의 키워드 감지 시 ➔ `AM_HALF` (`08:30 ~ 12:30`)로 매핑.
       * 키워드가 전혀 식별되지 않는 경우 ➔ 안전한 시스템 기본값 `AM_HALF` (`08:30 ~ 12:30`)으로 가상 폴백(Fallback).
  3. **차감 일수(`days`)의 절대 보존**:
     * 과거 문서에 기표된 `days` 값(0.5일, 1.0일 등)은 어떠한 경우에도 임의 재계산하지 않고 원본 그대로 유지하여, 기존 연차 잔여일수의 왜곡을 0건으로 보장.

### 8.2. 연차 원장(Ledger) 상의 과거 사용량 처리: 프로젝션 & 스냅샷
* **실시간 원장 프로젝션 (Projection-on-Read)**:
  * 신규 연차 원장은 물리 테이블을 따로 복제할 필요 없이, `approvalDocs` 중 `status === '완료'`인 문서를 `normalizeLegacyLeaveDoc`으로 읽어 `USAGE` 트랜잭션 스트림으로 메모리상 프로젝션(Projection)합니다.
  * 따라서 과거 기결재 건도 신규 연차 원장의 잔여일수 계산 공식($\text{Remaining} = \text{Grant} - \text{Used}$)에 즉각 안전하게 합산됩니다.
* **기준일 이전 과거 이력 관리 (필요 시)**:
  * 대량의 다년도 과거 이력 조회가 필요한 경우, 구 시스템 마감 시점의 잔여/사용량을 1건의 `LEGACY_SNAPSHOT` 원장 트랜잭션으로 요약 기표하여 성능을 최적화할 수 있습니다.

### 8.3. 기결재 문서의 취소 및 변경 프로세스
* **절대 원본 문서 수정 금지**:
  * 이미 승인 완료된 과거 휴가를 취소하거나 날짜를 변경해야 할 때, 기존 문서를 '반려'나 '삭제' 상태로 DB에서 변경하는 행위를 엄격히 금지합니다.
* **불변 감사 추적을 위한 신규 취소 결재 상신**:
  * 사용자는 신규 서식인 **[휴가 취소 신청서]**를 상신하여 결재를 받습니다 (원 결재문서 번호 `originalDocId` 참조).
  * 취소 문서가 최종 승인(`completedAt`)되면, 연차 원장에 `CANCELLATION (+0.5)` 트랜잭션이 추가 기표되어 차감되었던 연차가 투명하게 복원됩니다.

### 8.4. 시스템 모듈별 영향도 및 연동 처리
* **실시간 상태관리 (`UserPresence`)**:
  * 상태 관리는 **당일(Today)** 기준이므로, 이미 지나간 날짜의 기결재 문서는 상태 변화를 일으키지 않습니다.
  * 시스템 배포 시점에 "당일 또는 미래 날짜"로 기결재되어 있는 과거 반차 건에 대해서만 런타임 어댑터를 통해 `08:30~12:30` 또는 `13:30~17:30` 부재 상태로 정상 반영됩니다.
* **근태관리 (`Commute`) & 캘린더 (`Calendar`)**:
  * 캘린더는 과거 일정도 표시하므로, 런타임 어댑터가 부여한 가상 시간대를 기반으로 캘린더에 깨짐 없이 시간대별 블록으로 렌더링됩니다.
