# 결재규칙(전결규정) 관리 분리 및 A4 캔버스 직인란 연동 설계 계획서

## 1. 개요 및 배경

### 1.1 현황 및 문제점
- **서식 디자이너의 과부하**: 현재 결재서식 관리 화면(`ApprovalFormEditor`) 좌측 패널에 필드 속성뿐만 아니라 결재규칙 설정까지 탭으로 들어가 있어, 화면이 복잡해지고 스크롤이 발생합니다.
- **전결 규정의 전사성(Cross-form) 무시**: 기업의 위임전결 규정은 대개 특정 서식 1개가 아니라 **"금액별 전결 기준(100만 이하 팀장, 1,000만 이상 대표이사)"**처럼 여러 서식에 공통 적용되는 전사 규칙이 대부분입니다. 서식마다 일일이 들어가서 똑같은 규칙을 반복 등록해야 하는 비효율이 존재합니다.
- **캔버스 시각적 피드백의 부재**: A4 캔버스 우측 상단에 결재 직인란이 표시되고 있지만, 결재선을 수정하려면 좌측 탭을 오가야 하므로 "보이는 것을 바로 클릭해 수정한다"는 위지윅 원칙에 어긋납니다.

### 1.2 목표
1. **서식 디자이너의 스크롤 제로 달성**: 결재서식 관리 화면은 오직 **"A4 위지윅 캔버스 & 필드 도구함/속성"**에만 100% 집중하도록 결재규칙 UI를 분리.
2. **A4 캔버스 결재 직인란 1클릭 모달 연동**: 관리자가 A4 캔버스 상단의 **결재 직인 테이블을 클릭하면 그 자리에서 해당 서식의 결재선 규칙 모달**이 열려 즉시 수정할 수 있는 True WYSIWYG 인터랙션 제공.
3. **[결재규칙 관리] 전용 독립 메뉴 신설**: 전사 공통 규칙 및 각 서식별 규칙을 한곳에서 일목요연하게 조망하고 우선순위(드래그)를 총괄 관리할 수 있는 독립 대시보드 화면 구축.

## 2. 사용자 인터랙션 아키텍처 (2-Way Flow)

```
[경로 A: 서식 디자인 중 결재선 편집]

│ A4 공문서 캔버스                                       │
│                ┌───────────────────────────────────┐   │
│   출 장 신 청 서│ 결재 직인란 (기안 | 팀장 | 대표)  │◀──┼── [클릭!]
│                └───────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘
                          │
                          ▼ (모달 팝업 열림)
┌────────────────────────────────────────────────────────┐
│ 📑 '출장신청서' 결재선 규칙 설정 모달                   │
│ • 조건 1: 전 임직원 공통 (팀장 결재)                  │
│ • 조건 2: 100만 원 이상 (본부장 결재)                  │
│ • [+ 규칙 추가]                                        │
└────────────────────────────────────────────────────────┘

[경로 B: 전사 결재규칙 총괄 관리]
┌────────────────────────────────────────────────────────┐
│ 기준정보 > 결재규칙 관리 (독립 메뉴)                   │
│                                                        │
│ • 전사 공통 규칙 (금액 조건별 전결 기준)               │
│ • 서식별 특화 규칙 (출장, 휴가, 지출결의 등)           │
│ • 드래그 앤 드롭으로 우선순위 일괄 정렬                │
└────────────────────────────────────────────────────────┘
```

## 3. 세부 컴포넌트 설계 및 변경 사항

### 3.1 [컴포넌트 1] A4 캔버스 결재 직인란 인터랙션 (`ApprovalDraftDocumentSheet.tsx`)
- **수정 대상**: `src/modules/gw/approval/components/ApprovalDraftDocumentSheet.tsx`
- **추가 속성**: `onStampTableClick?: () => void;`
- **동작 방식**:
  - `isDesignMode={true}`일 때, 우측 상단 `ApprovalStampTable` 컨테이너에 호버 효과 적용:
    - `cursor-pointer ring-2 ring-transparent hover:ring-teal hover:bg-teal-soft/20 transition-all rounded p-1`
    - 마우스 호버 시 `(클릭하여 결재선 규칙 설정)` 툴팁 안내 배지 노출.
  - 클릭 시 부모의 `onStampTableClick()` 콜백을 호출하여 결재규칙 설정 모달을 오픈.

### 3.2 [컴포넌트 2] 결재규칙 설정 모달 (`ApprovalRouteRuleModal.tsx`)
- **신규 생성**: `src/modules/base/approvalForm/routeRules/ApprovalRouteRuleModal.tsx`
- **기능**:
  - 기존 `ApprovalRouteRuleSettings` 컴포넌트를 모달 다이얼로그 형태로 래핑.
  - 서식 디자이너에서 직인란을 클릭했을 때 모달이 부드럽게 팝업.
  - 규칙을 추가/수정/삭제하고 모달을 닫으면, **우측 A4 캔버스의 직인란에 수정된 결재선이 즉시 리프레시 반영**.
  - 취소/닫기 및 ESC 키 지원.

### 3.3 [컴포넌트 3] 서식 디자이너 패널 슬림화 (`ApprovalFormEditor.tsx`)
- **수정 대상**: `src/modules/base/approvalForm/components/ApprovalFormEditor.tsx`
- **개선 내용**:
  - 좌측 패널에 있던 복잡한 결재규칙 목록을 제거하여, **[도구함 & 필드 속성] 탭을 100% 스크롤 프리(Scroll-Free) 구조**로 완성.
  - `showRouteRuleModal` 상태를 두고, 직인란 클릭 시 `ApprovalRouteRuleModal`을 오픈.
  - 서식 기본설정 탭에도 `[결재규칙 모달 열기]` 바로가기 버튼을 제공.

### 3.4 [컴포넌트 4] 결재규칙 관리 독립 메뉴 화면 (`ApprovalRouteRuleScreen.tsx`)
- **신규 생성**: `src/modules/base/routeRule/ApprovalRouteRuleScreen.tsx`
- **기능**:
  - 전사의 모든 결재규칙(`ApprovalRouteRule[]`)을 조회 및 관리하는 전용 대시보드.
  - **상단 툴바**: 전체 규칙 수 통계, 서식별 필터(전체, 공통, 특정 서식별), 검색창, `+ 새 결재규칙 등록` 버튼.
  - **규칙 마스터 테이블/그리드**:
    - 우선순위 (드래그 앤 드롭으로 순위 변경)
    - 규칙명 (예: "지출 1,000만 원 이상 대표이사 결재")
    - 적용 대상 (전사 공통 or 특정 서식)
    - 트리거 조건 (금액 범위: 1,000만원 ~, 기안부서 조건 등)
    - 자동 생성 결재선 타임라인 배지 (`기안 → 팀장 → 본부장 → 대표이사`)
    - 액션: `[편집]`, `[복사]`, `[삭제]`
  - 기존 `ApprovalRouteRuleEditor` 컴포넌트를 100% 재사용하여 중복 방지.

### 3.5 [라우팅 및 메뉴] 메뉴 트리 연결 (`menu-tree.ts`)
- **수정 대상**: `src/app/menu-tree.ts` 및 라우터
- **위치**: `기준 정보 > 결재규칙 관리` (또는 `전자결재 > 결재규칙 관리`)
- **경로**: `/base/approval-rules`

## 4. 원칙 준수 및 안전성 보장

1. **중복 배제 (No Duplication)**:
   - 결재선 편집기(`ApprovalRouteRuleEditor`)와 결재선 훅(`useRouteRules`, `useUpsertRouteRule`, `useRemoveRouteRule`)을 그대로 재활용하여 모달과 독립 화면 양쪽에서 공유.
2. **기존 엔진 무결성**:
   - 기안 시 결재선을 판별하는 `evaluateRules` 엔진 로직 및 스키마(`ApprovalRouteRule`)는 단 1글자도 변경 없이 100% 호환.
3. **데이터베이스 불변성 (`rule-readonly`)**:
   - Appwrite 데이터베이스의 기존 결재문서 및 마스터 데이터를 임의로 변경/덮어쓰지 않음.
