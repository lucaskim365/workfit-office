# 결재서식 시트화(엑셀 형태) 개편 설계

- 작성일: 2026-10-21
- 상태: 빌더 검토 반영, 사용자 승인 대기
- 선행 작업(운영 반영 완료): 엑셀식 표 편집기·시트 모델 v2(c80e542), 회사 직인(3475fce6), 대외 문서 설정(49317034), 결재선 규칙 편집기 통일(921ddc63), 사업관리 › 발주 현황(72adab0f)

## 1. 왜 하는가

지금 결재서식은 "필드(텍스트·날짜·표…)를 위에서 아래로 쌓은 것"이다. 이 구조에서는
- **다른 표나 일반 필드의 값을 수식에 넣을 수 없다** — 표마다 따로 계산된다.
- **너비·비율 조절이 거칠다** — 필드는 절반/전체, 표 열은 비율 정도만 된다.
- 발주서처럼 정해진 엑셀 양식을 그대로 옮기기 어렵고, 칸 단위로 데이터(도입기업·사업·회사 정보)를 연결하기도 어렵다.

사용자 결정: **서식 전체를 엑셀처럼 셀 단위 시트 한 장으로 만든다.** 모든 서식을 이 형태로 통일한다. 사업관리(도입기업·사업)·발주 현황과의 연결도 이 시트 위에서 칸 단위로 한다.

## 2. 사용자 확정 사항

| 항목 | 결정 |
|---|---|
| 서식 형태 | 서식 전체 = 셀 단위 시트 1장. 제목·라벨·입력칸·표가 모두 같은 격자의 셀 |
| 통일 범위 | 기존 18개 서식 포함 **전부** 시트 방식으로 |
| 전환 방식 | **관리자가 직접** 새 시트 서식을 만든다(엑셀 불러오기 또는 직접 그리기). 자동 변환 기능은 만들지 않음 |
| 기존 서식·문서 | **지우지도 고치지도 않는다.** 새 서식이 완벽히 확인될 때까지 기존 서식으로 시스템이 계속 돌아가야 함 |
| 엑셀 불러오기 | .xlsx 불러오기 포함. 값·병합·열 너비·행 높이·글꼴·굵게·색·테두리·**수식**까지 |
| 기안자 화면 | 엑셀식 시트 화면(열 A·B·C, 행 1·2·3 머리글, 격자, 도구 모음, 수식 입력줄)에서 작성 |
| 기안자 권한 | 값·틀(행·열 추가/삭제, 병합, 서식, 수식) 모두 변경 가능. **데이터 불러오기·보안(비공개)·직인 위치·칸 이름은 불가**(관리자 전용) |
| 인쇄·PDF | **가로는 A4 폭에 자동 맞춤**, 세로는 길면 여러 장으로 나눔 |
| 발주서 | 결재 완료 발주서는 사업관리 › 발주 현황에 모임(완료). 개편 후 사업·도입기업별로 모아 보기 |
| 문서관리 | 보류(현재 '준비 중'). 이번 범위 아님 |
| 대체 서식 | 새 시트 서식은 **어느 기존 서식을 대체하는지** 고를 수 있고, 고르면 그 서식의 결재선 규칙·연동·문서 종류 분류를 이어받음 |
| 엑셀 색 | **엑셀 색 그대로** 저장. 도구 모음 색 고르기에도 '직접 색 지정' 추가 |
| 시험 중 상태 | 두지 않음 — 시험은 개발 DB에서 |
| 도입기업·사업 데이터 불러오기 | **이번 범위에서 뺌** — 관련 기능 추가 때 다시 설계(사용자 지시) |
| 이관 후 | 모든 서식 이관이 끝나면 사용자가 기존 서식을 삭제할 예정 — §10 주의 참고 |
| 자동 전결 | 규칙 미매칭 기본 결재선의 자동 전결은 그대로 둠(사용자가 수동 정리 예정) |

## 3. 하지 않는 것 (이번 범위 밖)

- 기존 서식 → 시트 서식 자동 변환
- 기존 문서를 시트 형태로 다시 그리기(기존 문서는 기존 모습 그대로 영구 열람)
- 문서관리(사내규정·매뉴얼 문서고) DB화
- 모바일(PWA)에서 기안 작성 — 모바일은 보기·결재만(현행 유지)
- 엑셀 내보내기(.xlsx 저장), 여러 시트 탭, 차트, 조건부 서식, 피벗, 매크로
- VLOOKUP 등 고급 함수 (불러올 때 값만 가져오고 알림)
- 도입기업·사업 데이터 불러오기와 발주 현황의 사업·도입기업별 보기(추후 별도 설계)
- 비공개 칸의 서버 측 보호(지금처럼 화면에서 가림)

## 4. 실패로 보는 것

- 기존 서식으로 기안·결재·열람·인쇄가 하나라도 안 되는 것
- 기존 approvalForms·approvalDocs 데이터를 바꾸거나 지우는 것 (프로젝트 읽기 전용 규칙)
- 휴가 차감·캘린더 일정·근태(휴일근무·연장근로)·금액별 결재선 등 **기존 연동이 시트 서식 문서에서 동작하지 않는 것**
- 진행 중 문서에 직인이 찍히거나, 비공개 칸이 노출되는 것
- 시트 서식 인쇄물이 A4 가로를 넘어 잘리는 것
- 화면에 내부 코드·키(셀 이름 토큰, 열 키 등)가 그대로 보이는 것

## 5. 전체 구조

```
결재서식(approvalForms)
 ├─ 기존 방식: fields[] (지금 그대로)
 └─ 시트 방식: sheet (새 속성)  ← 서식 1장 = 시트 1장
                │
기안 작성 ──────┤ form.sheet 있으면 SheetDraft, 없으면 기존 DraftDocumentSheet
결재 문서 보기 ─┤ 문서에 시트가 있으면 SheetDocView, 없으면 기존 ApprovalDocumentView 본문
                │
문서(approvalDocs.payload)
 ├─ fieldValues.__sheet   : 작성된 시트 전체(값·틀·서식) — 보기·인쇄의 원본
 ├─ fieldValues.<칸 이름> : 이름 붙은 칸의 값 (기존 연동이 읽는 키 그대로: period, leaveType, …)
 └─ fieldValues.__link    : 연동 유형(휴가·외근·…)
```

두 방식은 **서식 단위로 공존**한다. 같은 화면 코드 안에서 `form.sheet` 유무로 갈라진다.

### 5.1 시트 모델 확장 (SheetPayload v3 — 문서 전체용)

오전에 만든 `SheetPayload`(v2, 표 하나)를 서식 전체로 넓힌다. 같은 모듈(`sheetModel.ts`·`sheetOps.ts`·`formulaEngine.ts`)을 확장하고, 표 필드용 v2 경로는 기존 서식을 위해 그대로 둔다.

추가 개념(셀 단위, 모두 `"r:colKey"` 키 맵):

| 개념 | 내용 | 누가 정함 |
|---|---|---|
| `rowHeights` | 행 높이(px) | 관리자·기안자 |
| `colWidths` | 열 너비(px) — v2와 같음 | 관리자·기안자 |
| `cellInputs` | 입력 칸 종류: 글자·여러 줄·숫자·금액·날짜·기간·드롭다운(목록)·여러 선택·체크·사람·부서 | 관리자 (기안자 불가) |
| `cellNames` | 칸 이름(연동 키) — 시스템 목록에서만 선택 | 관리자 |
| `cellBinds` | 데이터 불러오기(도입기업1·2, 사업, 우리 회사, 기안 정보의 각 항목) | 관리자 |
| `cellLocks` | 기안자 수정 잠금(라벨·제목 칸 등) — 선택 | 관리자 |
| `cellStyles` | 굵게·색·배경·정렬·숫자 표시·테두리·**직인**(v2 그대로) | 서식: 둘 다 / 직인: 관리자 |
| `secretCells/Rows/Cols` | 비공개(v2 그대로) | 관리자 |
| `cellFormulas` | 수식(A1 주소, 범위, 함수) | 둘 다 |

- 열 키는 v2처럼 화면에 안 보이는 내부 키. 주소(A1)는 위치로 계산한다.
- 문서 하나의 모든 칸이 한 시트에 있으므로 "다른 표 값 참조" 문제는 사라진다(같은 시트의 다른 칸일 뿐).
- 수식 엔진: 기존 SUM·AVERAGE·MIN·MAX·ROUND에 **IF, 비교 연산(> < >= <= = <>), 문자열 결합(&)** 추가. 오류는 `#오류`, 0 나누기는 0(현행 규칙 유지).

### 5.2 저장

- **approvalForms**: 새 속성 `sheet`(문자열, 1,000,000자) 추가 — 시트 서식의 원본. `fields` 는 비워 두거나(시트 서식) 기존 값 유지(기존 서식). 운영·개발 DB에 속성 추가만 하고 기존 데이터는 그대로.
- 서식 메타에 `linkType`(연동 유형) 추가 — 속성 추가 없이 `sheet` JSON 안에 둔다.
- **approvalDocs**: 이미 `payload`(1,000,000자)에 문서 전체를 JSON으로 저장하므로 **DB 변경 없음**. `fieldValues.__sheet`(시트 직렬화 문자열), `fieldValues.__link`, 이름 붙은 칸 값을 넣는다.
- 크기 예산: 40행×12열, 서식·수식 포함 시 수십 KB 수준. 1MB 한도에 여유. 불러온 엑셀이 한도를 넘으면 불러오기 단계에서 막고 안내.

### 5.3 기존 연동 유지 — 연동 유형 + 칸 이름

기존 연동은 **서식 코드**(`휴가`·`외근`·`국내출장`·`해외출장`·`휴일근무`·`휴일근무신청`·`연장근로`)와 **필드 키**로 문서를 알아본다. 새 시트 서식은 기존 서식과 코드가 달라야 하므로(기존 서식을 지우지 않음) 다음으로 바꾼다.

1. 시트 서식에 **대체 서식**(`replaces`: 기존 서식 code, 선택)을 둔다. 고르면 그 code가 이 서식의 **연동 유형**이 된다(예: `휴가`). 고르지 않으면 연동 없는 새 서식.
   - 결재선 규칙 매칭(`approvalRoute/engine.ts`의 docType 비교, 서식별 규칙 목록)은 `docType === 규칙.docType || replaces === 규칙.docType` 로 넓혀 **기존 서식의 규칙을 그대로 이어받는다**.
   - 문서 종류 필터·검색 분류, 취소 기안(원문서 docType 복사 → 휴가 취소 시 일수 복원)도 `docLinkType` 기준으로 같게 동작해야 한다(builder 전수 조사).
2. 문서 상신 시 `fieldValues.__link = replaces`(연동 유형)를 저장한다.
3. 연동 코드가 `doc.docType === '휴가'` 처럼 보는 곳(확인된 곳: `scheduleEngine.ts`, `leave/legacyAdapter.ts`, `leave/userLeaveBalance.ts`, `commute/approvalDayIndex.ts`, 그 외 builder가 전수 조사)을 `docLinkType(doc)` 한 함수로 바꾼다: `fieldValues.__link ?? docType`. 기존 문서는 `__link`가 없어 지금과 똑같이 동작.
4. **칸 이름**: 연동 유형마다 필요한 이름 목록을 시스템이 갖고, 관리자는 그 목록에서 칸에 이름을 붙인다. 상신 시 이름 붙은 칸의 값을 `fieldValues.<이름>`에 복사한다. 이름 = 기존 필드 키 그대로(예: 휴가 `period`, `period__end`, `period__days`, `leaveType`, `startTime`, `endTime`, `substituteId`, `emergencyContact`; 외근·출장 `destination`, `purpose`, `transportation`, `companions` 등 — builder가 `scheduleEngine.ts`·휴가 정책 코드에서 전수 목록화).
5. 연동 유형별 **필수 칸 이름**이 빠지면 서식 저장을 막고 "휴가원에는 '휴가 시작일' 칸이 필요합니다"처럼 안내(화면에는 한글 이름만, 키는 노출 안 함).
6. 공통 칸 이름(모든 서식): `body`(본문 — 문서 목록 미리보기·검색), `amount`(결재 금액 — 금액별 결재선 규칙). 결재 금액 칸은 지금 `amountFieldOf` 와 같은 역할.
7. 이름 붙은 **입력 칸**(휴가 시작일·결재 금액 등)은 값 입력만 되고 수식은 넣을 수 없다. 휴가 일수처럼 시스템이 계산하던 값(`period__days`, 반차·반반차)은 연동 유형 '휴가'일 때 기간 입력 칸 옆에 **시스템이 계산해 채우는 칸**(관리자가 '휴가 일수' 이름을 붙인 칸)으로 처리 — 기존 휴가 정책 함수(`calculateLeaveDays`)를 그대로 호출. 이 칸은 **기안자가 고칠 수 없게 잠그고, 상신할 때 시스템이 다시 계산**해 넣는다.

### 5.4 데이터 불러오기 (이번 범위: 우리 회사·기안 정보만)

- 관리자가 칸을 고르고 도구 모음 **"데이터 불러오기"** → 우리 회사(회사명·사업자번호·대표자·주소·전화·팩스), 기안 정보(기안자·기안부서·기안일) 중 선택.
- 기안 시작 시 채움. 기안자가 고쳐 쓸 수 있고, 상신 시점 값으로 저장.
- 구조는 나중에 도입기업·사업 묶음을 더할 수 있게 `cellBinds: { 'r:col': 'company.name' }` 형태(출처.항목)로 둔다. 도입기업·사업은 관련 기능 추가 때 다시 설계(사용자 지시).

### 5.5 서식 편집 (관리자)

- 서식 관리 › 새 서식 만들 때 **"시트 서식"** 선택 → 시트 편집기(오전에 만든 SheetEditor를 문서 전체용으로 확장한 것)가 A4 폭 안내선과 함께 열린다.
- 도구 모음(오늘 것 + 추가): 굵게·글자색·배경색(팔레트 + 직접 색 지정)·정렬·숫자 표시·테두리·병합·행/열 추가삭제·수식 도우미 버튼·셀 찍기 + **입력 칸 종류 · 칸 이름 · 데이터 불러오기 · 비공개 · 직인 칸 · 잠금**.
- **엑셀 불러오기**: .xlsx 선택 → 첫 번째 시트를 읽어 값·병합·열 너비·행 높이·글꼴 굵기·글자/배경색(**엑셀 색 그대로**)·정렬·테두리·숫자 표시·**수식**을 가져온다. 지원 안 하는 함수 칸은 값만 가져오고 목록으로 알림. 라이브러리는 SheetJS(xlsx) 또는 ExcelJS 중 서식 정보(테두리·색)를 읽을 수 있는 것 — builder 판단, 브라우저에서 지연 로드.
- 결재선 규칙·대외 문서·기본 참조자·보안 등급 등 **서식 설정은 지금 화면 그대로** 공유.
- **대체 서식** 선택 칸(기존 서식 목록). 새 서식 시험은 개발 DB에서 하고, 운영에서는 새 서식을 '사용'으로 켠 뒤 기존 서식을 '사용 안 함'으로 바꿔 새 기안 목록에서 숨긴다.
- 관리자가 사용 중인 시트 서식을 고쳐도 **작성 중 기안은 그대로**. 대신 지금처럼 '최신 서식 반영' 안내가 떠서 기안자가 원하면 적용(기안자가 바꾼 틀은 서식 기준으로 바뀌고 값은 보존 — 표 개편 때 만든 규칙과 같음).

### 5.6 기안 작성 (기안자)

- 시트 서식을 고르면 **엑셀식 시트 화면**(머리글·격자·도구 모음·수식 입력줄)이 문서 본문 자리에 열린다. 문서 머리(문서 제목, 결재란/직인 안내, 결재선·수신처·첨부·관련문서)는 지금 기안 화면 그대로.
- 입력 칸 종류에 맞는 입력기: 날짜·기간 달력, 드롭다운, 사람·부서 선택(기존 선택 창 재사용), 체크.
- 기안자도 틀을 자유롭게 바꿀 수 있다. 다만 관리자 전용 설정(입력 칸 종류·칸 이름·데이터 불러오기·비공개·직인·잠금)은 도구 모음에 안 보이고, **칸 이름·데이터 불러오기·직인·비공개가 붙은 칸이 든 행·열은 삭제를 막는다**("연동된 칸이 있어 지울 수 없습니다"). 행·열을 넣으면 이 설정들은 칸을 따라 이동.
- 임시저장·자동저장·상신은 지금 흐름 그대로(값만 `fieldValues.__sheet` 로).
- 기안 중 스크롤 강제이동 등 기존에 고친 입력 문제 재발 금지.

### 5.7 결재·열람·인쇄

- 결재자·열람자 화면: **머리글·격자 없이** 문서 모양으로(오늘 만든 SheetView를 문서 전체로). 비공개 칸 가림, 직인은 완료 문서에만, 대외 문서 설정 반영.
- 인쇄·PDF: 시트 가로 너비 합을 **A4 인쇄 폭에 비율로 맞춤**(CSS 축소), 세로는 행 단위로 페이지 나눔(행이 페이지 경계에서 잘리지 않게 `break-inside: avoid`). 발주 현황의 PDF 다운로드도 같은 화면 사용.
- 모바일(PWA) 상세: 같은 문서 모양을 가로 스크롤로.
- 기존 서식 문서는 지금 화면 그대로.

### 5.8 사업관리 연결

- 이번 범위 밖(도입기업·사업 데이터 불러오기와 함께 추후 설계). 시트 발주서도 결재가 완료되면 지금처럼 발주 현황에 모인다(서식 이름·코드에 '발주').

## 6. 단계(제안)

큰 작업이라 단계마다 운영 배포 가능하게 나눈다. 각 단계는 기존 서식에 영향 없음.

1. **시트 모델·수식 확장** — v3 모델, 행 높이·입력 칸·칸 이름·데이터 불러오기 구조, IF·비교·결합 연산. (화면 변화 없음)
2. **서식 편집기(시트 서식 만들기)** — 시트 편집기 문서 전체용, 관리자 전용 도구, 대체 서식 선택, approvalForms.sheet 저장. (운영 DB 속성 1개 추가)
3. **엑셀 불러오기**
4. **기안 작성·결재·열람·인쇄(A4)** — 시트 서식으로 실제 문서가 돈다. 일반 서식(연동 없음)부터.
5. **대체 서식·칸 이름** — 결재선 규칙 이어받기, 휴가·연장근로·휴일근무·외근·출장·금액·본문 연동. `docLinkType` 전환.
6. **데이터 불러오기(우리 회사·기안 정보)**
7. (사용자) 서식별 전환: 개발 DB에서 새 시트 서식 만들어 확인 → 운영에서 만들기 → 사용 → 기존 서식 '사용 안 함'

## 7. 내 판단으로 정한 것 (검토 시 확인 부탁)

- 칸 이름은 자유 입력이 아니라 **시스템 목록에서 선택**, 연동 유형별 필수 이름이 빠지면 서식 저장을 막음.
- 연동 칸·데이터 불러오기·직인·비공개 칸이 든 행·열은 기안자 **삭제 금지**.
- 시스템 계산 칸(휴가 일수 등)은 잠금 + 상신 시 재계산. 이름 붙은 입력 칸은 수식 불가.
- 서식 코드 의존 연동을 `docLinkType(doc)` 로 일원화 — 기존 문서는 동작 동일.
- `approvalForms` 에 `sheet` 속성 1개만 추가, 그 외 서식 메타(대체 서식 등)는 sheet JSON 안.
- 수식 함수 추가 범위: IF·비교·문자열 결합. 0으로 나누기는 0 유지.
- 비공개 칸은 화면에서만 가림(현행과 같음).

## 8. 빌더 재량

- 엑셀 파서 라이브러리 선택, 컴포넌트 분리, 시트 가상화(행이 많을 때) 여부.
- 시트 편집기 성능 최적화 방식.
- 인쇄 A4 맞춤 구현 방식(CSS zoom/transform 등).

## 9. 검증

- 단위 테스트: 시트 v3 모델(입력 칸·칸 이름·데이터 불러오기 이동/보존), 수식 IF·비교·결합, 엑셀 불러오기(샘플 .xlsx → 시트 값·병합·수식), `docLinkType`, 칸 이름 → fieldValues 복사, 필수 칸 이름 검사.
- 회귀: 기존 서식 기안·결재·열람·휴가 차감·캘린더·근태 — 기존 테스트 + 화면 확인.
- 화면 확인은 단계별로 사용자와 함께(사용자가 직접 테스트하는 것을 선호).

## 10. 기존 시스템 영향과 이관 후 삭제 주의

**영향 없도록 한 것**
- 기존 서식·문서 데이터는 읽기만 한다. DB 변경은 `approvalForms` 에 빈 속성 `sheet` 1개 추가뿐.
- 기존 서식은 화면 경로가 갈라져(`form.sheet` 유무) 지금 코드 그대로 돈다.

**코드가 바뀌어 회귀 확인이 필요한 곳** (기존 동작은 같아야 함)
- 연동 코드의 서식 코드 비교 → `docLinkType(doc)` 전환(휴가 차감·캘린더·근태). 기존 문서는 `__link` 가 없어 결과 동일.
- 결재선 규칙 매칭에 `replaces` 비교 추가. 기존 서식은 `replaces` 가 없어 결과 동일.
- 단계마다 기존 테스트 + 기존 서식 기안·결재·열람 확인.

**이관 후 기존 서식 삭제 시 주의 (사용자 결정 필요 시점: 이관 완료 후)**
- 기존 방식 문서는 화면을 그릴 때 **서식 정의(필드 라벨·배치)를 서식에서 읽는다.** 기존 서식을 지우면 그 서식으로 쓴 **과거 문서가 제대로 안 보이게** 된다.
- 삭제 전에 둘 중 하나가 필요: (a) 지우지 않고 '사용 안 함'으로만 두기, (b) 과거 문서가 서식 없이도 보이도록 문서마다 서식 사본을 붙이는 별도 작업. 이관이 끝날 때 다시 정한다.
- 결재선 규칙도 기존 서식 code를 가리키므로, 대체 서식이 이어받는 동안은 규칙을 지우면 안 된다.
