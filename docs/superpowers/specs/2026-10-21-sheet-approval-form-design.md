# 결재서식 시트화(엑셀 형태) 개편 설계

- 작성일: 2026-10-21
- 상태: 사용자 승인(10-22), §5.0 엑셀 편집기 모듈 분리 추가(10-22), **§11 변경 결정(11-03) — 본문과 다르면 §11이 우선**
- 선행 작업(운영 반영 완료): 엑셀식 표 편집기·시트 모델 v2(c80e542), 회사 직인(3475fce6), 대외 문서 설정(49317034), 결재선 규칙 편집기 통일(921ddc63), 사업관리 › 발주 현황(72adab0f)

## 1. 왜 하는가

지금 결재서식은 "필드(텍스트·날짜·표…)를 위에서 아래로 쌓은 것"이다. 이 구조에서는
- **다른 표나 일반 필드의 값을 수식에 넣을 수 없다** — 표마다 따로 계산된다.
- **너비·비율 조절이 거칠다** — 필드는 절반/전체, 표 열은 비율 정도만 된다.
- 발주서처럼 정해진 엑셀 양식을 그대로 옮기기 어렵고, 칸 단위로 데이터(도입기업·사업·회사 정보)를 연결하기도 어렵다.

사용자 결정: **서식 전체를 엑셀처럼 셀 단위 시트 한 장으로 만든다.** 모든 서식을 이 형태로 통일한다. 사업관리(도입기업·사업)·발주 현황과의 연결도 이 시트 위에서 칸 단위로 한다.

## 2. 사용자 확정 사항

| 항목 | 결정 |
|---|---|
| 서식 형태 | 서식 전체 = 셀 단위 시트 1장. 제목·라벨·입력칸·표가 모두 같은 격자의 셀 |
| 통일 범위 | 기존 18개 서식 포함 **전부** 시트 방식으로 |
| 전환 방식 | **관리자가 직접** 새 시트 서식을 만든다(엑셀 불러오기 또는 직접 그리기). 자동 변환 기능은 만들지 않음 |
| 기존 서식·문서 | **지우지도 고치지도 않는다.** 새 서식이 완벽히 확인될 때까지 기존 서식으로 시스템이 계속 돌아가야 함 |
| 엑셀 불러오기 | .xlsx 불러오기 포함. 값·병합·열 너비·행 높이·글꼴·굵게·색·테두리·**수식**까지 |
| 기안자 화면 | 엑셀식 시트 화면(열 A·B·C, 행 1·2·3 머리글, 격자, 도구 모음, 수식 입력줄)에서 작성 |
| 기안자 권한 | 값·틀(행·열 추가/삭제, 병합, 서식, 수식) 모두 변경 가능. **데이터 불러오기·보안(비공개)·직인 위치·칸 이름은 불가**(관리자 전용) |
| 인쇄·PDF | **가로는 A4 폭에 자동 맞춤**, 세로는 길면 여러 장으로 나눔 |
| 발주서 | 결재 완료 발주서는 사업관리 › 발주 현황에 모임(완료). 개편 후 사업·도입기업별로 모아 보기 |
| 문서관리 | 보류(현재 '준비 중'). 이번 범위 아님 |
| 대체 서식 | 새 시트 서식은 **어느 기존 서식을 대체하는지** 고를 수 있고, 고르면 그 서식의 결재선 규칙·연동·문서 종류 분류를 이어받음 |
| 엑셀 색 | **엑셀 색 그대로** 저장. 도구 모음 색 고르기에도 '직접 색 지정' 추가 |
| 시험 중 상태 | 두지 않음 — 시험은 개발 DB에서 |
| 도입기업·사업 데이터 불러오기 | **이번 범위에서 뺌** — 관련 기능 추가 때 다시 설계(사용자 지시) |
| 이관 후 | 모든 서식 이관이 끝나면 사용자가 기존 서식을 삭제할 예정 — §10 주의 참고 |
| 자동 전결 | 규칙 미매칭 기본 결재선의 자동 전결은 그대로 둠(사용자가 수동 정리 예정) |

## 3. 하지 않는 것 (이번 범위 밖)

- 기존 서식 → 시트 서식 자동 변환
- 기존 문서를 시트 형태로 다시 그리기(기존 문서는 기존 모습 그대로 영구 열람)
- 문서관리(사내규정·매뉴얼 문서고) DB화
- 모바일(PWA)에서 기안 작성 — 모바일은 보기·결재만(현행 유지)
- 엑셀 내보내기(.xlsx 저장), 여러 시트 탭, 차트, 조건부 서식, 피벗, 매크로
- VLOOKUP 등 고급 함수 (불러올 때 값만 가져오고 알림)
- 도입기업·사업 데이터 불러오기와 발주 현황의 사업·도입기업별 보기(추후 별도 설계)
- 비공개 칸의 서버 측 보호(지금처럼 화면에서 가림)

## 4. 실패로 보는 것

- 기존 서식으로 기안·결재·열람·인쇄가 하나라도 안 되는 것
- 기존 approvalForms·approvalDocs 데이터를 바꾸거나 지우는 것 (프로젝트 읽기 전용 규칙)
- 휴가 차감·캘린더 일정·근태(휴일근무·연장근로)·금액별 결재선 등 **기존 연동이 시트 서식 문서에서 동작하지 않는 것**
- 진행 중 문서에 직인이 찍히거나, 비공개 칸이 노출되는 것
- 시트 서식 인쇄물이 A4 가로를 넘어 잘리는 것
- 화면에 내부 코드·키(셀 이름 토큰, 열 키 등)가 그대로 보이는 것

## 5. 전체 구조

```
결재서식(approvalForms)
 ├─ 기존 방식: fields[] (지금 그대로)
 └─ 시트 방식: sheet (새 속성)  ← 서식 1장 = 시트 1장
                │
기안 작성 ──────┤ form.sheet 있으면 SheetDraft, 없으면 기존 DraftDocumentSheet
결재 문서 보기 ─┤ 문서에 시트가 있으면 SheetDocView, 없으면 기존 ApprovalDocumentView 본문
                │
문서(approvalDocs.payload)
 ├─ fieldValues.__sheet   : 작성된 시트 전체(값·틀·서식) — 보기·인쇄의 원본
 ├─ fieldValues.<칸 이름> : 이름 붙은 칸의 값 (기존 연동이 읽는 키 그대로: period, leaveType, …)
 └─ fieldValues.__link    : 연동 유형(휴가·외근·…)
```

두 방식은 **서식 단위로 공존**한다. 같은 화면 코드 안에서 `form.sheet` 유무로 갈라진다.

### 5.0 엑셀 편집기 모듈 분리 (10-22 사용자 결정)

엑셀 편집기는 **다른 프로젝트에서도 갖다 쓸 수 있는 독립 모듈**로 만든다.

- 위치: `src/lib/sheet/` — 지금은 이 저장소 안의 독립 폴더, 다른 프로젝트가 실제로 생기면 그때 폴더째 패키지로 꺼낸다.
- 경계: 모듈 안 파일은 **모듈 안 파일(상대 경로)·`react`·엑셀 파서 라이브러리만** 불러온다. `@/…`·전자결재 코드 불러오기 금지 — 테스트로 강제.
- 모듈이 가진 것: 시트 데이터 구조(값·병합·서식·열 너비·행 높이·수식), 수식 계산기, 행·열 조작, 엑셀 불러오기, 화면(`SheetEditor`·`SheetView`).
- 모듈은 "결재"를 모른다. 칸마다 붙는 부가 정보는 **이름공간별 범용 맵**(`cellMeta`, 행·열용 `rowMeta`·`colMeta`)으로 두고, 행·열이 움직이면 모듈이 함께 옮긴다. 뜻은 쓰는 쪽이 정한다.
- 전자결재가 얹는 것(`src/modules/gw/approval/sheetForm/`): 입력 칸 종류·칸 이름·데이터 불러오기·잠금·비공개·직인을 이 맵의 이름공간으로 저장하고, 도구 모음 추가 버튼·칸 꾸미기·행/열 삭제 허용 판단을 편집기에 넘겨 준다.
- 기존 표 필드 편집기(`formFields/SheetEditor`·`sheetModel`·`sheetOps`·`formulaEngine`)는 기존 서식용으로 **그대로 두고** 고치지 않는다. 새 모듈은 이들의 검증된 규칙을 옮겨 새로 만든다.
- 모듈 안 색은 `#rrggbb`만 쓴다(엑셀 색 그대로). 팔레트는 색 고르기 화면의 미리 정한 색 목록일 뿐이다.

### 5.1 시트 모델 (문서 전체용)

`src/lib/sheet` 의 시트 모델 위에 전자결재 칸 속성을 이름공간으로 얹는다. 아래 표의 결재 전용 개념(입력 칸·칸 이름·데이터 불러오기·잠금·비공개·직인)은 `cellMeta`/`rowMeta`/`colMeta` 이름공간이다.

개념(셀 단위는 `"r:colKey"` 키):

| 개념 | 내용 | 누가 정함 |
|---|---|---|
| `rowHeights` | 행 높이(px) | 관리자·기안자 |
| `colWidths` | 열 너비(px) — v2와 같음 | 관리자·기안자 |
| `cellInputs` | 입력 칸 종류: 글자·여러 줄·숫자·금액·날짜·기간·드롭다운(목록)·여러 선택·체크·사람·부서 | 관리자 (기안자 불가) |
| `cellNames` | 칸 이름(연동 키) — 시스템 목록에서만 선택 | 관리자 |
| `cellBinds` | 데이터 불러오기(도입기업1·2, 사업, 우리 회사, 기안 정보의 각 항목) | 관리자 |
| `cellLocks` | 기안자 수정 잠금(라벨·제목 칸 등) — 선택 | 관리자 |
| `cellStyles` | 굵게·색·배경·정렬·숫자 표시·테두리·**직인**(v2 그대로) | 서식: 둘 다 / 직인: 관리자 |
| `secretCells/Rows/Cols` | 비공개(v2 그대로) | 관리자 |
| `cellFormulas` | 수식(A1 주소, 범위, 함수) | 둘 다 |

- 열 키는 v2처럼 화면에 안 보이는 내부 키. 주소(A1)는 위치로 계산한다.
- 문서 하나의 모든 칸이 한 시트에 있으므로 "다른 표 값 참조" 문제는 사라진다(같은 시트의 다른 칸일 뿐).
- 수식 엔진: 기존 SUM·AVERAGE·MIN·MAX·ROUND에 **IF, 비교 연산(> < >= <= = <>), 문자열 결합(&)** 추가. 오류는 `#오류`, 0 나누기는 0(현행 규칙 유지).

### 5.2 저장

- **approvalForms**: 새 속성 `sheet`(문자열, 1,000,000자) 추가 — 시트 서식의 원본. `fields` 는 비워 두거나(시트 서식) 기존 값 유지(기존 서식). 운영·개발 DB에 속성 추가만 하고 기존 데이터는 그대로.
- 서식 메타에 `linkType`(연동 유형) 추가 — 속성 추가 없이 `sheet` JSON 안에 둔다.
- **approvalDocs**: 이미 `payload`(1,000,000자)에 문서 전체를 JSON으로 저장하므로 **DB 변경 없음**. `fieldValues.__sheet`(시트 직렬화 문자열), `fieldValues.__link`, 이름 붙은 칸 값을 넣는다.
- 크기 예산: 40행×12열, 서식·수식 포함 시 수십 KB 수준. 1MB 한도에 여유. 불러온 엑셀이 한도를 넘으면 불러오기 단계에서 막고 안내.

### 5.3 기존 연동 유지 — 연동 유형 + 칸 이름

기존 연동은 **서식 코드**(`휴가`·`외근`·`국내출장`·`해외출장`·`휴일근무`·`휴일근무신청`·`연장근로`)와 **필드 키**로 문서를 알아본다. 새 시트 서식은 기존 서식과 코드가 달라야 하므로(기존 서식을 지우지 않음) 다음으로 바꾼다.

1. 시트 서식에 **대체 서식**(`replaces`: 기존 서식 code, 선택)을 둔다. 고르면 그 code가 이 서식의 **연동 유형**이 된다(예: `휴가`). 고르지 않으면 연동 없는 새 서식.
   - 결재선 규칙 매칭(`approvalRoute/engine.ts`의 docType 비교, 서식별 규칙 목록)은 `docType === 규칙.docType || replaces === 규칙.docType` 로 넓혀 **기존 서식의 규칙을 그대로 이어받는다**.
   - 문서 종류 필터·검색 분류, 취소 기안(원문서 docType 복사 → 휴가 취소 시 일수 복원)도 `docLinkType` 기준으로 같게 동작해야 한다(builder 전수 조사).
2. 문서 상신 시 `fieldValues.__link = replaces`(연동 유형)를 저장한다.
3. 연동 코드가 `doc.docType === '휴가'` 처럼 보는 곳(확인된 곳: `scheduleEngine.ts`, `leave/legacyAdapter.ts`, `leave/userLeaveBalance.ts`, `commute/approvalDayIndex.ts`, 그 외 builder가 전수 조사)을 `docLinkType(doc)` 한 함수로 바꾼다: `fieldValues.__link ?? docType`. 기존 문서는 `__link`가 없어 지금과 똑같이 동작.
4. **칸 이름**: 연동 유형마다 필요한 이름 목록을 시스템이 갖고, 관리자는 그 목록에서 칸에 이름을 붙인다. 상신 시 이름 붙은 칸의 값을 `fieldValues.<이름>`에 복사한다. 이름 = 기존 필드 키 그대로(예: 휴가 `period`, `period__end`, `period__days`, `leaveType`, `startTime`, `endTime`, `substituteId`, `emergencyContact`; 외근·출장 `destination`, `purpose`, `transportation`, `companions` 등 — builder가 `scheduleEngine.ts`·휴가 정책 코드에서 전수 목록화).
5. 연동 유형별 **필수 칸 이름**이 빠지면 서식 저장을 막고 "휴가원에는 '휴가 시작일' 칸이 필요합니다"처럼 안내(화면에는 한글 이름만, 키는 노출 안 함).
6. 공통 칸 이름(모든 서식): `body`(본문 — 문서 목록 미리보기·검색), `amount`(결재 금액 — 금액별 결재선 규칙). 결재 금액 칸은 지금 `amountFieldOf` 와 같은 역할.
7. 이름 붙은 **입력 칸**(휴가 시작일·결재 금액 등)은 값 입력만 되고 수식은 넣을 수 없다. 휴가 일수처럼 시스템이 계산하던 값(`period__days`, 반차·반반차)은 연동 유형 '휴가'일 때 기간 입력 칸 옆에 **시스템이 계산해 채우는 칸**(관리자가 '휴가 일수' 이름을 붙인 칸)으로 처리 — 기존 휴가 정책 함수(`calculateLeaveDays`)를 그대로 호출. 이 칸은 **기안자가 고칠 수 없게 잠그고, 상신할 때 시스템이 다시 계산**해 넣는다.

### 5.4 데이터 불러오기 (이번 범위: 우리 회사·기안 정보만)

- 관리자가 칸을 고르고 도구 모음 **"데이터 불러오기"** → 우리 회사(회사명·사업자번호·대표자·주소·전화·팩스), 기안 정보(기안자·기안부서·기안일) 중 선택.
- 기안 시작 시 채움. 기안자가 고쳐 쓸 수 있고, 상신 시점 값으로 저장.
- 구조는 나중에 도입기업·사업 묶음을 더할 수 있게 `cellBinds: { 'r:col': 'company.name' }` 형태(출처.항목)로 둔다. 도입기업·사업은 관련 기능 추가 때 다시 설계(사용자 지시).

### 5.5 서식 편집 (관리자)

- 서식 관리 › 새 서식 만들 때 **"시트 서식"** 선택 → 시트 편집기(오전에 만든 SheetEditor를 문서 전체용으로 확장한 것)가 A4 폭 안내선과 함께 열린다.
- 도구 모음(오늘 것 + 추가): 굵게·글자색·배경색(팔레트 + 직접 색 지정)·정렬·숫자 표시·테두리·병합·행/열 추가삭제·수식 도우미 버튼·셀 찍기 + **입력 칸 종류 · 칸 이름 · 데이터 불러오기 · 비공개 · 직인 칸 · 잠금**.
- **엑셀 불러오기**: .xlsx 선택 → 첫 번째 시트를 읽어 값·병합·열 너비·행 높이·글꼴 굵기·글자/배경색(**엑셀 색 그대로**)·정렬·테두리·숫자 표시·**수식**을 가져온다. 지원 안 하는 함수 칸은 값만 가져오고 목록으로 알림. 라이브러리는 SheetJS(xlsx) 또는 ExcelJS 중 서식 정보(테두리·색)를 읽을 수 있는 것 — builder 판단, 브라우저에서 지연 로드.
- 결재선 규칙·대외 문서·기본 참조자·보안 등급 등 **서식 설정은 지금 화면 그대로** 공유.
- **대체 서식** 선택 칸(기존 서식 목록). 새 서식 시험은 개발 DB에서 하고, 운영에서는 새 서식을 '사용'으로 켠 뒤 기존 서식을 '사용 안 함'으로 바꿔 새 기안 목록에서 숨긴다.
- 관리자가 사용 중인 시트 서식을 고쳐도 **작성 중 기안은 그대로**. 대신 지금처럼 '최신 서식 반영' 안내가 떠서 기안자가 원하면 적용(기안자가 바꾼 틀은 서식 기준으로 바뀌고 값은 보존 — 표 개편 때 만든 규칙과 같음).

### 5.6 기안 작성 (기안자)

- 시트 서식을 고르면 **엑셀식 시트 화면**(머리글·격자·도구 모음·수식 입력줄)이 문서 본문 자리에 열린다. 문서 머리(문서 제목, 결재란/직인 안내, 결재선·수신처·첨부·관련문서)는 지금 기안 화면 그대로.
- 입력 칸 종류에 맞는 입력기: 날짜·기간 달력, 드롭다운, 사람·부서 선택(기존 선택 창 재사용), 체크.
- 기안자도 틀을 자유롭게 바꿀 수 있다. 다만 관리자 전용 설정(입력 칸 종류·칸 이름·데이터 불러오기·비공개·직인·잠금)은 도구 모음에 안 보이고, **칸 이름·데이터 불러오기·직인·비공개가 붙은 칸이 든 행·열은 삭제를 막는다**("연동된 칸이 있어 지울 수 없습니다"). 행·열을 넣으면 이 설정들은 칸을 따라 이동.
- 임시저장·자동저장·상신은 지금 흐름 그대로(값만 `fieldValues.__sheet` 로).
- 기안 중 스크롤 강제이동 등 기존에 고친 입력 문제 재발 금지.

### 5.7 결재·열람·인쇄

- 결재자·열람자 화면: **머리글·격자 없이** 문서 모양으로(오늘 만든 SheetView를 문서 전체로). 비공개 칸 가림, 직인은 완료 문서에만, 대외 문서 설정 반영.
- 인쇄·PDF: 시트 가로 너비 합을 **A4 인쇄 폭에 비율로 맞춤**(CSS 축소), 세로는 행 단위로 페이지 나눔(행이 페이지 경계에서 잘리지 않게 `break-inside: avoid`). 발주 현황의 PDF 다운로드도 같은 화면 사용.
- 모바일(PWA) 상세: 같은 문서 모양을 가로 스크롤로.
- 기존 서식 문서는 지금 화면 그대로.

### 5.8 사업관리 연결

- 이번 범위 밖(도입기업·사업 데이터 불러오기와 함께 추후 설계). 시트 발주서도 결재가 완료되면 지금처럼 발주 현황에 모인다(서식 이름·코드에 '발주').

## 6. 단계(제안)

큰 작업이라 단계마다 운영 배포 가능하게 나눈다. 각 단계는 기존 서식에 영향 없음.

1. **시트 모델·수식 확장** — v3 모델, 행 높이·입력 칸·칸 이름·데이터 불러오기 구조, IF·비교·결합 연산. (화면 변화 없음)
2. **서식 편집기(시트 서식 만들기)** — 시트 편집기 문서 전체용, 관리자 전용 도구, 대체 서식 선택, approvalForms.sheet 저장. (운영 DB 속성 1개 추가)
3. **엑셀 불러오기**
4. **기안 작성·결재·열람·인쇄(A4)** — 시트 서식으로 실제 문서가 돈다. 일반 서식(연동 없음)부터.
5. **대체 서식·칸 이름** — 결재선 규칙 이어받기, 휴가·연장근로·휴일근무·외근·출장·금액·본문 연동. `docLinkType` 전환.
6. **데이터 불러오기(우리 회사·기안 정보)**
7. (사용자) 서식별 전환: 개발 DB에서 새 시트 서식 만들어 확인 → 운영에서 만들기 → 사용 → 기존 서식 '사용 안 함'

## 7. 내 판단으로 정한 것 (검토 시 확인 부탁)

- 칸 이름은 자유 입력이 아니라 **시스템 목록에서 선택**, 연동 유형별 필수 이름이 빠지면 서식 저장을 막음.
- 연동 칸·데이터 불러오기·직인·비공개 칸이 든 행·열은 기안자 **삭제 금지**.
- 시스템 계산 칸(휴가 일수 등)은 잠금 + 상신 시 재계산. 이름 붙은 입력 칸은 수식 불가.
- 서식 코드 의존 연동을 `docLinkType(doc)` 로 일원화 — 기존 문서는 동작 동일.
- `approvalForms` 에 `sheet` 속성 1개만 추가, 그 외 서식 메타(대체 서식 등)는 sheet JSON 안.
- 수식 함수 추가 범위: IF·비교·문자열 결합. 0으로 나누기는 0 유지.
- 비공개 칸은 화면에서만 가림(현행과 같음).

## 8. 빌더 재량

- 엑셀 파서 라이브러리 선택, 컴포넌트 분리, 시트 가상화(행이 많을 때) 여부.
- 시트 편집기 성능 최적화 방식.
- 인쇄 A4 맞춤 구현 방식(CSS zoom/transform 등).

## 9. 검증

- 단위 테스트: 시트 v3 모델(입력 칸·칸 이름·데이터 불러오기 이동/보존), 수식 IF·비교·결합, 엑셀 불러오기(샘플 .xlsx → 시트 값·병합·수식), `docLinkType`, 칸 이름 → fieldValues 복사, 필수 칸 이름 검사.
- 회귀: 기존 서식 기안·결재·열람·휴가 차감·캘린더·근태 — 기존 테스트 + 화면 확인.
- 화면 확인은 단계별로 사용자와 함께(사용자가 직접 테스트하는 것을 선호).

## 10. 기존 시스템 영향과 이관 후 삭제 주의

**영향 없도록 한 것**
- 기존 서식·문서 데이터는 읽기만 한다. DB 변경은 `approvalForms` 에 빈 속성 `sheet` 1개 추가뿐.
- 기존 서식은 화면 경로가 갈라져(`form.sheet` 유무) 지금 코드 그대로 돈다.

**코드가 바뀌어 회귀 확인이 필요한 곳** (기존 동작은 같아야 함)
- 연동 코드의 서식 코드 비교 → `docLinkType(doc)` 전환(휴가 차감·캘린더·근태). 기존 문서는 `__link` 가 없어 결과 동일.
- 결재선 규칙 매칭에 `replaces` 비교 추가. 기존 서식은 `replaces` 가 없어 결과 동일.
- 단계마다 기존 테스트 + 기존 서식 기안·결재·열람 확인.

**이관 후 기존 서식 삭제 시 주의 (사용자 결정 필요 시점: 이관 완료 후)**
- 기존 방식 문서는 화면을 그릴 때 **서식 정의(필드 라벨·배치)를 서식에서 읽는다.** 기존 서식을 지우면 그 서식으로 쓴 **과거 문서가 제대로 안 보이게** 된다.
- 삭제 전에 둘 중 하나가 필요: (a) 지우지 않고 '사용 안 함'으로만 두기, (b) 과거 문서가 서식 없이도 보이도록 문서마다 서식 사본을 붙이는 별도 작업. 이관이 끝날 때 다시 정한다.
- 결재선 규칙도 기존 서식 code를 가리키므로, 대체 서식이 이어받는 동안은 규칙을 지우면 안 된다.

1단계 브랜치를 운영 main(11-03)에 합쳐 검토하고, 요구사항을 다시 정리해 아래처럼 바꾼다. 본문과 다르면 이 절을 따른다.

### 11.1 이 개편으로 얻으려는 것 (요구사항)

| 누가 | 원하는 것 | 해결 방법 |
|---|---|---|
| 경영진 | 발주서 등에서 **프로젝트를 드롭다운으로 고르면 그 문서에 필요한 프로젝트 정보가 모두 채워짐** | 데이터 불러오기에 사업·도입기업 추가(§11.4) |
| 관리자·개발자 | **엑셀 양식 파일을 올리면 그대로 새 서식이 생김** — 지금은 서식 하나 만드는 데 손이 너무 감 | 엑셀 불러오기(§5.5) — 지금 구조로는 불가능에 가까워 시트 전환의 핵심 이유 |
| 관리자 | 한 줄에 표 여러 개, 칸 크기 자유 조절 | 시트 격자 |
| 관리자 | 표 칸 크기를 바꾸면 옆 칸이 줄어 글씨가 잘림 | 열 너비를 직접 정하는 시트 구조 (기존 서식의 버그는 별도로 고친다) |

### 11.2 문서에는 값만 저장한다 (§5.2 변경)

- 본문은 문서마다 시트 전체(`fieldValues.__sheet`)를 저장했다. 측정해 보니 40행×12열에 테두리·서식을 넣으면 문서 하나가 약 57KB — 운영 문서 평균(약 4.8KB, 516건)의 12배다. 결재 문서 전체를 한 번에 읽는 화면이 여러 곳이라 문서가 쌓일수록 느려진다.
- **틀(배치·병합·너비·서식·수식·칸 속성)은 서식 버전마다 한 번만** 저장하고, **문서에는 값만**(`extractValues` — 입력·불러오기 칸 값과 수식 결과) 저장한다.
  - 문서: `fieldValues.__values`(칸 키 → 글자), `fieldValues.__formVersion`(서식 버전 id), 이름 붙은 칸 값(`namedValues`, 본문 §5.3 그대로).
  - 서식 버전: 새 컬렉션(예: `approvalFormVersions`)에 서식을 저장할 때마다 틀 한 벌을 쌓는다. **기존 컬렉션은 건드리지 않는다**(읽기 전용 규칙).
- 상신된 문서를 볼 때는 그 문서의 서식 버전 틀에 값을 얹고 **다시 계산하지 않는다**(`applyValues(..., { recalc: false })`). 서식을 고치거나 계산 규칙이 바뀌어도 결재 당시 모습·숫자가 그대로다. 지금 방식의 "옛 문서가 현재 서식으로 다시 그려지는" 문제(§10)도 시트 서식에서는 생기지 않는다.
- 크기는 지금 문서와 비슷한 수준이 된다.

### 11.3 기안자는 입력 칸만 고친다 (§2 '기안자 권한' 변경)

- 본문은 기안자도 행·열·병합·서식·수식을 바꿀 수 있게 했다. 그러면 문서마다 틀이 달라져 §11.2(값만 저장)가 불가능하고, 자동 입력할 칸 위치도 문서마다 달라진다.
- **기안자는 관리자가 입력 칸으로 정하고 잠그지 않은 칸만 고친다**(`isDraftEditable`). 붙여넣기도 그 칸에만 들어가고 시트를 늘리지 않는다(`pasteDraftTsv`). 도구 모음은 기안자에게 보이지 않는다.
- **열린 문제 — 반복 행**: 발주서 품목처럼 줄 수가 문서마다 다른 표가 필요하다. 관리자가 '반복 구간'(행 범위)을 정하면 기안자가 그 안에서만 행을 넣고 빼게 하고, 값 키는 반복 회차로 매기는 방식을 2단계에서 설계한다.

### 11.4 데이터 불러오기 범위를 넓힌다 (§3·§5.4·§5.8 변경)

- **(11-03 추가) 사업 데이터는 아직 인트라넷에 연동돼 있지 않다.** 담당 차장이 프로젝트 관리 엑셀을 보내 주면 항목을 정한다. 그때까지는 **구조만** 열어 둔다: 불러오기 출처를 `출처.항목`(예: `project.name`)으로 두어 나중에 출처를 더할 수 있게 하고, 입력 칸 종류에 "출처 선택"(드롭다운)을 넣을 자리를 남기며, 불러온 값은 상신 때 복사한다.
- **사업(프로젝트) 불러오기를 이번 범위에 넣는다.** 관리자는 칸에 '사업 선택' 입력 칸과, 그 사업의 항목(사업명·도입기업명·계약 금액 등 — 사업관리 데이터 항목에서 고름)을 연결한다. 기안자가 드롭다운에서 사업을 고르면 연결된 칸이 채워진다.
- **관련 문서 값 가져오기**: 관련 문서를 고르면 그 문서의 **이름 붙은 칸 값**을 가져온다(예: 품의서 → 발주서 품목·금액). 위치(B3)가 아니라 칸 이름으로 찾으므로 서식이 달라도 된다.
- 가져온 값은 **상신할 때 문서에 복사**한다. 사업 정보나 원본 문서가 나중에 바뀌어도 결재된 문서는 그대로다.

**프로젝트 값 채우기로 방향 정리(11-03 사용자)**

**기안 작성**
- 기안 서식 목록에 시트 서식이 나온다(사용을 켠 것). 기안 화면은 서식 버전 틀을 문서 모양 그대로 보여 주고 **입력 칸에만 입력 상자**를 둔다(`SheetDraftForm`): 글·여러 줄(쓰면 행이 늘어 글씨가 잘리지 않음)·숫자/금액(쓸 때는 숫자, 벗어나면 서식대로 콤마)·날짜·기간·선택(드롭다운)·여러 개 선택·체크. 사람·부서는 아직 글 입력.

- 문서 `fieldValues`: `__values`(칸 값 JSON — 입력 칸과 수식 결과), `__formVersion`(`서식코드@v번호`), 이름 붙은 칸 값(`body`·`amount`). '결재 금액' 칸 값은 문서 금액이 되어 금액별 결재선 규칙이 읽는다.
- **칸 이름 정리(11-03 사용자)**: 칸 이름 목록은 **금액키**(`amount`) 하나. 기존 서식 필드의 '금액키' 체크와 같은 역할 — 그 칸 값이 문서 금액이 되어 결재선 규칙의 금액 조건(이상~미만)이 읽는다. ### 11.11 반복 구간 (2026-11-03)

- 기존 서식 '표'에는 기안자용 [행 추가]·[행 삭제]가 있고 사용 중인 서식(계약보고서·소모품 신청서·원자재 품의서·채용 품의서·발주서 — 개발 DB 기준)이 쓴다. 시트로 옮기려면 같은 기능이 필요해 넣었다.
- **시트는 한 장의 격자라 행 전체를 넣는다**(엑셀 '행 삽입'과 같음). 같은 행에 나란히 있는 표(계약보고서 매출구분·매입구분)는 함께 늘어난다 — 따로 늘려야 하면 위아래로 배치한다. 열 범위만 밀어내는 방식('셀 삽입 → 아래로')은 옆 표·병합과 어긋나 넣지 않았다.
- 관리자: 행을 골라 칸 속성 패널 '반복 구간'에서 이름과 함께 지정(`rowMeta.repeat[행] = { id, label }`). 편집기에서 첫 열에 보라색 띠. 구간 한가운데에 행을 넣으면 그 행도 구간에 넣는다(`healRepeatSections`). 저장 전 검사: 끊긴 구간, 구간 안 칸 이름(새 행에 본뜨지 않음).
- 기안자: 시트 아래 '품목 5줄 [행 삭제] [행 추가]'. 행 추가는 구간 **끝에** 붙이고 마지막 행을 본뜬다 — 서식·테두리·입력 칸·잠금·비공개·행 높이·마지막 행 안의 가로 병합, 수식은 한 행 아래로 옮겨서. 끝 바로 다음에 넣으므로 구간을 덮는 범위 수식(`=SUM(E8:E12)`)이 늘어나고, 구간 전체를 세로로 덮는 병합(왼쪽 이름 칸)도 늘린다. 행 삭제는 마지막 줄을 지우고, 관리자가 그린 줄 수 밑으로는 못 줄인다(기존 표와 같음). 구간당 최대 200줄 추가.
- 저장: 문서에 구간별로 더 붙인 줄 수만(`fieldValues.__rows` = `{구간 id: 줄 수}`). 보기·작성은 서식 버전 틀을 같은 규칙으로 펼친 뒤 값을 얹는다(`expandRepeats`) — 아래 구간부터 펼쳐 위 구간 행 번호가 흔들리지 않게.

### 11.12 관련 문서 값 가져오기 (2026-11-03, 4단계 중 막히지 않은 부분)

- **칸 이름을 직접 쓸 수 있다**(칸 속성 '칸 이름' › 직접 쓰기…). 시스템 이름은 금액 키(`amount`) 하나, 직접 쓴 이름은 '품명'·'공급가액'처럼 아무 이름(30자, '__'로 시작 금지). 서식에 하나씩.
- **반복 구간 안 칸의 이름 = 그 구간의 열 이름.** 값은 줄마다 하나씩(목록). 한 열에 이름 하나. 금액 키는 구간 밖에만.
- 문서에 `fieldValues.__named` = `{ 이름: 값 | 값[] }` 를 남긴다(작성할 때마다). 문서 맨 위 칸에는 시스템 이름(`amount`)만 복사 — 직접 쓴 이름이 기존 필드 키와 섞이지 않게.
- 기안 화면: 관련 문서를 고르면 시트 위에 '관련 문서 값 가져오기 [문서번호 제목]' 단추. 누르면 같은 이름 칸을 채운다(확인 창에 채울 이름 목록, 이미 쓴 값은 바뀜). 반복 구간 열은 줄이 모자라면 행을 늘리고 남는 줄은 비운다. 수식 칸·입력 칸 아닌 칸은 채우지 않는다. 가져온 칸의 사람 ID(`__refs`)는 지운다.
- 원본: 시트 문서는 `__named`, 옛 서식 문서는 필드 라벨을 이름으로(글·장문·숫자·금액·날짜·기간·선택·다중선택·부서 — 표·직인 등 제외). 문서는 이미 받아 둔 목록(캐시)에서 찾는다.
- 가져온 값은 이 문서에 복사되어 저장된다 — 원본 문서가 나중에 바뀌어도 그대로.
- 남은 것: 옛 서식 '표' 필드의 줄 값을 반복 구간으로 가져오기(표 열 이름 ↔ 칸 이름).

### 11.13 5단계 — 대체 서식·연동 칸 이름 (2026-11-04)

팀원 계획(§5.3, §6-5)대로 구현. 기존 문서·서식은 결과가 같다(아래 '기존 동작').

**대체 서식(연동 유형)**
- 서식 편집기 서식 정보에 '대체 서식 (연동)' — 휴가원·외근·국내출장·해외출장·휴일근무 중 하나를 대신한다고 정한다.
- 저장 위치: 서식 버전(`approvalFormVersions.link`, 새 컬렉션의 속성 — 기존 `approvalForms` 는 그대로). 대체 서식만 바꿔 저장해도 새 버전(문서가 어느 연동으로 쓰였는지 버전에 묶임).
- 상신하면 문서 `fieldValues.__link` = 대체한 서식 코드.

**연동 코드 전환 — `docLinkType(doc)` = `fieldValues.__link ?? docType`** (`src/domain/approvalDoc/linkType.ts`)
- 일정·근태 연결(`scheduleEngine.extractScheduleInfo`), 휴일근무 근태(`approvalDayIndex`), 휴가 이력·잔여(`leave/legacyAdapter`, `leave/userLeaveBalance`), 수신함 외근·출장 기안자 판정(`approvalDoc/engine`), 휴가 양식 보존(`approvalDoc.repo` migrateDoc), 모바일 휴가 표시, 근태 휴가 보기.
- 결재선 규칙: `r.docType === 서식코드 || r.docType === 연동 유형` — 대체한 서식의 규칙을 그대로 이어받는다(`RouteContext.linkType`).
- 기안 화면의 휴가 검사·휴가 양식(LeaveForm)·외근·출장 검사·휴일근무 근무 일자(주말·공휴일만) 검사도 연동 유형으로.

**연동 칸 이름** (`LINK_TYPES` — 기존 필드 키 그대로, 화면엔 한글)
- 휴가: 휴가 종류(`leaveType`, 필수, 선택 칸 — 항목은 휴가 정책 이름만, 붙이면 자동으로 채움), 휴가 기간(`period`, 필수 — 기간 칸이면 `period`·`period__end` 로 나눠 넣음), 휴가 종료일, 휴가 일수(`period__days`, 시스템 계산 — 기존과 같은 calculateLeaveDays, 공휴일 제외·반차 0.5), 시작·종료 시각, 업무 대행자(`substituteId`, 사람 칸 — 사용자 ID 를 넣음), 긴급 연락처, 사유(`body`).
- 외근: 외근 일자(필수)·외근지(필수)·외근 구분·시각·목적·교통수단·동행자·사유. 출장: 출장 기간(필수)·출장지(필수)·목적·교통수단·동행자(해외는 출장 구분)·사유. 휴일근무: 근무 일자(필수, 주말·공휴일만 고를 수 있는 달력)·출근·퇴근 시각·근무 시간·사유.
- 서식 저장 전 검사: 필수 연동 칸이 없거나 휴가 종류 항목이 정책에 없으면 막는다.
- 상신 때 연동 칸 값을 문서 맨 위 칸(기존 필드 키)으로 복사 — 연동 코드가 기존 휴가원 문서와 똑같이 읽는다. 이름 붙은 칸 값은 입력 칸이 아니어도 문서에 저장(시스템 계산 칸).

**기존 동작** — 기존 문서엔 `__link` 가 없어 `docLinkType` 이 `docType` 그대로. 결재선은 linkType 이 없으면 비교가 그대로. 시험: 기존 테스트 전체 + 시트 외근·휴일근무 문서의 근태·일정 연결, 연동 유형 결재선 매칭.

**남은 것**
- 휴일근무 '출근·퇴근 시각 근태 자동 입력'(기존 서식의 자동 입력 단추)은 시트 서식엔 아직 없다 — 손으로 입력.
- 실제 서식 전환(§6-7): 개발 DB에서 시트 서식(대체 서식 지정) 만들어 기안·결재·휴가 차감·캘린더 확인 → 운영. 기존 서식은 '사용 안 함'(삭제 금지 — §10).
- 운영 배포 때 `npm run appwrite:schema:sheet -- --prod` 는 새 컬렉션만 만든다(이미 있으면 건너뜀). link 속성은 새 컬렉션 생성에 포함.

### 11.14 문서 보기·부품 목록 (2026-11-04)

참고: 다우오피스 양식 편집기 — 워드 같은 웹 문서 편집기(HTML)에 표를 그리고, 왼쪽 부품 목록(텍스트·숫자·날짜·기간·사용자·결재선·기안자/문서번호 등)을 표 칸에 넣는 방식. 엑셀 격자는 아니지만 '표 + 칸마다 부품'이라는 핵심은 시트 서식과 같다. 그래서 저장 형식(시트·칸 속성)은 그대로 두고 편집 화면만 맞췄다.

- **문서 보기**(기본): `SheetEditor` 의 `paper` — 행·열 머리를 가는 띠로 줄이고, 격자를 실제 문서 틀(문서 머리→시트→첨부·맺음말) 안에 그린다. 띠 클릭으로 행·열 고르기(Shift 로 늘리기), 띠 끝 끌기로 크기 바꾸기. 넓은 시트는 종이를 넓힌다(문서·인쇄는 종전대로 줄여 맞춤). 격자 보기와 오가며, 고른 보기는 브라우저에 기억.
- **부품 목록**: 오른쪽 '칸 속성' 위. 입력 부품 11종·자동 항목(기안 정보 4종)·회사 직인·반복 구간·부품 빼기. 칸을 고르고 누르거나 칸으로 끌어 놓는다(고른 범위 안에 놓으면 범위 전체). 하는 일은 칸 속성의 입력 칸·자동 채우기·직인·반복 구간과 같다. 입력 부품과 자동 항목은 한 칸에 함께 두지 않는다(넣으면 다른 쪽을 지움). 수식 칸엔 입력 부품을 넣지 않는다.
- 남은 차이(뒤로): 결재선·본문 편집기를 표 안 아무 데나 두는 부품으로 — 결재 칸 수가 결재선에 따라 달라지고 인쇄 모양이 바뀌어 작업이 크다.

### 11.15 문서 머리를 시트 안으로·대외 문서 (2026-11-04)

문제: 고정된 문서 머리(문서 정보 표·제목 줄)와 엑셀 본문의 색·글꼴·선이 달라 두 양식처럼 보임. 엑셀 양식마다 색이 달라 머리를 어느 하나에 맞출 수 없다 → 머리 항목을 시트 칸(부품)으로 옮겨 관리자가 서식 색으로 함께 칠한다(다우오피스도 기안자·문서번호를 양식 표 안 부품으로 둔다).

- **문서 항목 부품**(bind `doc.title`·`doc.preservation`·`doc.visibility`): 기안자가 시트 칸에서 제목·보존연한·공개범위를 쓴다. 값은 칸이 아니라 문서 자체(title·preservationPeriod·visibility)에 저장 — 문서 목록·검색·모바일·권한은 그대로. 문서 보기는 문서 값을 보인다(`DraftInfo.title·preservation·visibility`).
- **머리에서 자동으로 빼기**: 시트에 기안 정보·문서 항목 칸이 있으면 문서 머리의 같은 항목(문서번호·기안부서·기안자·기안일·보존연한·공개범위·제목 줄)을 뺀다(`sheetHeaderItems` → `withBodyHeader`). 문서가 쓴 **서식 버전의 시트**로 정하고 서식에 저장하지 않는다 — 서식을 고쳐도 이미 쓴 문서의 머리는 그대로(상신 문서 불변). 제목 줄은 화면용 표시 `titleRow`(서식 설정 목록엔 없음).
- **[문서 정보 표 넣기]**: 시트 맨 위에 문서번호·기안부서 / 기안자·기안일 / 보존연한·공개범위 / 제목 표 + 빈 줄. 열이 넷보다 적으면 늘린다. 넣은 뒤엔 일반 칸 — 색·위치·병합을 서식에 맞게. 새 시트 서식은 이 표가 든 틀로 시작한다.
- **대외 문서**: 시트 편집기에 서식 '대외 문서'(hideDocInfoOnComplete, 기존 서식과 같은 설정) + 행 속성 '대외 문서에서 숨김'(rowMeta `extHide`). 결재 완료 대외 문서(거래처용·발주서 PDF)에서 머리·결재란·첨부·맺음말과 함께 숨김 행을 통째로 뺀다(칸만 비우면 빈 줄이 남아 어색해서 행 단위). 문서 정보 표로 넣은 행은 처음부터 숨김. 미리보기에 '대외 문서' 탭.
- 아직 시트 밖: 회사 로고 줄, 결재란(결재선에 따라 칸 수가 바뀜 — 다음 과제), 첨부·관련 문서·맺음말.

### 11.16 문서 머리 전체를 시트 안으로 (2026-11-04)

편집 화면이 문서 머리(고정)와 시트로 나뉘어 복잡해 보인다는 의견 → 문서 머리 전체를 시트 칸으로 옮긴다. 시트 밖에는 문서 기능(첨부·관련 문서·긴급 후결 안내)만 남는다.

- **문서 머리 부품**(bind `doc.approvalLine`·`doc.logo`·`draft.sign`): 칸에 그림을 끼운다(값 없음). 그림은 문서를 그리는 쪽이 만들어 넘긴다(`SheetSlots`) — 기안 화면은 `ApprovalDraftDocumentSheet` 의 결재란(누르면 결재선 편집)·로고·기안자 서명을, 문서 보기는 `ApprovalDocumentView` 의 결재란(취소완료 도장 포함)·로고·서명을 그대로 쓴다. `sheetBody` 는 함수로 slots 를 받는다.
- **결재란이 시트에 있으면 문서 머리 전체를 뺀다**(`sheetHeaderItems` → 모든 머리 항목 + 제목 줄 + `stampTable`). 결재란이 없는 시트(문서 정보 표만, 또는 아무것도 없음)는 종전처럼 항목별로 뺀다 — 이미 쓴 문서·서식 모양 그대로.
- **[문서 머리 넣기]**(종전 [문서 정보 표 넣기]): 위 — 회사 로고 / 큰 제목·결재란(한 줄, 높이 96px, 결재란은 오른쪽 절반) / 문서 정보 표, 아래 — 맺음말·기안일·기안자 서명. 새 서식은 이 틀로 시작(열 너비는 A4 인쇄 폭에 맞춰 나눔). 엑셀을 불러오면 있던 머리를 엑셀 위·아래에 다시 넣고 큰 제목 칸은 비운다(엑셀 제목과 겹치지 않게).
- **대외 문서**: 로고 줄·문서 정보 표·맺음말은 숨김 행, 큰 제목 줄은 남김(제목이 비면 숨김). 결재란 칸은 대외 문서에서 저절로 빈다.
- **직인 서식**: 문서 보기의 직인 서식 판단에 시트의 회사 직인 칸을 더했다(`sheetHasSeal`) — 전에는 옛 서식 항목만 봐서 시트 서식은 완료 후에도 결재란이 보였다(버그). 직인 서식은 진행 중에만 결재란, 완료 후엔 결재란 칸을 비우고 회사 직인.
- 서식 편집기: 문서 머리 전체가 시트에 있으면 '문서 머리에 보일 항목' 목록 대신 안내 한 줄(대외 문서 체크는 남김), 격자 보기의 머리 미리보기도 감춘다. 미리보기 문서 틀은 결재란이 보이게 예시 결재선(나 한 명)을 쓴다.

### 11.17 기존 서식 부품·자동 변환 (2026-11-04)

기존 서식을 시트로 옮기기 전에 빠진 부품을 채우고, 기존 서식으로 시트 초안을 만드는 변환을 붙였다.

- **자동번호**(cellMeta `autoNo` = AutoNumberConfig): 기존 '자동번호'와 같은 번호 모양. 상신 때(`issueAutoNumbers`) 문서가 쓴 서식 버전의 자동번호 칸에 번호를 매겨 칸 값(`__values`)에 넣는다 — 재상신은 받은 번호 그대로, '문서번호로 표시'면 `DOC_NO_VALUE_KEY` 도. 순번 채널의 칸 구분은 시트 안 순서(`sheet#1`…) — 칸 주소는 행을 넣고 빼면 바뀌므로 쓰지 않는다. 작성 화면은 '상신하면 자동으로 매겨집니다(예: …)'. 순수 로직은 `domain/approvalForm/sheetAutoNumber.ts`.
- **회사 정보 머리글**(bind `doc.letterhead`): 기존 '회사정보'와 같은 `CompanyLetterheadBlock`(기본 설정).
- **회사 로고**: 문서 머리 로고 칸을 workfit 로고 대신 회사 정보 화면의 대표 로고(`CompanyLogo`)로. 미등록이면 작성 화면에만 안내.
- **안내문**(cellMeta `guide`): 칸 글자를 작성 화면에만 흐리게, 결재·인쇄·대외 문서엔 안 나옴.
- **직인 고르기**(cellMeta `sealMark`): 회사 직인 칸이 쓸 직인(회사 로고·직인 목록). 문서 보기는 시트가 고른 직인으로 감싼다.
- **문서 이름(큰 제목)** 칸: 편집기에 '격식 문서명(없다면 서식명)이 자동으로 들어갑니다' 안내.
- **기존 서식 → 시트 초안**(`legacyFormToSheet`): 서식 목록 카드의 [시트로 만들기]. 새 서식(`코드_시트`, 이름 끝 '(시트)', 사용 안 함)으로 열고 기존 서식은 그대로.
  - 항목 → [라벨 | 값](반쪽은 한 줄에 둘), 섹션 → 제목 줄. 입력 종류·선택 항목·금액 키(amount)·연동 칸 이름(휴가 period 등)·비공개·대외 숨김을 옮긴다. 연동 서식 코드(휴가 등)면 대체 서식도.
  - 표 → 칸·병합·굵게·정렬·회색 바탕, 빈 칸은 입력 칸, 마지막 줄은 반복 구간. 수식은 값만(경고).
  - 직인 → 발신 명의 + 직인 칸(고른 직인), 자동번호·회사정보·안내문 → 각 부품, 문서제목 → 문서 정보 표의 제목 칸(문서 정보 표를 안 넣는 서식은 본문 제목 칸).
  - 문서 머리 전체를 넣되 기존 서식이 숨긴 항목은 뺀다(공문: 로고·큰 제목·문서 정보·맺음말 없이 결재란만). 일부만 숨긴 문서 정보는 경고.
  - 옮기지 못한 것(필수 표시, 조건부 보이기, 표 수식)은 편집기 위 안내로.
  - 개발 DB 서식(휴가원·계약보고서·공문·발주서)으로 변환·미리보기 확인.

### 11.18 기존 서식에 시트 붙이기(같은 코드)·시트 적용 스위치 (2026-11-04)

§11.17 의 변환은 새 코드(`휴가_시트`)로 새 서식을 만들었다. 그런데 서식 코드를 기준으로 도는 기능이 결재선 규칙 밖에도 있다 — 결재함 완료 탭 서식 필터(PC·모바일), 대결(부재) 설정, 문서함 '특정 서식만' 권한, 자동번호 순번. 코드가 바뀌면 옛 문서와 새 문서가 갈리고 이것들이 안 걸린다. 그래서 **같은 코드에 시트 틀을 붙이는 방식**으로 바꿨다.

- 서식 기록(approvalForms)·항목 목록은 그대로(읽기 전용). 시트 틀은 버전 기록(approvalFormVersions)에 v1부터 쌓는다. 옛 문서는 `__formVersion` 이 없어 기존 항목으로, 새 문서는 시트로 그려진다(문서마다).
- **시트 적용 스위치**(새 컬렉션 `approvalSheetSwitches`, 서식마다 한 줄): 기존 서식은 켜기 전까지 기안이 기존 양식(붙이는 중인 틀이 기안자에게 안 보임), 처음부터 시트로 만든 서식은 기본 켜짐. 기안 화면은 `liveSheetVersion`. 편집기 머리의 [시트로 기안 켜짐/꺼짐], 서식 목록 배지 '시트 준비 중'.
- 편집기 저장: 기존 서식은 시트 틀만 저장하고, 서식 설정을 바꿨을 때만 서식 기록에 저장 — 그때도 항목 목록은 그대로(`saveHeader`). [기존 양식 편집]으로 기존 편집기에.
- [서식 설정] 탭: 정렬·보존연한·맺음말·기안 권한·보안·기본 수신/참조·결재선 규칙(기존 편집기와 같은 부품) — 처음부터 시트로 만든 서식도 이제 여기서.
- 시트 문서는 기존 항목을 그리지 않는다(기안 화면·문서 보기·모바일·편집기 미리보기에 `fields: []` 로 넘김). 기존 양식 전용 동작(휴일근무 자동 채우기, 표 최신 구조 반영, 직인 문구, 휴가 구분 단추)은 시트 문서에서 끈다. 시트 문서는 기존 양식의 자동번호 항목도 쓰지 않는다(순번을 두 번 받지 않게).
- 자동번호 순번 이어받기: 변환할 때 칸 번호 모양에 기존 항목 키(`channelKey`)를 넣어, 같은 코드·키·모양이면 기존 양식과 같은 순번을 이어 쓴다.
- [시트로 만들기] → '이 서식에 시트 붙이기'(같은 서식으로 연다). 옮기는 동안의 도구라 다 옮긴 뒤 숨겨도 된다. '대체 서식'은 연동 기능(다른 회사가 처음부터 휴가원을 만들 때 등)으로 남긴다.

함께 고친 것:
- 결재 완료일 줄은 결재가 끝나기 전엔 숨김(작성·결재 중), 회사 로고 줄은 대외 문서에도 보임(거래처 문서의 일부).
- 사람(여러 명) 입력 칸 — 칸에 '이름 (부서), …', 사용자 ID 는 쉼표로(__refs). 한 사람만 받는 연동 칸에는 [사람].
- 반복 구간 [행 추가]·[행 삭제]를 구간 바로 아래 띠로(SheetView `afterRow`, 인쇄 안 됨).
- 필수 입력(cellMeta `required`): 비어 있으면 상신을 막는다('필수 칸을 채워 주세요: 휴가 종류'), 이름표는 같은 줄 왼쪽 글자. 변환이 기존 '필수'를 옮긴다.
- 배포 때 `npm run appwrite:schema:sheet -- --prod` 가 approvalSheetSwitches 도 만든다(개발 DB는 만들어 둠).

### 11.19 행 보이기 조건 (2026-11-05)

기존 서식의 조건부 항목(visibleIf '키:값' — 지출결의 '지출 항목이 식대일 때만 식대 분류')을 시트에서도.

- 저장: rowMeta `showIf` = `{ name, values }`. 칸 이름 `name` 인 칸 값이 `values` 중 하나일 때만 행을 보인다(여러 선택 칸은 고른 것 중 하나라도, 체크 칸은 ✓). 조건 칸이 시트에 없으면(이름을 지웠으면) 숨기지 않는다. 숨은 행에 있는 조건 칸 값은 없는 셈 — 그 칸을 보는 행도 숨는다.
- 숨은 행은 기안 화면·문서 보기·인쇄·모바일에서 빠지고(SheetView `hiddenRows`), 필수 입력 검사에서 빠지며, 그 행의 이름 붙은 칸 값은 문서 맨 위 칸에 빈 값으로 — 지출 항목을 바꾼 뒤 전에 고른 다른 '분류'가 결재선 규칙 조건에 걸리지 않게. 칸 값(__values)은 그대로 남는다(다시 바꾸면 되살아남).
- 편집기: 칸 속성 패널 [행 보이기 조건] — 칸 이름 붙은 선택·여러 선택·체크 칸을 고르고 값을 체크. 고른 행 안의 칸은 조건 칸이 될 수 없다. 격자 마지막 열 오른쪽 아래 '조건 · 지출 항목 = 식대' 표시.
- 변환: visibleIf 항목이 만든 행(라벨·값 줄, 안내문, 표 줄)에 조건을 걸고, 조건 칸에 기존 키를 칸 이름으로 붙인다. 반쪽 항목은 조건이 같을 때만 한 줄에 둘. 섹션 항목이 모두 같은 조건이면 섹션 제목 줄도.
- 반복 구간에 기안자가 줄을 더하면 새 줄도 조건·대외 숨김을 그대로 받는다.
- 자동번호: 상신 때 번호를 받을 칸은 문서가 펼친 모양 기준(`docAutoNumberCells`) — 조건으로 숨은 행의 칸은 번호를 받지 않고(기존 양식과 같음, 순번이 헛돌지 않게), 반복 구간에 더한 줄만큼 아래 칸 자리를 민다(전에는 서식 틀 자리에 넣어 반복 구간 아래 자동번호 칸이 엉뚱한 칸에 들어갈 수 있었다).

### 11.20 전체 검토 뒤 고친 것 (2026-11-05)

- 반복 구간 [행 추가]: 한 줄짜리 구간의 가로 병합(변환한 표 마지막 줄 등)을 세로로 늘려 새 줄 칸이 덮이던 것 — 세로 병합(여러 줄)만 늘린다.
- 숨긴 행이 걸친 병합(SheetView `hiddenRows`): 보이는 줄 수만큼으로 그리고, 맨 위 행이 숨었으면 첫 보이는 행에서 원래 칸 내용·모양으로. 전에는 옆 칸이 한 칸씩 밀렸다.
- 조건으로 숨은 행의 입력 값은 기안 중에 비운다(`clearConditionHidden`) — 합계 수식·금액 키·연동 값(휴가 등)·관련 문서 가져오기·숫자 검사에 숨은 값이 남지 않게. 조건을 되돌리면 빈 칸으로 다시 나온다.
- 대외 문서: 조건으로 숨은 행은 대외 숨김 행을 빼기 전에 정해 함께 뺀다(조건 칸이 대외 숨김 행에 있어도 맞게).
- 기존 양식으로 쓴 임시 저장·반려 문서를 다시 열면 '시트로 기안'을 켠 뒤에도 기존 양식 그대로(전에는 시트로 바뀌어 쓴 내용이 안 보였다).
- 기존 서식에 붙인 시트에 엑셀을 불러와도 기존 서식의 '큰 제목 숨김'을 켜지 않는다(서식 기록이 바뀌어 옛 문서 제목까지 사라지던 것).
- 모바일 시트 문서: 문서 이름·기안자 직위·보존연한 기본값·회사 정보 칸을 PC 와 같게.
- 자동번호 자리 계산의 줄 수를 펼친 모양과 같은 상한·정수로.
