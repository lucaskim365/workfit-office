# 결재서식 표 — 엑셀식 편집기 개편 설계

- 작성일: 2026-10-21
- 브랜치: `fix/approval-table-excel` (main 0bffa92 기준) — 업무계획·사업관리 브랜치와 섞지 않고 **이것만 따로 운영 배포**
- 선행 커밋: ba9197d (수식 빈 칸 대체 버그 수정)

## 1. 왜 하는가

지금 결재서식의 표는 "맨 위 고정 제목 행 + 계산 유형 버튼(열 합산·비율·차액)" 방식이다. 사용자는 엑셀에 익숙하고, 버튼식 계산 설정으로는 원하는 표를 만들기 어렵다. 사용자 요구: **"최대한 엑셀과 동일하게."** 서식 관리자와 기안자 모두 같은 엑셀식 편집기로 표를 자유롭게 만들고 고칠 수 있어야 한다.

## 2. 목표

1. 표 편집기를 엑셀처럼 바꾼다.
   - 맨 위 고정 제목 행(색 다른 headerValues 행) 없음 — 첫 줄부터 평범한 셀.
   - 열 머리글 A·B·C…, 행 머리글 1·2·3… 표시(편집 화면에서만, 문서 보기·인쇄에는 안 보임).
   - **표 위에 고정 도구 모음 + 수식 입력줄**(사용자가 A안 선택). 수식 입력줄 왼쪽에 선택 셀 주소(예: `C3`).
2. 셀(또는 드래그로 고른 범위)에 서식 지정:
   - 굵게
   - 글자색, 배경색 (정해진 팔레트에서 선택)
   - 가로 정렬: 왼쪽·가운데·오른쪽
   - 숫자 표시: 일반·금액(1,000)·백분율
   - **테두리**: 모든 테두리 / 바깥 테두리 / 굵은 바깥 테두리 / 테두리 없음 (엑셀 테두리 버튼과 같은 방식)
3. 수식 직접 입력: 칸이나 수식 입력줄에 `=A1-A2`, `=SUM(B1:B5)*0.1` 식. 수식 입력 중 다른 셀을 클릭하면 그 주소가 커서 위치에 삽입(드래그하면 `B1:B5` 범위).
4. 틀 변형: 행·열 추가(원하는 위치에 삽입)·삭제, 셀 병합·병합 해제, 열 너비 조절, 셀 내용 편집. 행·열 삽입/삭제 시 수식 주소가 엑셀처럼 따라 움직인다(`shiftFormulaCoordinates` 확장).
5. **기안자도 위 1~4를 모두 할 수 있다.** 기안자가 바꾼 내용은 그 결재 문서(approvalDocs의 해당 필드 값)에만 저장되고 서식 마스터는 그대로다.
6. 문서 보기(PC `ApprovalDocumentView`, 모바일 `MobileApprovalDetail`, 인쇄)에서 셀 서식(굵게·색·정렬·테두리·숫자 표시)이 그대로 보인다.

## 3. 하지 않는 것

- 엑셀 파일 가져오기/내보내기, 시트 여러 장, 차트, 조건부 서식, 글꼴 종류·크기, 기울임, 세로 정렬.
- 모바일(PWA) 기안 작성 — 무기한 연기 상태. 모바일은 보기만.
- 함수는 SUM 외에 AVERAGE·MIN·MAX·ROUND 정도까지만(내 판단, §6).

## 4. 실패로 보는 것 (기술적으로 돌아가도 안 되는 것)

- **기존 서식(approvalForms)·결재 문서(approvalDocs) 데이터를 일괄 변환하거나 덮어쓰는 것** — 절대 금지(프로젝트 읽기 전용 규칙). 예전 형식은 읽을 때 화면에서만 새 형식으로 바꾼다.
- 예전 양식·문서가 안 열리거나, 예전 수식 결과가 달라지는 것(ba9197d로 고친 대체 규칙 버그 제외).
- 예전 표의 자동 합산(합계 칸 `sumCell`/`amountCells`) 값이 비거나 달라지는 것.
- 결재선 금액 규칙이 영향을 받는 것 — 결재선 금액은 서식의 별도 '금액' 필드(`amountFieldOf`)에서 오며 표와 무관. 이 연결을 건드리지 않는다.
- 비공개 칸(`secretCols`/`secretCells`/`secretRows`)이 노출되는 것.
- 화면에 내부 키·개발용 설명 문구가 보이는 것(예: "~에 저장되어 표시").
- 기안 작성 중 입력 시 화면이 튀는 것(이전에 고친 스크롤 강제이동 회귀 금지).

## 5. 결정된 것 (사용자 확정)

| 항목 | 결정 |
|---|---|
| 방향 | 최대한 엑셀과 동일하게 |
| 제목 행 | 없음. 첫 줄부터 평범한 셀, 강조는 셀 서식으로 |
| 도구 위치 | A안 — 표 위 고정 도구 모음 + 수식 입력줄 |
| 기안자 권한 | 값·서식·수식·행/열 추가삭제·병합 등 **모든 틀 변형** 가능 |
| 저장 범위 | 기안자 변경은 그 문서에만. 서식 마스터 불변 |
| 서식 종류 | 굵게, 글자색, 배경색, 가로 정렬, 숫자 표시, **테두리** |
| 비공개 칸 | 설정(켜기/끄기)은 **서식 관리자만**. 기안자에게는 설정 메뉴 없음. 기안자의 행·열 삽입/삭제·병합 시 비공개 표시는 칸을 따라 이동(풀리지 않음). 비공개 칸 포함 행·열 삭제는 막지 않음(내용이 함께 사라질 뿐 노출 아님) |
| 표 자동 합산(합계 칸) | **새 편집기에서 없앰.** 합계는 `=SUM(..)` 수식으로. 예전 형식 표에 이미 있는 `sumCell`/`amountCells` 자동 합산은 기존 규칙(열 키에 '금액' 포함 + amountCells 합)대로 계속 계산하되 새로 지정하는 UI는 없음 |

## 6. 내 판단으로 정한 것 (검토 시 확인 부탁)

### 6.1 데이터 형식 — 기존 JSON 확장(버전 2)

표 값은 지금처럼 필드 값(문자열 JSON)에 저장한다. 기존 키는 유지하고 다음을 더한다.

```ts
interface TableDataPayloadV2 extends TableDataPayload {
  version: 2;
  cellStyles?: Record<string, CellStyle>; // 키 "rIdx:colKey" (cellFormulas와 같은 규칙)
}
interface CellStyle {
  bold?: boolean;
  color?: string;      // 팔레트 토큰 이름 (예: 'red'), 임의 hex 아님
  bg?: string;         // 팔레트 토큰 이름
  align?: 'left' | 'center' | 'right';
  numFmt?: 'general' | 'currency' | 'percent';
  border?: { t?: BorderW; r?: BorderW; b?: BorderW; l?: BorderW }; // 'none' | 'thin' | 'thick'
}
```

- `cols`는 계속 **내부 열 키**(행 데이터 객체의 키)로 쓴다. A·B·C는 열 순서로 계산한 표시용 주소일 뿐 저장하지 않는다.
- 새 형식에서는 `headerValues`를 화면에 그리지 않는다. 다만 예전 수식의 `[행라벨:열제목]` 참조 해석용 별칭으로는 계속 보관·사용한다(삭제하지 않음).
- 숫자 표시는 `cellStyles.numFmt`와 기존 `cellFormulas[k].format`이 겹친다. 수식 칸은 `format`을 그대로 쓰고, 도구 모음에서 숫자 표시를 바꾸면 수식 칸은 `format`, 일반 칸은 `numFmt`를 바꾼다. (하나로 합치는 것은 빌더 재량이나, 예전 데이터 해석이 깨지면 안 됨)
- 테두리 기본: 셀 서식이 없으면 지금처럼 얇은 격자선. "테두리 없음"은 해당 변을 명시적으로 `none`.

### 6.2 예전 형식 → 새 형식 변환 (읽을 때만, 메모리에서)

`normalizeTablePayload(raw): TableDataPayloadV2` 순수 함수 하나로 모은다. `version !== 2`이면:

1. 제목 행(headerValues, 머리글 병합 = `merges`의 `startRow: -1`)을 **0번 행**으로 끌어내린다 — 각 열 셀 값 = `headerValues[col] ?? col`, 서식 = 굵게 + 연한 배경 + 가운데 정렬(지금 제목 행 모습과 비슷하게).
2. 기존 데이터 행은 한 칸씩 아래로. 따라서 다음을 모두 +1 이동:
   - `cellFormulas` 키의 행 번호, 수식 안의 A1 주소(`shiftFormulaCoordinates(expr, {type:'row_add', atIndex:0})`)
   - `merges`(-1 → 0 포함), `sumCell`, `amountCells`, `secretCells`, `secretRows`
   - `[2:금액]`처럼 **숫자 행 번호로 쓴 괄호 참조**도 +1 (라벨 참조 `[소계:금액]`, `LAST`는 그대로)
   - `SUM(ABOVE)`·`SUM([열])`은 "위의 모든 행 합"이라 제목 행이 숫자가 아니면 결과 동일 — 제목 행 셀이 숫자로 읽히지 않도록 합산 시 0번 변환 행 제외는 불필요(제목은 글자). 단 제목이 숫자처럼 생긴 예외("2026" 등)가 있으면 결과가 달라지므로, 변환 행을 `legacyHeaderRow: true` 표시로 합산에서 빼는 것이 안전 — **빌더가 테스트로 확인**.
3. 다른 표에서 이 표를 참조하는 `[표]!D4` 같은 타 표 A1 참조도 대상 표가 변환되면 행이 밀린다 → 타 표 참조 해석 시 상대 표도 `normalizeTablePayload`를 거친 뒤 해석하고, 참조하는 쪽 수식도 같은 규칙으로 +1 이동해야 결과가 같다. 이 부분은 회귀 테스트 필수(§8).
4. 저장은 사용자가 그 표를 편집해 저장(서식 관리자가 양식 저장 / 기안자가 문서 상신·임시저장)할 때만 새 형식으로. 앱이 스스로 DB를 고쳐 쓰지 않는다.

### 6.3 "최신 서식 반영" 버튼(ApprovalDraftScreen)

지금은 마스터와 현재 표의 수식·병합·열·머리글이 다르면 "서식 마스터 업데이트" 안내가 뜬다. 기안자가 틀을 바꾸면 늘 다르게 되어 안내가 계속 뜬다.

- 문서 표 값에 `baseSig`(작성 시작 시점 마스터 구조의 해시)를 기록하고, **마스터의 현재 해시 ≠ baseSig일 때만** 안내를 띄운다.
- 반영 시 확인창에 "직접 바꾼 표 구조·서식은 양식 기준으로 바뀝니다(입력한 값은 보존)"를 명시.
- `baseSig`가 없는 예전 문서는 지금 비교 방식 유지.

### 6.4 함수 범위

SUM, AVERAGE, MIN, MAX, ROUND(값, 자리) — 대소문자 무시. 기존 `SUM(ABOVE)`, `SUM([열])`, `[행:열]`, `[표]![..]` 문법은 계속 해석. 사칙연산·괄호·백분율은 기존 계산기 사용. 알 수 없는 함수·잘못된 주소는 셀에 `#오류` 표시(내부 메시지 노출 금지).

### 6.5 편집기 구성

- 기존 `TableDesignerModal`(1931줄)의 계산 유형 UI(열 합산·비율·차액 버튼, 셀렉트 박스 수식 조립)는 **새 편집기에서 제거**. 수식은 직접 입력만.
- 새 컴포넌트(예: `SheetEditor`)를 만들어 서식 설계(`ApprovalFormEditor` → 표 필드)와 기안 작성(`TableFieldEditor`의 모달) 양쪽에서 같은 것을 쓴다. 기안 화면에서 표 본문 인라인 입력은 지금처럼 되고, "표 편집" 버튼으로 같은 편집기를 연다 — 또는 인라인에서 바로 도구 모음을 붙이는 것도 빌더 재량. 단 인라인 입력 시 스크롤 강제이동 회귀 금지.
- 선택: 클릭 = 한 칸, 드래그·Shift+클릭 = 범위. 방향키 이동, Enter 아래로, Tab 오른쪽으로, F2/더블클릭 편집, Delete 내용 지우기, Ctrl+B 굵게. 복사/붙여넣기는 텍스트(탭 구분) 범위 붙여넣기까지(엑셀에서 복사해 붙이기 가능하도록) — 내 판단으로 포함.
- 비공개 칸 설정은 서식 설계 화면의 도구 모음 "더보기" 메뉴에만 둔다(기안 화면에는 없음). 합계 칸 지정 UI는 없앰.

### 6.6 보기 화면

`ApprovalDocumentView`·`MobileApprovalDetail`·인쇄는 공통 읽기 전용 렌더러(예: `SheetView`) 하나로 통일하고 `normalizeTablePayload`를 거쳐 그린다. 행·열 머리글은 안 그린다.

### 6.7 검토 질문에 대한 내 판단

- **타 표 참조 이동**: 기안자/관리자가 표 X에 행·열을 넣거나 지우면, 같은 문서(서식) 안 다른 표의 `[X]!D4`·`[X]![2:금액]` 참조도 엑셀처럼 따라 움직인다. 가리키던 칸이 지워지면 `#오류`. 행·열 변경은 문서의 모든 표 수식을 함께 갱신하는 경로(예: `cascadeRecalculateAllTables` 옆에 구조 변경 전파 함수)로 처리.
- **"최신 서식 반영" 비교**: 양쪽(마스터·현재 문서)을 모두 `normalizeTablePayload`로 새 형식으로 바꾼 뒤 구조(열 수·수식·병합·서식)만 비교. 예전 문서도 이 방식으로 비교해 안내가 늘 뜨는 문제를 막는다. `baseSig`가 있으면 그것을 우선.
- **셀 키 통일**: 새 형식(version 2)의 모든 칸 지정 키는 `행번호:열키`로 통일(`cellFormulas`·`cellStyles`·`secretCells`). 예전 `secretCells`의 `행번호:열순서` 형식은 `normalizeTablePayload`에서 변환. 보기 화면도 normalize 후 새 키로 비공개 판정 — 비공개 노출 회귀 테스트 필수.
- **배포 중 예전 화면**: 예전 화면이 새 형식 값을 저장하면 version·cellStyles 등이 빠질 수 있다. 막는 장치는 두지 않고, 운영 배포는 업무 시간 외에 하고 배포 후 새로고침 공지(사용자에게 권고). normalize는 version 없는 값도 정상 처리하므로 데이터가 깨지지는 않고 서식만 빠짐.
- **보기 화면 값**: 문서 보기는 저장된 값을 그대로 보여 준다(다시 계산하지 않음).
