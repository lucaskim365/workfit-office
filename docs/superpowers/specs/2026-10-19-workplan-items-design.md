# 업무계획 항목형 개편 설계

- 작성일: 2026-10-19 (2026-10-20 개정: 팀즈식 일정 창·다른 사람 칸 권한·회의실 예약 연동·모바일)
- 범위: 업무계획(PC `WorkPlanScreen`·팀 월간표, 모바일 `MobileTaskScreen`), 업무계획 태그 관리, 회의실 예약 연동(자원예약 저장 함수 재사용)
- 상태: 설계 확정 대기

## 1. 배경

### 1.1 현재 구조
- `workPlans`: 사람 1명 × 하루 1건, 시간 없는 자유 글(`content`, 위지윅·체크박스·태그 문법). 칸 편집 리본에서 작성.
- `calendarEvents`: 시간·종류(GENERAL/MEETING/OUTSIDE/VACATION)·참석자가 있는 일정. 업무계획 "회의 등록"은 여기에 MEETING 1건을 만든다(`domain/calendarEvent/meeting.ts`).
- `outsideWorks`: 결재 없이 본인이 등록하는 외근·출장. 근태 판정·재실 상태·캘린더·업무계획에 반영.
- 업무계획 글 → 캘린더 일정 동기화(`[WP-SYNC:planId:idx]`, `workPlanCalendarBridge.ts`)가 있다.
- 사용자 태그는 사람마다 브라우저 `localStorage`에만 저장돼 공유되지 않는다(`useWorkPlanConfig.ts`).

### 1.2 외근·출장 "나에게만 보임" 조사 결과 (2026-10-19)
- 코드에 사람별 제한 없음. 등록 버튼은 **본인 칸을 눌러 편집할 때 뜨는 리본 안에만** 있다(`WorkPlanScreen.tsx:472`, 조건은 계정 '사용' + 본인 칸).
- 운영 `origin/main`에도 같은 코드가 배포돼 있고, 운영 DB에 유지승(U030)이 2026-10-16 출장 2건을 직접 등록한 기록이 있다. 컬렉션 권한은 전체 공개.
- 사용자 확인 결과 증상은 "다른 사람들이 등록 버튼을 못 찾음" → **진입점 발견성 문제.** 이번 개편에서 "칸 [+] → 태그 선택(외근/출장)"으로 진입점을 바꿔 해결한다.

## 3. 화면

### 3.1 PC 표
- 사람×날짜 표(`WorkPlanTeamMonthlyMatrix`)의 틀·정렬·색 규칙 유지.
- 칸 내용 = `buildDayEntries` 결과를 칩으로: `종일`/`HH:mm` + `[태그]` + 제목. 정렬: 종일 먼저 → 시작 시각 → 같은 시각이면 출처 순(회의, 외근·출장, 일반).
- 회의실 예약이 승인 대기인 회의 칩에는 작은 "대기" 표시.
- 진입: **칸 더블클릭** 또는 마우스를 올리면 뜨는 **[+]**(발견성 때문에 [+]도 유지) → 그 날짜·그 사람으로 일정 창.
  - 본인 칸: 모든 태그.
  - 다른 사람 칸: 회의만(주최자 = 나, 그 사람 = 참석자로 미리 채움). 외근·출장·일반 버튼은 비활성.
  - 사용 중이 아닌 계정(`status !== '사용'`)은 진입 자체가 없다.
- 칩 클릭 → 같은 일정 창을 **수정 모드**로(내가 고칠 수 있는 것) 또는 **보기 모드**로(그 외). 결재 건은 기존 결재 표시.
  - 고칠 수 있는 것: 내 일반 항목, 내가 주최한 회의, 내가 등록한 외근·출장.
- 표 맨 위 **전사 공통 일정 줄**(`WorkPlanCompanyScheduleModal`, `ownerUserId: '__COMPANY__'`)은 지금 동작 그대로 둔다(작성·수정 가능).
- 여러 날 외근·출장은 기존처럼 칸을 가로지르는 막대(`layoutWeekBars`).
- 예전 `workPlans` 글이 있는 날은 칸 맨 아래 흐린 **"이전 메모"** (서식 제거한 글, 읽기 전용, 길면 접기).
- 칸 클릭으로 열리던 편집 리본(`WorkPlanOfficeRibbonToolbar`)·위지윅 편집기·루틴 템플릿·서식 버튼은 제거.

### 3.2 일정 창 (`WorkPlanEventModal`, 새 컴포넌트)
시안: `.superpowers/brainstorm/*/content/modal-layout-v2.html`의 C안 상단 + 전체 창.

**틀** — 공통 `Modal` 확장(넓은 폭, 약 760px 기준 화면 배율 적용), 머리줄 = "새 일정 / 일정 수정" + 대상자·날짜, 바닥 = [취소] [저장](수정 모드는 왼쪽에 [삭제]).

**상단 도구 막대**
- 분할 버튼: [회의] [외근] [출장] [일반 ▾]. 일반 ▾ = 관리자 일반 태그 목록(숨김 제외, 색 점 + 이름). 고른 일반 태그 이름이 버튼에 표시된다.
- 수정 모드에서는 출처가 바뀌는 태그 변경(예: 회의 → 외근) 불가, 같은 출처 안(일반 태그끼리)만 변경 가능.
- 오른쪽: [리마인드] [루틴] — 흐린 비활성 버튼으로 자리만. 이번 범위에서 동작 없음.

**왼쪽 입력(태그별)** — 아이콘은 lucide.
| 칸 | 일반 | 회의 | 외근·출장 |
|---|---|---|---|
| 제목 | 필수 100자 | 필수 100자 | — (외근·출장은 제목 대신 행선지) |
| 날짜·시간 | 하루, 종일 또는 시작~종료 | 하루, 시각 필수 | 시작일~종료일(여러 날), 종일 또는 시각 |
| 참석자 | — | 이름·부서 검색 칩(기존 회의 참석자 선택과 같은 규칙) | 동행자(기존 `MemberPicker`) |
| 장소 | — | 직접 적기 / 회의실 선택(3.3) → `calendarEvents.location` | 행선지(필수) |
| 세부 내용 | 메모 1000자 | 메모·안건 2000자 | 목적 500자 + 메모 2000자 |
| 기타 | — | 공개 범위(기본 전사, 기존 회의와 같은 선택지) | 교통수단·연락처(기존 칸) |
- 회의: 같은 날·겹치는 시간·비슷한 제목 회의가 있으면 기존처럼 "참석자로 합류" 제안(`findSimilarMeetings`). 저장·알림 규칙은 기존 회의 저장과 같다(생성 알림 = 참석자, 10분 전 리마인더).
- 외근·출장 **세부 구분**(`subType`: 종일·오전·오후·시간 외근 / 국내·해외 출장, 근태 판정에 쓰임)은 기존 창처럼 [외근]/[출장]을 고르면 도구 막대 바로 아래 한 줄로 고른다. 기본값 = 각 구분의 첫 값(종일 외근, 국내 출장). (만든 사람 판단으로 정함)
- 외근·출장: 기존 `OutsideWorkFormModal`의 검증·겹침 경고·저장(`useCreateOutsideWork`/`useUpdateOutsideWork`)을 그대로 쓴다. 기존 창 하단의 설명 안내문은 넣지 않는다(화면 안내문 금지 규칙).
- 시간 표시 옆에 길이("1시간 30분").

**오른쪽 세로 시간표**
- 기본 08:00~19:00 표시, 위아래 스크롤로 00:00~24:00. 날짜 ‹ › 이동(창의 날짜와 연동).
- 겹쳐 보이는 것: 대상자 + (회의면) 참석자들의 그날 일정 — 일반 항목·회의·외근·출장(시간 있는 것). 회의실을 고르면 그 회의실의 예약도 흐리게 겹친다. 사람마다 색을 다르게 하지는 않고 출처별 색(회의 파랑·외근출장 주황·일반 회색)으로, 칩에 이름 표시.
- 지금 입력 중인 일정은 강조 막대로 표시. 막대를 끌어 옮기고, 아래 끝을 끌어 늘린다.
- 빈 곳 클릭 = 그 30분 칸 선택, 끌기 = 30분 단위 구간 선택. 왼쪽 시간 칸과 양방향으로 맞춘다. 종일이면 맨 위 "종일" 줄에 표시.
- 다른 사람 일정은 보이는 범위만: 회의는 기존 공개 범위 규칙, 일반 항목·외근·출장은 전사 공개(현재와 같음).

**저장 실패** — 창을 닫지 않고 이유 표시, 입력 유지.

### 3.3 회의실 예약 연동
- 회의 장소 칸에서 [직접 적기 | 회의실]. 회의실 = 자원예약의 `ROOM` 유형, `ACTIVE` 자원만.
- 회의실 목록에는 고른 시간에 비어 있는지 표시(예약 충돌 검사 규칙 재사용). **차 있는 방은 고를 수 없다**(목록에서 비활성, 사용자 확정 2026-10-20). 고른 뒤 시간을 바꿔 겹치게 되면 회의실 선택을 해제하고 이유를 보여 준다. 저장 시에도 충돌 검사로 한 번 더 막는다(그사이 다른 사람이 예약한 경우).
- 저장 순서: ① 회의실 예약 생성(`reservationRepo.create`, 제목 = 회의 제목, 목적 = 안건 또는 "회의", 참석자 = 회의 참석자) → ② 회의 일정 생성(장소 = 회의실 이름, 예약 ID 연결). ②가 실패하면 ①을 취소(`cancel`, 사유 "회의 저장 실패")하고 오류 표시.
- 승인 필요 회의실은 예약이 `PENDING`으로 들어가고, 회의 칩·창에 "승인 대기" 표시. 반려되면 칩에 "회의실 반려" 표시(회의 자체는 남는다).
- 회의 시간 변경 → 연결된 예약도 `reschedule`(승인 규칙은 자원예약 기존 동작을 따름). 겹쳐서 실패하면 회의도 저장하지 않고 이유 표시.
- 회의 삭제 → 연결된 예약 `cancel`(사유 "회의 취소").
- 회의실 변경 → 기존 예약 취소 + 새 예약.
- 연결된 예약이 이미 끝났거나 바꿀 수 없는 상태(시작 시각 지남, `REJECTED`·`CANCELLED`·`EXPIRED`·`COMPLETED`)면 예약은 건드리지 않고 회의만 수정·삭제한다. 반려된 회의에서 회의실을 다시 고르면 새 예약을 만들고 연결을 바꾼다. (만든 사람 판단으로 정함)
- 캘린더 화면 `CalendarEventModal`: `reservationId`·`location`을 보존하고, 연결 회의의 시간 변경·삭제 시 위와 같은 함수로 예약을 같이 바꾸거나 취소한다. 그 외 화면 변경 없음.
- 자원예약 화면·모듈 파일(`src/modules/gw/resource`, `src/mobile/resource`, `MobileResourceScreen`)은 다른 담당자(이재원) 작업 영역이므로 **수정하지 않는다.** `reservationRepo`·`resourceRepo`·도메인 규칙은 호출만 한다.

### 3.4 태그 관리 (관리자)
- 기존 업무계획 설정 창(`WorkPlanConfigModal`)의 태그 영역을 `workPlanTags` 기반으로 교체. 권한: `S_GW_WORK_PLAN_ADMIN` update (또는 슈퍼관리자).
- 고정 태그(회의·외근·출장)는 목록에 잠금 표시로만 보이고 이름·색 변경·삭제 불가.
- 일반 태그: 이름(필수, 10자, 중복 불가)·색(`TAG_COLOR_PRESETS`)·순서 편집, 추가. 삭제 = `hidden: true`(이미 쓴 항목은 계속 표시).
- 개인 `localStorage` 태그·템플릿 기능은 제거.

### 3.5 모바일 (`MobileTaskScreen`) — **빠른 입력 기본, 기능은 PC와 같게**
- 날짜 선택 → 그 날 `buildDayEntries` 결과를 시간순 목록으로(나 / 팀원 전환은 기존 화면 구성 유지). 다른 사람 목록 보기 가능, 다른 사람에게는 회의 초대만.
- **[+]** → 전체 화면 일정 창(같은 저장 함수·같은 규칙).
  - 처음 보이는 것: 태그 버튼 줄, 제목(외근·출장은 행선지), 날짜·시간. 시간은 지금 시각 다음의 30분 단위 시작 + 30분으로 미리 채움. 이 상태로 바로 [저장] 가능.
  - **[자세히]** 접힘 영역: 참석자, 장소·회의실, 세부 내용, 공개 범위, 외근·출장의 동행자·목적·교통수단·연락처·메모·종료일. 회의를 고르면 참석자 칸은 처음부터 펼침.
  - 시간표: 시간 칸 아래 접힘. 펼치면 빈 칸 탭 = 30분, 막대 아래 끝 끌기로 늘림(처음부터 끌어서 고르기는 스크롤과 충돌하므로 모바일에서는 쓰지 않음).
  - 리마인드·루틴: 상단 오른쪽 ⋯ 메뉴 안에 비활성 자리.
- 항목 탭 → 수정/보기 화면. 결재 건·이전 메모 보기 지원.
- 태그 관리(관리자)도 모바일에서 가능.
- 기존 할 일(To-Do) 입력·체크 UI는 제거, 이전 메모는 읽기 전용 표시.

## 4. 데이터

### 4.1 `workPlanItems` (신규)
| 칸 | 규칙 |
|---|---|
| `id` | `WI-{YYYYMMDD}-{4자리 순번}` (Appwrite ID 36자 이내) |
| `ownerUserId` | 누구의 업무 |
| `date` | 하루 (`isValidCalendarDate`) |
| `allDay` | boolean |
| `startTime`, `endTime` | `HH:mm` 또는 null. allDay=false면 둘 다 필수, start<end, 30분 단위로 강제하지 않음(직접 입력 허용) |
| `tagId` | `workPlanTags.id` |
| `title` | 1~100자 |
| `memo` | 0~1000자 |
| `createdBy` | 실제 입력한 users.id (= `ownerUserId`, 다른 사람 칸 입력이 없어졌으므로) |
| `createdAt`, `updatedAt` | ISO datetime |

- 쓰기 규칙: `ownerUserId` = 행위자 본인, 행위자 계정 '사용' — 저장소에서 검사.

### 4.2 `workPlanTags` (신규)
| 칸 | 규칙 |
|---|---|
| `id` | `WT-{4자리 순번}` |
| `name` | 1~10자, 숨기지 않은 태그끼리 중복 불가 |
| `colorId` | `TAG_COLOR_PRESETS`의 id |
| `order` | 정렬 |
| `hidden` | boolean |

- 고정 태그는 코드 상수(`FIXED_WORK_PLAN_TAGS`: MEETING·OUTSIDE·TRIP, 이름·색 고정)이며 DB에 넣지 않는다.
- 기본 일반 태그 5개(업무·보고·교육·마감·집중)는 배포 시 프로비저닝 스크립트로 1회 생성. 화면이 자동 생성하지 않는다.
- 태그를 못 찾는 항목(삭제된 ID 등)은 회색 "기타"로 표시.

### 4.3 `calendarEvents.reservationId`·`location` (기존 컬렉션에 선택 칸 2개 추가)
- `reservationId`: string 64, 선택(null 기본). 회의와 연결된 회의실 예약 ID.
- `location`: string 100, 선택(null 기본). 회의 장소(직접 적은 글 또는 회의실 이름). 지금은 장소 칸이 없어 메모에 적고 있었다. (만든 사람 판단으로 정함)
- 칸 추가만 하고 기존 문서는 건드리지 않는다(없으면 null로 읽음). 캘린더 화면의 `CalendarEventModal`은 두 칸을 보존한다(덮어쓰지 않도록 저장 시 기존 값 유지).
- 운영 DB: 프런트 배포 **전에** 두 칸을 먼저 만든다(없으면 회의 저장이 "Unknown attribute"로 실패).

### 4.4 칸 목록 조립 — `buildDayEntries` (순수 함수, `src/domain/workPlan/dayEntries.ts`)
입력: 대상 사람 id, 날짜, 원본 목록(항목·회의 일정·외근출장·결재 외근출장/휴가·예전 글·연결 예약 상태). 출력: 정렬된 `DayEntry[]` + `legacyMemo`.

| 출처 | 그 사람 칸에 포함 조건 | 수정 |
|---|---|---|
| `workPlanItems` | `ownerUserId` = 그 사람, `date` = 그 날 | 본인 |
| `calendarEvents` MEETING | 주최자 또는 참석자, 그 날 | 주최자 (기존) |
| `calendarEvents` 회의 외 | 지금 칸 표시 규칙(`isOfficialCalendarEvent`: 사내행사·OUTSIDE·VACATION·`CAL-APPR-*`·제목에 회의/미팅) 그대로 | 업무계획에선 불가(보기만) |
| `outsideWorks` | 본인 또는 동행자, 기간에 그 날 포함, `linkedApprovalDocId` 없음 | 등록 본인 (기존) |
| 결재 완료 외근·출장·휴가 | 기존 표시 규칙(`fromApprovalSchedule` 등) | 불가 |
| `workPlans` 예전 글 | 그 사람·그 날 글이 있으면 `legacyMemo` | 불가 |

- `[WP-SYNC:` 표시가 있는 캘린더 일정(`isWorkPlanDerivedEvent`)은 칸에서 제외 — 같은 내용이 이전 메모에 있어 중복되므로. 캘린더 화면에서는 그대로.
- 업무계획 글 → 캘린더 동기화는 더 이상 새로 만들지 않는다. 이미 만든 일정은 지우지 않는다.
- 시간표(3.2)도 같은 함수 결과를 여러 사람에 대해 모아 쓴다.

### 4.5 기존 데이터 보호
- `workPlans`·`calendarEvents`·`outsideWorks`·`reservations`의 **기존 문서를 수정·삭제하는 코드 없음.** 예외는 전사 공통 일정 줄(`__COMPANY__`, 기존 동작 유지)과 기존 기능 그대로의 본인 작업(내 회의·외근·출장 수정, 내 회의에 연결된 예약의 변경·취소)뿐.
- 결재 데이터(`approvalDocs`·`approvalForms`)는 읽기만.
- 운영 DB 변경 = 새 컬렉션 2개 생성(권한은 기존 업무계획 컬렉션과 같은 방식) + 기본 태그 5건 + `calendarEvents.reservationId`·`location` 칸 추가.

## 5. 오류 처리
- 일반 항목은 한 건씩 저장하므로 칸 단위 덮어쓰기 충돌(`conflictError`)이 없어진다. 같은 항목을 동시에 고치면 나중 저장이 이긴다(본인만 고치므로 드묾).
- 저장 실패: 창 유지 + 이유 표시.
- 회의 + 회의실: 3.3의 순서·되돌리기. 되돌리기(예약 취소)마저 실패하면 "회의실 예약은 남아 있음, 자원예약에서 취소해 주세요"를 보여 준다.
- 비활성 계정(`status !== '사용'`)은 추가·수정 불가(저장소에서도 거부).
- 다른 사람 칸 규칙(회의만)은 화면과 저장소 둘 다에서 검사(일반 항목 `ownerUserId` ≠ 행위자면 거부).
