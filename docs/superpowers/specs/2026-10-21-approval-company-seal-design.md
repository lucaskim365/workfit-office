# 결재서식 — 회사 직인 모드 설계

- 작성일: 2026-10-21
- 브랜치: main(운영 c80e542) 기준 새 브랜치 — 사업관리 작업보다 먼저, 따로 운영 배포

## 1. 왜

발주서·공문처럼 밖으로 나가는 문서는 결재란(결재자 도장 칸) 대신 **회사 직인**이 찍혀야 한다. 결재는 내부적으로 그대로 받되, 문서·인쇄본에는 결재란 없이 직인만 보여야 한다.

## 2. 사용자 확정 사항

- 서식 편집에서 서식을 **회사 직인 모드**로 바꿀 수 있다.
- 결재 과정(결재선 지정·승인)은 **그대로**.
- 직인 모드 서식의 문서·인쇄본: 오른쪽 위 **결재란을 숨김**, **최종 승인(완료) 후** 직인이 찍힘.
- 직인 이미지는 **시스템 관리 > 회사 정보**에서 등록(로고 등록과 같은 방식).
- 직인 위치는 서식 설계자가 **양식(필드)이나 표 칸**으로 직접 지정.

## 3. 설계

### 3.1 회사 정보 — 직인 이미지
- `companyInfo`에 `sealUrl`(512), `sealPath`(256) 추가. 화면은 기존 로고 등록 블록 옆에 "회사 직인" 등록·삭제(같은 업로드 함수 재사용, 경로 `branding/company-seal-…`). 배경이 투명한 PNG 권장 문구 없이 미리보기만.
- **DB 변경**: dev·운영 `companyInfo` 컬렉션에 문자열 속성 2개 추가(기존 데이터 변경 없음). 운영은 배포 전에 추가.

### 3.2 직인 위치 지정 — 두 가지
1. **직인 필드**: 필드 종류에 `'직인'` 추가. 서식 설계자가 다른 필드처럼 원하는 자리에 배치. 라벨은 직인 옆 문구(예: "주식회사 워크핏 대표이사 김○○"). 기안 입력은 없음.
2. **표 칸 직인**: 엑셀식 표 편집기(서식 설계 화면에서만)에 "직인 칸" 지정·해제 버튼. 셀 서식 `CellStyle.seal?: true`. 그 칸 내용 위에 직인 이미지를 겹쳐 그림(도장처럼 글자 위에 반투명하지 않게 겹침, 칸 오른쪽에 붙임).

### 3.3 직인 모드 판정
- 서식의 필드 중 `'직인'` 필드가 있거나, 표 칸에 `seal` 서식이 하나라도 있으면 **직인 모드**. 별도 서식 속성(DB 컬럼)을 만들지 않는다 — `approvalForms` 스키마 변경 없음.
- 서식 편집 화면 결재란 자리에 "결재란 대신 회사 직인" 상태 표시, 설정 패널에 "회사 직인 모드" 켜기/끄기 스위치: 켜면 문서 끝에 `'직인'` 필드를 하나 추가(위치는 설계자가 옮김), 끄면 직인 필드와 표 칸 직인 지정을 모두 해제.

### 3.4 표시 규칙
- 직인 모드 문서: 기안 작성·문서 보기·인쇄·모바일에서 결재란 숨김. 결재 진행 상황은 기존 결재 진행 패널(문서 밖 UI)에서 그대로 확인.
- 직인 이미지: 문서 상태가 **완료**일 때만 표시. 작성·진행 중에는 직인 자리에 "(직인)" 흐린 글자로 자리만 보임. 서식 설계 미리보기에서는 등록된 직인을 보여 줌.
- 직인 이미지가 등록돼 있지 않으면 완료 문서에도 "(직인)" 글자만.
- 이미지는 문서를 볼 때의 회사 정보 직인을 사용(문서에 따로 저장하지 않음 — 내 판단: approvalDocs 스키마 변경 회피. 직인을 교체하면 예전 완료 문서도 새 직인으로 보임).

## 4. 하지 않는 것
- 결재 과정 생략, 직인 날인 권한·날인 대장, 직인 여러 개(법인인감/사용인감 구분), 문서별 직인 선택.

## 5. 실패로 보는 것
- 직인 모드가 아닌 기존 서식의 결재란 표시가 바뀌는 것.
- 진행 중 문서에 직인이 찍혀 보이는 것.
- 기존 서식·문서 데이터 변경(읽기 전용 규칙).

## 6. 검증
- 단위 테스트: 직인 모드 판정(`isSealForm(fields)`), 표 칸 seal 서식 왕복.
- `npx tsc --noEmit`, `npm run build`. 화면 확인은 사용자 직접(사용자 요청).
